> 今日概念在知识树中的位置：S7-01 让 **run** 可见可续；S7-02 在 **写操作前** 加了 **审批闸**；S7-03 让 **超时与重试** 不再 **双出库、双入账**。灰度第五周，**澄光制造** 又来电——这次不是 **「批了没发」**，而是 **「黄灯转了五分钟，张工点了联系支持，坐席打开后台 **不知道能改哪一步**」**。今天拆 **人工接管话术与权限**：**办事链自动办不下去** 时，**谁有权接半成品 run、接后能看/能改/能代操作什么、对用户说什么、交接怎么留痕**——**不是把客服后台当成万能 root**。

### 场景白板（读故事前 30 秒）

- **本集入口**：**应用 B｜修小言**——**张先生** 的 **RUN-CG-20261009-041** 在 **⑥ 通知仓库** 进入 **黄色「确认中」** 五分钟后仍 **unknown**；他点 **「联系真人支持」**；**阿梅** 侧星尘 **真人支持** 坐席接单。
- **人工接管（Human Takeover）**：白话：**AI 小言** 办的 **同一笔 run** 由 **有权限的人** 接手继续——**不是新开聊天**，而是 **继承步骤条、审批单、下游单号** 的 **交接班**。
- **接管权限（Takeover Authorization）**：白话：**接的人能做什么**——只读查 trace、代点 **重试本步**、改收货地址、**驳回并取消 run**、还是 **只能留言让用户自己点**——**必须按角色写死**，不能 **坐席想点啥点啥**。
- **交接话术（Handoff Script）**：白话：**对用户、对主管、对仓库** 三套说法——**让用户知道「人在跟」又不泄露内部字段**；**让老周知道「不用重批」**；**让小刘知道「查的是哪张单」**。
- **本集冲突**：坐席 **能看见 run**，但 **没有「代重试」按钮**；张工在电话里催；仓库班长问 **「你们到底要几号单？」**——**技术能查，产品没定义「接得住」**。

## 寓言故事

### 一、黄灯转了五分钟，用户点了「联系支持」

S7-03 双轨上线后，澄光制造的 **张先生** 对 **黄色确认中** 已经习惯——**至少知道系统在问仓库**，不是 **瞎绿**。

周二下午，他对 **AI 小言** 再走 **CF-220 换芯发货**。**RUN-CG-20261009-041** 照例跑到 **⑥ 通知仓库拣货**，界面变黄：

> **正在与仓库确认拣货状态……**  
> 出库单 **SHP-1041-A** 已创建；审批 **APR-1009-018** 已生效。请勿重复提交。

后台每三十秒轮询一次 `get_pick_status`。**第一分钟** 无结果；**第三分钟** 仍 **unknown**；**第五分钟**，文案变成：

> **仓库系统响应较慢，我们仍在确认。您可稍候，或联系真人支持协助。**

张先生在产线边等备件，点了 **「联系真人支持」**。

星尘侧 **真人支持** 坐席小方接到单，标题自动带出：**「修小言 run 待接管 · RUN-CG-20261009-041」**。附：租户 **澄光制造**、用户 **张先生**、当前步 **step_6 unknown**、**`shipment_id=SHP-1041-A`**。

小方打开 **接管台**，左侧是 **步骤条**——①～⑤ 全绿，⑥ 黄圈转；右侧是 **trace 时间轴** 和 **用户会话摘要**。她第一反应很自然：**「那我帮用户点一下重试吧。」**

按钮区只有：**「添加内部备注」**、**「转二线研发」**、**「关闭会话（未解决）」**。

没有 **「代重试本步」**，也没有 **「标记 step 完成」**。

小方只好回电张先生：**「张工您稍等，我帮您催一下。」** 张先生问：**「到底批了没？仓库认哪张单？我车间等着换芯。」**

小方 **看不见 WMS**，只能把 run 链接 **@ 阿梅**。阿梅按惯例在内部建跟进单，备注：**「坐席无代操作权限；用户催货；unknown 超 5 分钟。」**

### 二、会诊：不是查不到，是「接的人不能办」

周三上午，林薇拉会诊：阿梅、小陈、大刘（WMS 对接）、**真人支持** 组长老吴，澄光 IT 与 **仓库班长小刘** 在线。

小陈先查 **RUN-CG-20261009-041** 的下游：**WMS 在 14:07:33 已生成 `pick_list_id=PK-041`**——和 S7-03 里 **「第一次 504 其实成功」** 同类，只是 **轮询窗口内网关没回全**。**第六步本该标绿**，但 **自动轮询在第五分钟超时转人工** 时，状态仍停在 **unknown**。

小刘在群里有点火：**「**PK-041 **早上就进了拣货队列；你们小言 **黄着**，我们以为 **还没定单**，线边 **干等**。」**

老周问：**「还要我再批一次吗？」**

张先生补充：**「支持小妹说 **帮我催**，结果 **四十分钟** 没人告诉我 **单号**——我以为 **又卡审批**。」**

林薇在白板上把问题拆开：

```text
技术真相：PK-041 已存在（可查）
产品缺口：
  1. 转人工时 run 没把「已查到的部分结果」带给坐席
  2. 坐席角色没有「代标完成 / 代重试 / 只读查下游」分级
  3. 对用户话术没有「接管中」模板——用户不知道人在跟什么
  4. 对外（仓库/主管）没有「请认这个单号」的协同话术
```

**「S7-01～03 解决 **机器怎么办**；今天解决 **人接手时怎么办**。** 演示里失败很少；值班里 **转人工不是失败**，是 **产品路径的一环**。」** 她说。

老吴举手：**「我们坐席不是工程师。** 能给 **查状态** 和 **告诉用户单号**，别给 **改出库数量**——上次有人手滑差点帮用户 **多要一套滤芯**。」**

苏姐在会诊里投 **账小言** 对照：**周会计** 上周 **importReconciliation unknown** 转财务支持，坐席 **只能看 run**，不能 **代点「确认入账」**——**对的**；但 **连「告知用户 ERP 其实已成功」** 的话术模板也没有，**周会计白跑一趟财务室**。

林薇点头：**「接管不是 **万能后台**，是 **有边界的交接班**。」**

### 三、谁能接、接后能改什么

林薇提交 **《修小言 / 账小言 人工接管话术与权限双轨方案》**，第一条就写 **角色**，不是功能列表。

**标准 / 规范流程（多租户、审计严、坐席分级）**

| 角色 | 典型人 | 接管时能做什么 |
|------|--------|----------------|
| **L1 · 租户支持坐席** | 星尘 **真人支持** / 客户 IT 服务台 | **只读** run + trace；**调用只读查询 tool**（`get_pick_status`）；**发送对用户标准话术**；**添加备注**；**升级 L2** |
| **L2 · 运营 / 客户成功** | **阿梅** 类、澄光 IT 对口人 | L1 全部 + **代「重试本步」（走先查后写）**、**代标 step 完成（需附查询凭证）**、**修改非审批类字段**（收货地址、联系电话） |
| **L3 · 产研值班** | 小陈 / 大刘 | L2 全部 + **暂停/恢复 run**、**触发补偿 tool**、**热修配置**；**不可绕过审批闸** |
| **业务审批人** | **老周** | **不是坐席**；仅在 **新写操作 / 超预算 / 改数量** 时走 **审批闸**；**接管不默认重批** |

**接管触发条件（产品统一，不靠坐席自觉）**

| 触发 | 行为 |
|------|------|
| **step unknown ≥ N 分钟**（如 5） | 自动 **创建接管单** + 用户侧 **「已转真人协助」** |
| **用户点「联系支持」** | 同上，**优先级更高** |
| **步级重试耗尽** | run **`failed` 可续办** + **强制推荐接管** |
| **用户情绪/辱骂/重复催单**（可选） | 建议转人工，**不自动代操作** |

**接管台必显「交接包」**（不是裸 trace）

```text
run_id · 租户 · 用户 · 当前步 · 审批单号（若有）
已成功步摘要 + 下游业务单号（ticket / shipment / pick_list）
unknown 原因分类 + 最后一次查询结果
推荐动作（系统算）：标完成 | 代重试 | 请用户补材料 | 升级 L2
对用户下一句建议话术（可编辑）
```

**权限硬规则**

- **无 `approval_id` 不得代触写出库/入账**——坐席 **不能替老周点批准**。  
- **代重试** 必须 **写 audit**：谁、何时、基于哪次查询、调了哪条 tool。  
- **改数量/金额** → **只能驳回 run 让用户重开** 或 **拉起新审批**，**禁止坐席直接改 step_5 参数**。  
- **接管期间** run 对用户侧标 **`handoff_in_progress`**——**AI 小言** 暂停自动推进，**避免人机双写**。

**话术三层**

| 对象 | 要点 | 示例 |
|------|------|------|
| **对用户（张先生）** | 承认等待；说明 **人在跟**；给 **可见单号**；不说内部甩锅 | 「已为您确认仓库拣货单 **PK-041**，货物在拣货队列，预计今日送达；无需再次申请。」 |
| **对审批人（老周）** | **不必重批**；除非 **数量/费用变了** | 「**APR-1009-018** 仍有效；当前是 **仓库回传慢**，不是二次出库申请。」 |
| **对协同方（小刘）** | **认哪个下游单**；请对方 **按单执行** | 「请按 **PK-041 / SHP-1041-A** 拣货；修小言侧已确认。」 |

**中小常用默认方案（星尘当前可卖）**

- **「一键交接包」**：转人工时 **自动把 shipment_id、pick_list（若查到）、审批号** 打进坐席屏；**L1 只能复制给用户**。  
- **「两个代操作」**：L2 仅开放 **「代标本步完成（附查询截图）」** + **「代重试本步」**——**其余全只读**。  
- **「三句用户话术」** 模板下拉：  
  1. **仍在确认**（unknown 未查清）  
  2. **已确认请等候**（查到 PK 号）  
  3. **需您补充**（缺地址/缺图）  
- **「人机互斥」**：接管中 **AI 不自动重试**；结案后 **交还 AI** 或 **run 终结**。  
- **可暂缓**：多坐席 **抢单池**、**视频核身**、**跨租户接管**——等 **坐席量 ≥ 3 人班次** 或 **客户合同写 SLA** 再上。

阿梅问老吴：**「L1 够吗？」**

老吴：**「**80% 是 **告诉用户单号** 和 **别重复点**。** 代重试给运营就行，**别给新人 **改出库**。」**

方案灰度后，**RUN-CG-20261009-041** 被用作 **培训样例**。新一次真实单 **RUN-CG-20261015-052** 又在 **⑥** 黄满五分钟。

林薇在 **S7 收官复盘** 里写五条人话——也是本季自检：

```text
1. 办事从哪开：用户意图 → 唯一 run_id（S7-01）
2. 卡在哪可见：步骤条 + unknown 黄灯（S7-01、S7-03）
3. 失败从哪续：步级重试 + 先查后写（S7-03）
```

**「Agent 值班，**不是 **永远自动办完**；**是 **自动能办则办，办不下去 **交给人 **且人 **接得住**。」** 阿梅说。

## 概念正解

**人工接管话术与权限（Human Takeover Handoff Script & Authorization）** 指：当 **Agent 办事 run** 因 **超时、不确定态、重试耗尽或用户主动求助** 而 **无法自动推进** 时，产品必须为 **真人支持 / 运营 / 值班研发** 定义 **分级接管权限**（只读、代查询、代重试、代标完成、改非敏感字段、升级）、**交接信息包**（run 状态、审批号、下游单号、推荐动作）、**人机互斥规则**（接管期间 AI 暂停自动写操作），以及 **对用户 / 审批人 / 协同方的标准话术**——**不是** 把客服后台做成 **无审计的万能 root**，也 **不是** 让人 **口头说「帮您催」** 却 **看不到单号**。

回扣故事：**RUN-041** **黄灯五分钟** 后张先生转人工；坐席 **能看见 trace** 却 **不能代标完成**，用户 **不知 PK-041 已存在**；仓库 **以为未定单**、老周 **以为要重批**；双轨方案用 **L1/L2/L3 权限、交接包、代操作 audit、三层话术、handoff_in_progress** 把 **「转人工」** 从 **「踢皮球」** 升级为 **「可交接的值班路径」**；账小言 **坐席可查不可替点确认入账**。

在 **S7 · Agent 从演示到值班** 中的位置：**收官篇**——收束 **「从哪开、卡哪、怎么续、谁批、何时人接」** 五条；**S6 知识运营与权限** 仍生效，本篇补 **办事链末端的人机协作**。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 写 **接管触发条件、角色权限矩阵、交接包字段、代操作 audit、人机互斥、话术模板 ID** |
| **方案评审** | 问：**L1 能否代重试？** 坐席改地址要不要 **重走审批？** **查到 PK 号** 谁有权 **代标 step 完成？** |
| **指标设计** | **接管率、接管后首次响应时长、unknown 人工解析时长、代操作占比、用户重复催单率、接管后 24h 复开率** |
| **跨团队沟通** | 对客服：**给权不给 root**；对客户 IT：**协同话术认哪个单号**；对研发：**接管与审批闸、幂等组件的边界** |

## 类比锚定

| 你熟悉的 PM 旧经验 | 人工接管话术与权限 |
|--------------------|-------------------|
| 快递 **「已转人工客服」** 且客服能看见 **运单号** | **交接包** 带 **run_id + 下游单号** |

| 司机端 **「乘客已改目的地，请确认」** 暂停导航自动重算 | **`handoff_in_progress`** 时 **AI 暂停自动写** |

## 类比边界说明

### A. 概念核心要点

1. **转人工是产品路径，不是例外**：要有 **触发条件、队列、SLA**，不能 **靠用户骂出来**。  
2. **权限按角色分级**：**大多数结案 = 查单 + 话术**；**代写操作** 极少数且 **audit**。  
3. **交接包 > 裸 trace**：坐席 **没时间读日志**；**推荐动作** 降培训成本。  
4. **话术是交付物**：**单号、是否要重批、预计时间** 要说清；**「帮您催」** 不算结案。  
5. **人机互斥**：人接时 **AI 别偷偷重试**；结案 **交还或终结 run**。

### B. 类比失效点

| 失效 | 为什么不能照搬 |
|------|----------------|
| **「像传统人工客服接管聊天」** | 办事 run 有 **步骤机、审批、下游单**；不是 **纯文本会话** |
| **「坐席啥都能帮用户点」** | **无审批代出库、无确认代入账** → **合规与双写风险** |
| **「转人工 = 失败」** | 指标上 **接管可以是成功路径**；别 **考核坐席「消灭人工」** |
| **「话术一套通吃」** | 对用户 **报单号**；对主管 **报审批仍有效**；对仓库 **报 PK**——**对象不同** |

## 本集 Checklist

**标准 / 规范流程**

- [ ] **接管触发** 自动化（unknown 超时、用户求助、重试耗尽）  
- [ ] **角色权限矩阵** L1/L2/L3 + **业务审批人** 边界  
- [ ] **交接包** 字段：run、审批号、下游单号、推荐动作  
- [ ] **代操作** 全量 **audit**；**无 approval 不得代写出库/入账**  
- [ ] **`handoff_in_progress`** 人机互斥  
- [ ] **三层话术** 模板（用户 / 审批人 / 协同方）  
- [ ] 账小言 **可查不可代确认** 单独规则  
- [ ] 指标：**接管率、解析时长、重复催单率**

**中小常用方案**

- [ ] 转人工 **自动带单号** 的交接包  
- [ ] L2 仅 **代标完成 + 代重试本步**  
- [ ] **三句用户话术** 下拉  
- [ ] 协同模板 **「请按 PK-xxx 拣货」**  
- [ ] 培训样例 run **做坐席演练**

**何时升级到完整版**

- 多班次坐席 **抢单 / 路由**；**跨租户** 接管；**视频核身** 后代操作；与 **S8 工单分派** 联动 **「派给对的人」**。
