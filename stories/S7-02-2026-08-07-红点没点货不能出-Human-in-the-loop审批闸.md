> 今日概念在知识树中的位置：S7-01 给 **办事链** 装了 **run 与步骤条**——张先生知道 **卡库存** 还是 **卡系统**。**断点续办** 上线后，新投诉来了：**工单建好了，滤芯却直接出了库**。**澄光制造** 设备主管在群里问：**「谁批准花这三千八？」** 今天拆 **Human-in-the-loop 审批闸**：**AI 小言** 走到 **花钱、发货、改账** 等 **写操作** 前，**必须有人点同意**——**不同意怎么办、审批单和 run 怎么绑、超时谁负责**。

### 场景白板（读故事前 30 秒）

- **本集入口**：**应用 B｜修小言**——**张先生** 在租户 **澄光制造** 里用 **AI 小言** 走 **报修 + 备件发货** 办事链；**阿梅** 盯客户工单与费用纠纷。
- **Human-in-the-loop（HITL）**：白话：**关键动作让人类点头**——不是「全程人工客服」，而是 **Agent 跑到写操作前停住**，等 **有权限的人** 在界面或飞书里 **批准 / 驳回**。
- **审批闸（Approval Gate）**：白话：办事链上的 **强制暂停点**——**未批准，工具不能真调**；批准后 **带着审批单号** 继续 **同一 run** 的下一步。
- **本集冲突**：**AI 小言** 在 **未获设备主管同意** 的情况下 **触发了出库**，仓库按单发货；事后 **费用归属扯皮**——**run 有进度条，却没有刹车**。

## 寓言故事

### 一、工单能办了，费用却先出了头

S7-01 灰度修复两周后，澄光制造的 **张先生** 在内部群里发了一条相对正面的反馈：**「这次报修 **知道卡在哪**，没再双单。」** 阿梅把截图转给林薇，备注：**「run 状态机算立住了。」**

新问题出在 **同一套办事链的下游**。

周五下午，张先生对着 **CF-220 冷却塔** 跟 **AI 小言** 说：

> **张先生**：上次轴承那单还在跟，这台 **滤芯 PM-8842** 到期了。帮我 **报修换芯**，有货的话 **直接发备件到我们车间**，别等工程师跑一趟仓库。

**AI 小言** 照例先开 run：**RUN-CG-20260822-011**。步骤条走得顺：

```text
① 识图确认机型 …… ✓
② 查质保 …… ✓（在保）
③ 查库存 PM-8842 …… ✓（仓内 3 件，单价 ¥1,280）
④ 创建售后工单 …… ✓（XR-2026-0822-063）
⑤ 创建备件出库单 …… ✓
⑥ 通知仓库拣货 …… ✓
```

张先生看见 **「备件已安排出库，预计今日 17:00 前送达车间」**，收工下班。

周一早上，澄光 **设备部主管老周** 在飞书 @ 了澄光 IT 服务台：**「上周五谁批的 **三台滤芯** 费用？张工那条线 **本月维修预算** 已经红了。小言 **没经过我就发货**？」**

IT 服务台坐席——**真人支持**——按惯例在星尘侧开了工单，标题：**「修小言 Agent 未经审批触发备件出库」**。坐席附了三张图：run 步骤条、出库单、老周在预算表里的红字截图。备注：**「用户张工反馈 **流程对了、授权错了**；主管要求 **费用类写操作必须审批**。」**

林薇收到 @ 后，先和小陈 **初判**：**不是模型幻觉，是 tool 真调了**；**不是 S7-01 状态机回退**，是 **状态机里少了一道闸**。

### 二、仓库说：你们没让我们停

周二会诊：林薇、阿梅、小陈、大刘（WMS 对接），澄光 IT 与 **真人支持** 坐席在线。

小陈先把 **RUN-CG-20260822-011** 的 trace 投屏：

```text
step_4 create_ticket(idempotency_key=run_011) → OK, ticket=XR-063
step_5 create_shipment_order(part=PM-8842, qty=3, ship_to=车间B)
       → tool 调用成功，无 approval_id 字段
step_6 notify_warehouse → OK
```

大刘指着 **step_5**：**「WMS 只认 **出库单号** 和 **库存扣减**——**谁批的**，我们接口里 **没字段**；你们平台 **没拦**，我们就 **按单拣货**。」**

阿梅转述老周原话：**「我不是不让换芯，是要 **在花钱前看见我批过**。** 张工现场图省事，一句 **直接发货**，小言 **当真了**。」**

张先生在工单备注里写得很委屈：**「我以为 **在保就免费走**——谁知道 **滤芯要算线体成本**？主管骂我 **先斩后奏**。」**

林薇在白板上画了一条线，把 S7-01 和今天的问题分开：

```text
S7-01 解决：办到哪、卡在哪、别双单
S7-02 解决：办之前，谁有权让「真写库」发生
```

**「问答时代，错答可以撤回；办事时代，**出库单出去 **就难收。** 护栏老关能拦 **脏话和越权导出**（S6），但 **「该不该花这笔钱」** 是 **业务审批**，不是 **安全策略**——要 **HITL 审批闸**。」** 她说。

小陈补充技术事实：**「`create_shipment_order` 在配置里标的是 **写操作**，但 **审批策略 = 无**；模型在 step_4 成功后 **合法地** 调了 step_5——**产品没定义 pause**。」**

### 三、刹车片要长在 run 的第四步和第五步之间

林薇让产品同学把 **修小言报修剧本** 摊开，标 **哪些 step 只读、哪些要写、哪些写要闸**：

| 步骤 | 工具 | 读/写 | 是否建议审批 |
|------|------|-------|--------------|
| 识图 | `recognize_device` | 读 | 否 |
| 查质保 | `query_warranty` | 读 | 否 |
| 查库存 | `query_spare_part` | 读 | 否 |
| 建工单 | `create_ticket` | **写** | 可选（低金额自动过） |
| **出库发货** | `create_shipment_order` | **写** | **是**（费用/库存） |
| 通知仓库 | `notify_warehouse` | 写（消息） | 跟走出库 |

**「闸不是加在聊天入口，是加在 **run 的某两步之间**。」** 林薇强调，**「用户说 **帮我发货**，Agent 可以 **规划到 step_5**——但 step_5 的 tool **不能真执行**，直到 **审批通过**。」**

她画了一张状态转移草图：

```text
step_4 done → step_5_pending_approval
                    │
         ┌──────────┼──────────┐
         ▼          ▼          ▼
    approved     rejected    timeout
         │          │          │
    调 tool     run 暂停    转人工/取消
    继续 run    通知用户    通知主管
```

小陈问：**「谁批？老周还是张工自己？」**

林薇：**「**租户配置**：澄光这条线 **出库金额 > ¥500** → **设备主管角色**；张工可以 **发起**，不能 **自批自花**。** 审批人不在线 → **超时策略** 写清楚，不能 **默认通过**。」**

阿梅想起 **账小言** 对照：**「苏姐说过，**`importReconciliation` 入账** 也是——**JSON 生成** 可以自动，**写 ERP** 必须 **财务接口人点确认**。** 同一套 **办事 run**，不同应用 **闸绑在不同 step**。」**

### 四、双轨落地：审批闸怎么装

林薇提交 **《修小言 / 账小言 HITL 审批闸双轨方案》**。

**标准 / 规范流程（多租户合同、费用敏感、审计要求高）**

| 层级 | 做什么 |
|------|--------|
| **写操作分级** | 产品维护 **工具目录**：只读 / 写-低敏 / 写-高敏（花钱、改库存、入账、对外通知）；**高敏默认必闸** |
| **审批策略引擎** | 按 **租户 + 应用 + 工具 + 条件**（金额、物料类型、产线预算）决定：**自动过 / 单人批 / 多级批 / 禁止** |
| **闸与 run 绑定** | 触发审批时 run 进入 **`awaiting_approval`**；生成 **`approval_id`**，与 **`run_id + step_name`** 一对一；**批准后** 用 **同一 approval_id** 调 tool，**拒绝** 则 run **`rejected` 可解释** |
| **审批载体** | 飞书/钉钉 **卡片** + 修小言 **审批中心**；卡片展示 **摘要、金额、引用工单、run 链接**；**一键批/驳** |
| **权限** | 审批人来自 **客户 IAM 角色**（设备主管、财务接口人）；**发起人 ≠ 审批人**（可配置例外） |
| **超时与升级** | 例如 **4 小时未批** → 通知升级 + run **保持暂停**（**禁止** 静默自动通过）；可选 **转真人支持** |
| **审计** | 日志：**谁、何时、批/驳、批注**；与 S6 权限 **可审计** 对齐 |
| **模型侧** | 提示词：**未拿到 `approval_token` 不得声称已发货**；UI **步骤条显示「待主管批准」** |

**中小常用默认方案（星尘当前可卖）**

- **「三张表起步」**：`approval_policy`（哪几个 tool 要批）+ `approval_request`（待办）+ run 状态 **`awaiting_approval`**。  
- **「硬编码两闸」**：报修链只闸 **`create_shipment_order`** 和 **`create_purchase_request`**；账小言只闸 **`importReconciliation`**——**先覆盖 80% 纠纷**。  
- **「单级单人批」**：金额 **> ¥500** → 推 **设备主管** 飞书卡片；**≤ ¥500** 且 **在保** → **自动过**（可关）。  
- **「驳回可续办」**：驳回后 run **不删**；用户可 **改数量 / 改地址 / 取消发货**，从 **step_5 重新发起审批**——**不重头识图**。  
- **「话术模板」**：**「已为您准备好出库申请，待 **周主管** 批准后即可发货；您无需重复报修。」**  
- **可暂缓**：可视化 **审批流编排器**、**会签 / 或签**、与 **客户 OA 双向同步**——等 **费用纠纷 ≥2 起/月** 或 **合同写审计条款** 再上。

阿梅问澄光：**「老周希望批在哪？」**

老周回复很具体：**「我手机飞书 **红点** 点一下就行；**没点之前，仓库别动。** 张工可以看见 **「等您主管批准」**，别写 **已发货**。」**

### 五、接近结尾：红点没点，货不能出

方案灰度第三周，张先生又走了一遍 **换芯 + 发货**——同一滤芯，数量改成 **1 件**。

**AI 小言** 回复：

> 报修任务 **RUN-CG-20260905-018** 进行中：  
> ①–④ 已完成，工单 **XR-0912-071** 已创建。  
> **⑤ 备件出库（PM-8842 ×1，约 ¥1,280）— 待审批**  
> 已提交 **设备主管周建国** 批准。批准前 **不会出库**。

老周手机弹出飞书卡片：**「张工申请：CF-220 滤芯出库 ×1，送车间 B。** [批准] [驳回] [查看 run]」**。他点了 **批准**。

十秒后，张先生界面 **⑤ 变绿**，**⑥ 通知仓库** 才执行。步骤条最后一行：**「主管已于 14:32 批准，预计今日送达。」**

老周在澄光内部群说了一句：**「这才像 **派工**，不像 **先发货后补票**。」**

林薇在复盘里写 S7 第二句人话：

**「Agent 办事，**读** 可以快，**写** 要能停。** 审批闸是 **写操作前的强制暂停**——**模型想办 ≠ 系统真办**；**人点同意 ≠ 聊天里说一句好的**。」**

小陈把字段名写在角上：**`approval_id` · `approval_token` · `run_status=awaiting_approval`.** 阿梅补对照：**「账小言那边，苏姐的 **入账确认** 也是同一张闸——**只是审批人换成财务接口人**。」**

张先生回访：**「等老周点头那半天，我 **至少没背锅**。」**

## 概念正解

**Human-in-the-loop 审批闸（HITL Approval Gate）** 指：在 **Agent 办事链** 中，对 **会产生业务后果的写操作**（出库、采购、改价、入账、对外发通知等），系统在 **真正调用工具之前** 强制进入 **等待人工批准** 状态；**有权限的人** 在指定界面 **批准或驳回** 后，**同一 run** 才继续或终止。**HITL** 强调 **关键节点有人把关**；**审批闸** 强调 **产品化的暂停机制**——与 **聊天里随口说「好的」** 不同，**批准** 要产生可审计的 **`approval_id`**，并与 **`run_id + step`** 绑定。

回扣故事：S7-01 修好的 **run 与步骤条** 让张先生 **看见进度**；但 **`create_shipment_order` 无闸**，模型 **合法调用** 导致 **未批先发货**；双轨方案用 **写操作分级、审批策略、run 暂停态、飞书卡片、驳回可续办** 把 **「想发货」** 和 **「真出库」** 拆开。

在 **S7 · Agent 从演示到值班** 中的位置：**基础偏应用**——状态机立住后，第二道关是 **写操作谁点头**；后续 **工具失败重试与补偿**、**人工接管** 会叠加在 **已批准 / 已驳回 / 待批** 的 run 之上。**没有审批闸，重试可能重复发货；人工接管也不知道「卡在等谁批」。**

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 每个 tool 标 **读/写**；写操作写清 **触发审批条件、审批人角色、超时、驳回后用户路径** |
| **方案评审** | 问：**未批时 tool 是否物理不可调？** 模型能否 **口头说已发货**？**approval_token** 如何防伪造？ |
| **指标设计** | **待批时长 P95、驳回率、超时转人工率、未批误调用率（应为 0）** |
| **跨团队沟通** | 对客户 IT：**IAM 角色与审批人映射**；对仓库：**无 approval_id 不出库**；对财务（账小言）：**入账闸与报修闸复用组件** |

## 类比锚定

| 你熟悉的 PM 旧经验 | HITL 审批闸 |
|--------------------|-------------|
| 报销单 **提交 → 主管批 → 财务打款** | **run 暂停 → 审批 → 调写操作 tool** |
| 电商 **货到付款 / 大额订单人工审核** | **金额阈值触发闸**；未审 **不下单给仓库** |
| 发布 **变更窗口 + 负责人点发布** | **高敏 tool = 生产写库**；**批准 = 发布按钮** |
| 合同 **双章生效** 前不能履约 | **approval_token 到位** 前 **tool 层拒绝** |
| 飞书 **请假条待审批** | **审批卡片** 绑 **run 摘要**；**驳回到发起人** |

## 类比边界说明

### A. 概念核心要点

1. **闸在 tool 前，不在聊天后**：**批准** 是 **系统状态**，不是 **用户回复「可以」**。  
2. **与 run 强绑定**：**`awaiting_approval`** 要有 **唯一 approval_id**；**续办、审计、客服** 都查这一张单。  
3. **写操作分级**：不是 **每一步都要人批**——**读多写少**，**写里再分高低敏**。  
4. **默认拒绝执行**：**超时 ≠ 自动通过**；**未批** 时 **tool 层硬拦**，靠 **提示词不够**。  
5. **发起人 ≠ 审批人**：现场工程师 **可发起**，**花钱授权** 在主管/财务。

### B. 类比失效点

| 失效 | 为什么不能照搬 |
|------|----------------|
| **「和 OA 审批流完全一样」** | Agent **步骤可动态**（先查库存再决定要不要发货）；闸是 **按 tool + 条件** 触发，不是 **固定 12 个表单节点** |
| **「人工客服点头就行」** | 客服 **无 IAM 角色** 不能代批 **产线预算**；**HITL** 要 **权限系统**，不是 **任意真人** |
| **「驳回就整条 run 作废」** | 常见是 **改参数重提审批**（少发一件、换地址）；**run 保留** 已成功只读步 |
| **「护栏老关已经拦了」** | 老关拦 **安全与合规话术**；**花谁的钱、动谁的库存** 是 **业务审批**，机制不同 |

## 本集 Checklist

**标准 / 规范流程**

- [ ] **工具目录** 标注读/写；**高敏写操作** 默认 **必闸**  
- [ ] **审批策略**：租户 × 工具 × 条件（金额、角色、预算）  
- [ ] run 状态 **`awaiting_approval`**；**`approval_id` ↔ `run_id + step`** 一对一  
- [ ] **未批时 tool 层拒绝**；模型 **不得声称已完成写操作**  
- [ ] 审批 **飞书/钉钉卡片 + 应用内审批中心**；**发起人 ≠ 审批人**（可配置）  
- [ ] **超时升级**；**禁止静默自动通过**  
- [ ] **审计日志**：谁、何时、批/驳、批注；对接 S6 **可审计**  

**中小常用方案**

- [ ] **硬编码两闸**：出库 + 采购（报修）；**入账确认**（账小言）  
- [ ] **单级单人** + **金额阈值 ¥500**（示例，租户可调）  
- [ ] **三张表**：policy / request / run 状态扩展  
- [ ] **驳回可改参重提**，不 **重头 run**  
- [ ] **固定话术**：「待 XX 批准，批准前不会出库」  

**何时升级到完整版**

- **费用/库存纠纷 ≥ 月级**；合同 **审计条款**；需 **多级会签、OA 同步**；**同一 run 多闸串联**；与 **补偿事务**（S7-03）联动。
