## 寓言故事

### 一、温度稳了，标题还是偶尔「跑偏」

温度事故回滚后的第二周，林薇以为 **商小言** 的 FAQ 窗口总算能睡安稳觉了。退货口径 **同问十次，关键结论一致**；营销文案入口单独挂着 **高温模板**，还带 **「请人工审核」** 水印。

偏偏 **商品标题生成** 又出了新幺蛾子。

某家居商家批量上传了三十款 **「北欧风实木餐椅」**，让 **商小言** 一键出 **淘宝/拼多多标题**。前二十八个还算正常，第二十九个标题里突然蹦出 **「皇室御用·御膳房同款·北欧实木椅」**——商家运营截图发群：**「我们卖的是 299 的椅子，这词敢上吗？」**

林薇拉日志：上岗剧本没动，检索片段只有 **材质、尺寸、风格** 三类合规字段；**Temperature 0.75**，在营销工具允许的区间内。她困惑：**「温度没超标，怎么还会冒出这种词？」**

小陈把 **推理参数面板** 全屏投出来。在 Temperature 下面，还有一行她上周才匆匆略过的控件：

**Top-p：0.95**  
小字：**从概率最高的词开始累加，直到累计概率达到 p，只在这个候选池里抽样。**

**「温度管每个词『有多敢冒险』；Top-p 管你 **敢把多大的候选名单摊开**。两个一起拧，效果会叠乘。」** 小陈说。

---

### 二、名册太长，离谱词也能进候选

为了复现，小陈在预发环境 **固定用户输入和检索结果**，只改 Top-p，连跑五组。

同一款餐椅、同一份卖点清单：

| Top-p | 五次标题里出现的「怪味」 |
|-------|--------------------------|
| **0.3** | 几乎全是 **「北欧实木餐椅 家用靠背」** 一类，略闷，但无违禁夸张词 |
| **0.7** | 出现 **「简约」「轻奢」「小户型」** 等正常营销词，偶有 **「爆款」** |
| **0.95** | 开始有 **「宫廷风」「御用」** 等低概率但「听起来很促销」的词 |
| **1.0** | 有一次直接带上 **「国家级非遗工艺」**——检索里根本没有 |

林薇盯着最后一行：**「Top-p 到 1.0，是不是等于 **不裁剪候选池**？」**

小陈点头：**「很多厂商默认 1.0，意思是 **全量候选都留着**。配合偏高的温度，就等于在 **很长的名册末尾** 也能抽到词——那些词 **整体概率低**，但 **并非绝对不可能**，所以偶尔会冒出来。」**

阿梅在旁辩解：**「厂商文档示例里 Top-p 和 Temperature 都写得挺高，我以为 **创意场景就该全开**。」**

林薇在复盘板上写：

**「温度高 = 在名册里 **更敢点冷门**；Top-p 高 = **名册本身就很长**。两个都高，FAQ 会飘，标题会吹。」**

---

### 三、掐头留尾：不是删词，是划边界

小陈在白板上画了一条 **从大到小排列的概率长条**，像一排 **候选人名牌**：

**「模型每写一个字，内部会先给 **所有可能的下一个词** 打个分，再排序。Top-p 的做法是：从第一名开始往下加，**加到累计概率刚好超过 p** 为止——这份 **掐头留尾** 出来的子集，就叫 **核（nucleus）**。」**

**「只在核里抽签。p 越小，名册越短，越像 **只从头部几个「大概率词」里选**；p 越大，名册越长， **尾巴上的怪词也有机会进池**。」**

林薇联想到招聘：**「像不是面试全城求职者，而是 **先划一条及格线：累计『够格』的人占到 90%** 再复试？」**

**「对。温度则是在复试里 **敢不敢给边缘候选人机会**。两个参数别混成一个旋钮。」**

当晚他们改了三件事：

1. **商品标题接口**：Top-p **0.7–0.85**，Temperature **0.7**；日志 **强制落库两者**；  
2. **FAQ / 制度 / 内小言**：Top-p **≤ 0.3**，Temperature **≤ 0.2**——**短名册 + 低冒险**；  
3. 配置台 **禁止租户把 Top-p 调到 1.0** 同步到 **全站默认**，创意工具需 **单独接口覆盖**。

阿梅问：**「那我把 Top-p 调到 0.1，是不是就绝对安全？」**

小陈摇头：**「名册太短，标题会 **千篇一律**，商家又说 **『像机器人』**。产品要的是 **分场景默认值**，不是 **极端避险**。」**

### 四、内小言的「过度保守」与双轨方案

同一周，**内小言** 收到星尘 HR 的反馈。

李女士连问三次 **「试用期能不能请婚假」**，三次答复 **核心结论一致**——**「试用期员工不适用婚假」**——但第三次多了一句 **「具体以劳动合同为准」**，第一次却没有。HR 苏姐问：**「温度都 0.1 了，怎么还会有这种差别？」**

日志显示：**Top-p 被某次灰度误设为 0.95**（与低温打架），修复前 **候选池过长**，低温只是在 **长名册里偏向头部**，仍偶尔抽到 **不同的礼貌尾巴句**。

修复后 Top-p **0.2**，同问十次，连 **尾巴句都一致** 了。李女士却吐槽：**「像复制粘贴。」**

林薇在 **双轨** 文档里补了一页：

**标准 / 规范流程（多租户、强审计）**

| 环节 | 做什么 |
|------|--------|
| **参数组合** | **FAQ/制度**：低 Top-p + 低 Temperature；**创意/标题**：中高 Top-p + 中高温，**分接口** |
| **变更门禁** | Top-p 默认值变更 = **二级发布**；PRD 写 **与温度的组合区间**，禁止单参数「拍脑袋」 |
| **评测** | 固定集 **同问 10 次**；抽 **低概率违禁词**、**标题夸大**、**口径尾巴不一致** |
| **可观测** | 日志 **temperature + top_p** 成对出现；事故复盘还原 **组合** 而非单旋钮 |

**中小常用默认方案（星尘当前）**

- **接云 API**：多数厂商 **Top-p 默认 1.0**；星尘 **FAQ 类强制 0.1–0.3**，创意 **0.7–0.9**，**前台不暴露 Top-p**，只映射 **「保守 / 标准 / 发散」** 体验档。  
- **可暂缓**：与 **老何（模型路由）** 联动「创意走四楼、FAQ 走二楼」——先 **参数分接口**，再 **路由分模型**。  
- **升级触发**：若 **标题/文案违禁词** 或 **同问尾巴句打架** 两周超阈值，再开 **剧本与检索** 评审，**不要先用极端 Top-p 掩盖剧本不清**。

### 五、接近结尾：名册与骰子，是两件兵器

又一周，商小言 **标题工具** 出的文案 **活但不再吹**；退货 FAQ **连礼貌尾巴都一致**；配置台帮助文档多了一张 **「参数组合卡」**：

| 场景 | Temperature | Top-p | 产品备注 |
|------|-------------|-------|----------|
| 制度/FAQ | 低 | 低 | 短名册，少冒险 |
| 商品标题 | 中 | 中高 | 允许营销词，禁夸大 |
| 头脑风暴 | 高 | 高 | 仅预发/人工审核 |

林薇给新同学讲岗，指着 **Top-p** 那一栏：

**「用户感觉不到这个参数，但会感觉到 **离谱词变多还是标题变水**。它不是第二个温度——是 **每写一个字之前，先圈定多长的候选名册**。」**

小陈把英文写在旁边：**Top-p，Nucleus Sampling，核采样。** 阿梅改参数前先问第二句：**「名册要 **多长**？场景是 **FAQ 还是标题**？」**

张先生在 **修小言** 群里补刀：**「故障码解释：**短名册**；备件促销文案：**名册可以长一点**，但别长到 **瞎编型号**。」** 林薇记下来：**同一应用，依然可以 **分场景拆 Top-p**——和温度一样，**别全站一个数**。

## 概念正解

**Top-p / 核采样（Nucleus Sampling）**，是大语言模型在生成 **每一个词（Token）** 时用的 **候选池裁剪参数**：模型先给所有可能的下一个词排概率，再从 **概率最高的词开始累加**，直到累计概率 **达到 p**，只在这个 **「核」** 子集里抽样选词。**p 越小**，候选池 **越短、越保守**，输出 **更单调但更稳**；**p 越大**，候选池 **越长**， **低概率但「看起来合理」的词** 也会进池，输出 **更多样，也更容易出现夸张、跑偏表述**。它 **不改变模型知识**，也 **不能替代** System Prompt、RAG 或护栏；常与 **Temperature** 配合——**Top-p 划名册边界，Temperature 决定在名册里有多敢点冷门**。

回扣故事：标题出现 **「御用」** 是 **Top-p 过高 + 温度不低 → 长名册尾部怪词进池**；内小言尾巴句不一致是 **低温配高 Top-p → 名册长但偏向头部，仍偶有差异**；分接口与组合卡是 **产品按场景定「名册长度 + 冒险度」**，而非单滑块或厂商默认 1.0 通吃。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 写明 **Top-p 默认值、允许区间、与 Temperature 的组合**；标题类写 **禁用夸大词清单 + 同批生成方差上限** |
| **方案评审** | 问：Top-p 是否 **1.0 等于不裁剪**？与温度 **叠乘后** FAQ 会不会仍飘？创意场景 **名册太短** 会不会伤商家满意度？ |
| **指标设计** | 低概率违禁词命中率、同问关键句一致率、标题 **人工采纳率 / 驳回率**、参数组合变更后的回归通过率 |
| **跨团队沟通** | 对运营：**「发散档 = 长名册 + 较高温度，只给标题工具」**；对算法：**「日志请 temperature、top_p 成对落库」**；对法务：**「夸大词往往是 **长尾候选** 问题，不全是剧本漏写」** |

## 类比锚定

**核心类比：招聘里的「累计及格线划复试名单」。** HR 不会面试全城所有人，而是按简历打分排序，**从上往下累加，直到「够格」的人累计占到设定比例（比如 90%）**，只在这份 **复试名单** 里安排面试；**Temperature** 则是在复试里 **面试官敢不敢给边缘候选人发 offer**。

| 你熟悉的 PM 经验 | Top-p 要素 |
|------------------|------------|
| 简历筛选 **「取前 30% 累计匹配度」** 再安排面试 | **从头部累加概率直到 p，构成候选池** |
| **复试名单太长** → 鱼龙混杂、浪费时间 | **Top-p 过高 → 低概率怪词进池** |
| **名单只留前三名** → 候选人千篇一律 | **Top-p 过低 → 标题/文案太模板** |
| 面试环节 **「敢不敢录用非第一名」** | **Temperature（与 Top-p 分工不同）** |
| 技术岗 **严筛**、创意岗 **宽进** 的不同招聘策略 | **FAQ 低 Top-p / 营销工具较高 Top-p** |

## 类比边界说明

### 一、概念核心要点

1. **Top-p 管的是「每步候选池有多长」**，从 **高概率词向下累加** 直到累计概率达到 p；不是「删掉低分词」那么简单，而是 **动态划界**。  
2. **常与 Temperature 叠乘**：**短名册 + 低温** → 极稳；**长名册 + 高温** → 极飘；产品要 **组合设计**，不能只看一个旋钮。  
3. **厂商默认 Top-p = 1.0** 往往等于 **几乎不裁剪**；ToB 场景 **FAQ/制度应主动压低**，创意工具 **单独区间**。  
4. **Top-p 过低会伤体验**：不是越保守越好，可能出现 **千篇一律、像复制粘贴**。  
5. **不能替代剧本与检索**：名册再短，**检索错、剧本漏写** 仍会答错；Top-p 只影响 **「在合理续写里选哪条」**。

### 二、类比在哪里会失效

| 类比说法 | 失效点 | 更准确的理解 |
|----------|--------|--------------|
| 「像招聘只要前 10 名」 | 候选池是 **按概率动态累加**，不是固定人数；每个位置的 **名册长度随上文变化** | **每生成一个词，名册重新算一遍** |
| 「Top-p 低就等于温度低」 | 两者 **机制不同**，可能出现 **低温 + 高 Top-p** 仍有一定方差 | **名册长度** 与 **名册内冒险度** 是两颗螺丝 |
| 「调到 0.1 就绝不会出违禁词」 | 低概率词若 **仍在核内** 仍可能被抽到；违禁还来自 **幻觉、剧本缺失** | Top-p 降 **夸大/怪词概率**，不保证 **事实正确** |
| 「创意场景 Top-p 拉满就好」 | 1.0 常配合高温会 **放大胡编与夸大** | 创意也要 **上限 + 人工审核 + 禁用词** |
