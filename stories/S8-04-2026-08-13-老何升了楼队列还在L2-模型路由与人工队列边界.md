### 场景白板（读故事前 30 秒）

- **本集入口**：**小言平台** 里有两套 **并行决策**——**老何（模型路由）** 管 **AI 对话走几楼模型**；**工单台** 管 **真人支持派给谁**。本篇讲 **边界契约** 与 **SLA 分层**。
- **模型路由（Model Routing）**：白话：**每条用户消息** 进网关时，按 **意图复杂度、成本、合规** 选 **模型档**（一至四楼）——**影响 AI 回答质量与延迟**，**不直接等于** **工单进哪个技能组**。
- **人工队列（Human Queue）**：白话：**需要真人接手的工单** 在 **技能组池里排队**——看 **S8-01～03 的分类、路由、改派**；**SLA** 通常挂 **「首次人工响应」「排队时长」**。
- **本集冲突**：**四楼 AI 已给出方案**，**L2 工单 SLA 仍超时**；**商小言 AI 会话未失败**，却 **误触发转人工**——**两条线没对齐，指标也挂错层**。

### 一、对话里已经「四楼」，工单屏上还是「排队中」

S8-03 上线一周，**修小言 L2 运营阿凯** 的屏上 **派单解释** 终于能展开——**RUN-054** 进来时，第一行清清楚楚：

### 四、双轨方案：边界契约 + SLA 分层

林薇提交 **《模型路由与人工队列边界及 SLA 双轨方案》**。

**标准 / 规范流程**

**1. Handoff 契约（对话 → 工单）**

| 触发类型 | 谁决定 | 必须同步字段 | 禁止 |
|----------|--------|--------------|------|
| **run 黄灯 / 用户点「联系支持」** | 应用规则 + S8 分类 | `run_id`、`intent_id`、**AI 对话摘要**、`last_model_floor` | 仅凭 **消息条数** 转人工 |
| **AI 明确失败**（工具超时、护栏拦截） | 对话层 | `failure_code` + 摘要 | 静默丢单 |
| **用户主动要求人工** | 用户 | 原话 + 摘要 | 无 |
| **仅对话升四楼** | **老何** | **不自动建单**（除非 run 策略要求） | floor=4 ⇒ 工单升级 |

**2. SLA 分层**

| SLA 指标 | 挂哪一层 | 起算点 | 示例阈值 |
|----------|----------|--------|----------|
| **AI 首 token** | 对话层 / 老何 | 用户发送 | P95 < 2s（三楼） |
| **AI 完整答复** | 对话层 | 用户发送 | P95 < 12s（四楼） |
| **工单首次人工响应** | 工单层 | **分配坐席后** 或 **用户明确要求人工后** | P2 < 15min |
| **池内排队时长** | 工单层 | 入 **目标技能组池** | 告警 > 10min |
| **端到端解决** | 业务层 | 建 run / 建工单 | 按租户合同 |

**RUN-054 修正**：**池内等待** 单独打点 **`queue_wait_ms`**；**SLA 红灯** 拆成 **「等坐席」** 与 **「坐席处理中」**；**AI 已输出有效答案** 时，**用户侧展示**：**「仓库状态已由助手更新，人工回电将补充确认」**——**不再只显示「排队中」**。

**3. 分派准确率（Dispatch Accuracy）指标族**

| 指标 | 定义 | 用途 |
|------|------|------|
| **意图准确率** | `intent_id` 与事后标注一致 | S8-01 门禁 |
| **首次路由准确率** | 首派技能组 **能办结** 或 **无需改派** | S8-02 门禁 |
| **改派率** | 首次派单后 **24h 内改派占比** | S8-03 体验 |
| **误转人工率** | AI 已结案仍进池 / 用户未请求 | **边界层** 门禁 |
| **上下文完整率** | 人工接单时 **带 AI 摘要** 占比 | handoff 契约 |

**REF-902 修正**：下线 **`message_count >= 6`** 规则；改为 **`ai_resolution_failed` OR `user_request_human` OR `sentiment_escalation`（带置信度）**；转人工 **强制带 `ai_handoff_summary`**。

**中小常用方案**

- **按 app_id 分池** + **run 带 `run_id` 前缀**（S8-01 已做）  
- **转人工仅两触发**：用户按钮 + AI 回复含 **「建议您联系人工」**  
- **SLA 只盯一个数**：**首次人工响应 < 30 分钟**（从 **分配坐席** 起算）  
- **每周人工抽 20 单** 标 **误转人工 / 路由错组**  
- **老何楼层** 与 **工单组** **不做自动映射**——**文档写死「正交」**

**何时升级到完整版**

- **统一队列多租户**；**AI 与人工混排** 需 **联合看板**；**误转人工** 造成 **大量空接**；客户合同 **区分 AI 段与人工段 SLA**；需 **`handoff 契约` 版本化 + 实时准确率门禁**。

## 概念正解

**模型路由与人工队列边界** 指：在 **同一平台** 上，**AI 对话的模型选档（老何）** 与 **真人工单的分派排队（S8 工单台）** 是 **两套正交决策**——前者优化 **单轮回答的质量与成本**，后者优化 **谁接单、排队多久、改派可审计**；二者 **仅在 handoff（转人工/建工单）瞬间** 通过 **契约字段**（意图、run_id、AI 摘要、失败码）同步，**不能用模型楼层映射技能组**，也不能用 **机械关键字** 替代 **「AI 真失败或用户真要人」**。

**分派准确率** 是 **工单层** 指标族：意图准、首派组准、少改派、少误转人工、人工接单带上下文。**排队 SLA** 需 **分层**：**AI 延迟** 挂对话层；**池内等待、首次人工响应** 挂工单层；**端到端业务时效** 挂合同层——**混挂则必误报**（如 AI 已答完仍显示「排队超时」）。

回扣故事：**RUN-054** **四楼 AI 已给停产替代**，**L2 池内仍漂二十一分钟**——根因是 **SLA 从建单起算 + 用户只见「排队中」**；**REF-902** **AI 结案后仍被第六条消息规则踢进人工池**——根因是 **对话层与工单层触发器未对齐**。**双轨方案** 用 **handoff 契约、SLA 分 phase、误转人工率、双栏看板** 收官 S8。

在 **S8 · 平台端 AI 分派工单** 中的位置：**进阶收官**——全季第五条 **「和模型路由差在哪、看什么指标」**；与 **第 19 篇老何** 形成 **跨季对照**，**S8 正式收官**。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 写 **handoff 触发枚举**、**禁止规则清单**（如 floor→skill_group 映射）、**`ai_handoff_summary` 字段** |
| **方案评审** | 问：**SLA 从建单还是分配起算？** **AI 已答是否还算排队超时？** **转人工默认带几轮摘要？** |
| **指标设计** | **对话层 P95 latency** vs **工单层 pool_wait P95** vs **misroute_to_human_rate** |
| **跨团队沟通** | 对算法：**楼层不是坐席组**；对客服：**接单屏必须有 AI 摘要**；对客户成功：**合同写清 AI 段与人工段** |

## 类比边界说明

### A. 概念核心要点

1. **正交不映射**：**模型楼层** 表达 **算力/能力档**；**技能组** 表达 **人能办什么事**——**四楼的「停产长答」** 可由 **L2 运营电话确认**，**不必存在 L4 坐席组**。  
2. **Handoff 是唯一同步面**：**平时各跑各**；**转人工/建工单** 时 **必须带上下文包**——**省掉摘要 = 逼用户重讲第三遍**。  
3. **SLA 分 phase**：**queue_wait**、**first_human_response**、**handle_time** **分开统计**——**否则 AI 帮用户省了时间，** KPI 仍红**。  
4. **误转人工是边界层核心指标**：比 **「多接几单」** 更伤体验——**人工空接、商家吓短信、坐席骂系统**。  
5. **准确率要分母清晰**：**首次路由准确率** 的分母是 **首派单**；**意图准确率** 要 **事后标注集**——**不能用一个「满意度」糊所有层**。

### B. 类比失效点

| 失效 | 为什么不能照搬 |
|------|----------------|
| **「像 IVR，按 0 永远进人工」** | AI 产品 **转人工** 应 **条件化**——**否则模型省钱目的落空** |
| **「对话和工单必然 1:1」** | 一 run **可仅 AI 结案**；一会话 **可建 0 张或多张工单** |
| **「SLA 越短越好」** | **四楼模型 + 长工具链** 必然拉高 **AI 段延迟**——**要与 **用户预期文案** 对齐，不是一味压 floor** |
| **「路由准确率 100% 才上线」** | **边界层** 更要盯 **误转人工** 与 **摘要完整率**——**完美首派不现实，但别空转人工** |

## 本集 Checklist

**标准 / 规范流程**

- [ ] **handoff 契约** 文档化：**触发枚举 · 必带字段 · 禁止规则**  
- [ ] **明确不写** `floor → skill_group` 自动映射  
- [ ] **SLA 分 phase**：`queue_wait` / `first_human_response` / `handle_time`  
- [ ] 转人工 **强制 `ai_handoff_summary`** + **`last_model_floor` 仅作参考**  
- [ ] 指标分栏看板：**对话层** vs **工单层**  
- [ ] 门禁：**误转人工率**、**上下文完整率**、**池内等待 P95**  
- [ ] 用户侧 **AI 进展与人工排队分开展示**  
- [ ] **handoff_contract_version** 与 **routing_policy_version** 同样可复盘  

**中小常用方案**

- [ ] 转人工 **仅用户按钮 + AI 明确失败**  
- [ ] SLA **只盯「分配后首次响应」**  
- [ ] **周抽 20 单** 标误转人工  
- [ ] **文档一页纸**：老何楼层 ≠ 工单组  
- [ ] 人工接单屏 **固定展示 AI 最后三轮摘要**  

**何时升级到完整版**

- **多租户统一队列**；合同 **区分 AI/人工 SLA**；**误转人工** 造成 **坐席空接成本**；需 **实时双栏大盘 + handoff 版本门禁 + 与 S7 run 状态机联动**。
