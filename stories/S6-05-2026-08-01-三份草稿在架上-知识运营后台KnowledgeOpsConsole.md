### 场景白板（读故事前 30 秒）

- **本集入口**：**应用 C｜内小言**——澄光制造飞书里的 **AI 小言**；**王姐** 是客户侧 HR 接口人（管制度上传）；**李女士** 等是普通员工。
- **知识运营后台（Knowledge Ops Console）**：白话：**管知识库「从上传到能被检索引用」全流程的操作台**——谁上传、谁审核、谁点发布/下架、状态是什么、什么时候生效，**一张表能看清**。

- **真人支持**：澄光 IT 服务台坐席建工单 → 星尘 **林薇**（对口 PM）与值班研发 **小陈** 初判；**不** 由比喻角色独自定级。

## 寓言故事

### 一、同一条问题，三张截图

澄光脚注体验修顺后的那个周一，工艺部飞书群又热闹起来——这次不是「高亮少半页」，而是 **口径打架**。

李女士问 **AI 小言**：**「今年育儿假新增那几天，要不要一次性休完？」**

小言答得干脆，脚注也工整。她把截图发到群里，想帮刚休完产假的同事。

五分钟后，同部门的赵工贴了 **另一张截图**：小言说 **「可拆分使用，每年最多分两次」**，脚注指向 **《休假管理办法（2025.8 版）》§3.4**——和李女士那张 **「须一次性休完」** 正面冲突。

又过一会儿，刚入职的实习生小周怯生生发第三张：**「我这边小言说 **查不到育儿假新增条款**，让我联系 HR。」** 脚注只有 **旧版 2024 年办法** 里的产假段。

王姐被 @ 进群里，脸色不好看。她在上周五下班前明明 **把 HR 定稿 PDF 拖进了内小言知识库**，文件名清清楚楚：《澄光制造员工休假管理办法（2025.8 版）》。她以为 **拖进去就等于全员能看见**。

澄光 IT 服务台坐席很快建了工单，备注：**「同一租户、同一问题，三人三种答案；疑似 **知识库内容不一致** 或 **发布流程** 问题。请星尘侧协助初判。」**

林薇收到转单，在内部频道 @ 值班研发小陈：**「非模型随机，先查 **库里到底有几份休假办法、各自什么状态**。客户 HR 称已上传新版，请核对是否 **未发布** 或 **多版本并存**。」**

---

### 二、上传了，不等于上架

小陈把澄光租户 `tenant_cg` 的知识库列表导出，王姐凑在屏幕前，越看越心虚。

```text
doc_id          文件名                              状态        上传人    上传时间           发布时间
cg-leave-2024   休假管理办法（2024版）              已发布      王姐      2025-03-01         2025-03-02
cg-leave-draft  休假管理办法（2025.8版）            草稿        王姐      2025-08-01 18:42   —
cg-leave-review 休假管理办法（2025.8版）-法务批注    待审        王姐      2025-08-01 18:45   —
cg-leave-2025   休假管理办法（2025.8版）-定稿        已发布      李法务    2025-08-01 19:10   2025-08-01 19:12
```

**「王姐，您周五拖了两次。」** 小陈指着屏幕，**「一次停在 **草稿**——系统没索引，所以小周 **检索不到** §3.4。一次进了 **待审**——按你们租户的 ACL，**工艺部本来不该看见**，但上周为赶脚注项目，临时开过 **「待审文档对 HR 与管理层可见」** 的灰度开关，赵工恰好被标成 **管理层可见组**，阿寻捞到了 **待审版** 的 §3.4。」**

李女士那张呢？小陈继续翻日志：**「她命中的是 **已发布定稿**——李法务周六早上点过 **发布**，但定稿里 §3.4 写的是 **「一次性休完」**；赵工命中的 **待审版** 里法务改成了 **「可拆分」**。两份都是 2025.8 文件名，**状态不同、正文不同**。」**

王姐愣住：**「我以为拖进知识库就……大家都能用了。」**

林薇在工单里写内部结论：**「根因：**上传 ≠ 发布**；**多状态并存 + 临时 ACL 灰度** 导致同题多源。体验层像模型胡说，实为 **运营后台缺流程、缺可见性**。初判 P2——口径风险，非大规模越权，但需 **当天止血**。」**

她顺手记了一条 **应用 A** 的对照：某商小言商家运营上周批量传了 **「双十一价目 FAQ」**，没点 **「对客服可见」**，买家问促销价时 **AI 小言** 仍引旧价目；商家在后台骂：**「我传了呀！」** 运营同学回：**「您在 **素材区**，不在 **已上架区**。」** 澄光和王姐，踩的是 **同一类坑**。

---

### 三、库房需要一张「台子」，不是多个抽屉

当天下午，林薇拉王姐、澄光 IT、小陈和产品同学开了个短会。王姐第一句话：**「你们能不能做一个 **后台**，让我一眼看见：**这份制度生效了没有、谁点的、旧版下架了没有？**」**

澄光 IT 负责人先追问：**「多数公司不都是法务在 OA 里批完，管理员再把定稿传进系统吗？那上传新版时直接废止旧版不就行了？为了一个 PDF 做四段生命周期，会不会过度？」**

林薇说：**「如果真能保证永远是一个管理员、只传最终稿、传完立即替换，确实不用做重。」** 她先在白板角落写下三档常见设计：

| 企业情况 | 一般怎么做 | 系统内需要什么 |
|----------|------------|----------------|
| **小团队 / 单管理员 / 文档少** | 飞书或 OA 审批完，只上传定稿 | **上传并发布 + 自动废止旧版**；保留当前版和操作记录即可 |
| **多人维护 / 上传后还要预览** | HR 上传、法务确认、管理员发布 | **草稿 / 已发布 / 已废止** 三态；生产检索只读已发布 |
| **多部门 / 强合规 / 定时生效** | 会签、分批或定时发布，要求审计举证 | 再增加 **待审、审批流、沙箱、完整审计**；必要时接 OA |

**「生命周期不是越长越好。」** 林薇在第一档下面画了圈，**「批准完全在系统外完成，也不需要库内预览的客户，发布即替换就够了。只有风险和协作复杂度上来，才增加状态。」**

她接着把澄光当前的结构画出来：

```text
王姐（HR 上传草稿） ─┐
李法务（确认定稿） ──┼→ 同一个知识库入口
租户管理员（控制发布）┘
                         ↓
                 解析 / 切片 / 索引
                  ↙             ↘
          HR、管理层预览       全员生产问答
```

澄光有 **HR、法务、租户管理员三种操作角色**，制度在定稿前就要进库试问；下游又同时服务 **受限预览** 和 **全员生产问答**。此前两边还共用索引，只靠临时 ACL 区分人群。于是，OA 里的「法务批准」并不会自动告诉阿寻 **哪一份可以进生产索引**；同名文件落库后，系统也不知道它是草稿还是正式制度。

小陈敲了敲日志：**「所以澄光必须补的，不是另造一套 OA，而是系统内明确的 **发布边界**：每个知识对象带 `publish_state`，生产索引只收 `published`，预览走隔离沙箱；发布新版再自动废止旧版。没有这道闸，外部审批再严，文件一进共享索引仍可能被员工捞到。」**

王姐听懂了：**「小公司一个人管，就按一下替换；我们这里三拨人、两个问答入口，系统必须认得哪张纸盖了章。至于多级会签，仍留在 OA，不必搬进来。」**

林薇把白板分成四列——她说这就是 **知识运营后台** 要回答的事：

| 列 | 运营要问的问题 | 没有台子时会发生什么 |
|----|----------------|----------------------|
| **从哪来** | 谁上传、何时上传、源文件是什么 | 同名文件堆三份，分不清定稿 |
| **能不能被看见** | 草稿 / 待审 / 已发布 / 已废止 | 待审被检索，员工看见 **未生效草案** |
| **谁批准** | 谁审核、谁点发布、生效时间 | 「我以为传了」其实 **没人点发布** |
| **坏了怎么办** | 谁下架、是否保留只读、废止后链到哪 | 旧版和新版 **同时被检索**，脚注各引各的 |

小陈补技术底线：**「阿寻 **默认只索引「已发布」**；待审、草稿 **绝不进生产检索**，除非开 **独立预览租户** 或 **明确标注的试运行环境**。ACL（S6-01）管 **谁有权看**；运营后台管 **这份文档算不算「正式上架」**——两道闸，不能混。」**

设计同学画了个 **列表页草图**：

- 每行：**文档名 · 版本 · 状态徽章 · 上传人 · 审核人 · 发布时间 · 可见范围摘要**  
- 行内动作：**提交审核 / 批准发布 / 下架废止 / 查看索引日志**  
- 顶部：**「当前对员工生效的版本」** 唯一高亮——王姐要的 **「一眼看见」**

王姐指着 **「待审」** 徽章问：**「周五晚上我就不该能让工艺部捞到这一份。」**

林薇点头：**「所以待审必须 **默认不可被普通员工检索**；HR 预览可以走 **「模拟问答」沙箱**，不要污染生产库。」**

### 四、双轨落地：先有一张表，再谈全自动

会上定了 **当天止血** 和 **季度建设** 两档——林薇照例拆成 **标准** 与 **中小默认**。澄光采用中间档：保留 OA 审批，不在知识库重做多级会签；库内只补 **三态、角色发布和预览隔离**。

**标准 / 规范流程（多制度库、多审核角色、要强审计）**

| 能力 | 做什么 |
|------|--------|
| **生命周期状态机** | 草稿 → 待审 → 已发布 → 已废止；**非法跳转拦截**（如草稿直发布需管理员权限并记审计） |
| **角色与权限** | **上传者 / 审核者 / 发布者** 可分离；发布按钮 **至少两人规则**（HR 上传 + 法务批准） |
| **版本与替换** | 发布新版时 **自动废止旧版** 或 **设生效日**；检索默认 **仅最新已发布** |
| **预览沙箱** | 待审内容在 **沙箱问答** 里测，**不写进生产索引** |
| **审计日志** | 谁何时上传、改状态、下架；支持导出 **合规举证** |
| **与引用联动** | 已废止文档脚注 **灰显 + 链到新版**（接 S6-03、S6-04） |
| **批量运营** | 按 **文件夹 / 标签** 批量提交、批量废止；商小言价目类 **定时生效** |

**中小常用默认方案（星尘当前可卖）**

- **「最小先行」**：若只有一个管理员且只上传定稿，直接 **发布新版 + 自动废止旧版**；不强加待审流程。
- **「多人再上三态」**：像澄光这样上传后还要预览，才使用 **草稿 / 已发布 / 已废止**；待审可先 **合并进草稿 + 飞书 @ 法务** 批准后再点发布。
- **「一张表」**：知识库列表 **强制展示状态列**；**已发布** 行绿色，**草稿灰色**；上传成功弹窗 **「尚未对员工生效，请点发布」**。  
- **「发布即替换」**：同一 `doc_key`（如「休假管理办法」）**只允许一份已发布**；点发布时 **弹窗确认是否废止旧版**。  
- **「按风险分权」**：单管理员可上传后直接发布；像澄光这样多人协作时，王姐可上传，**发布按钮仅法务 / 租户管理员**——最小化 **未审先发**。
- **「先止血」**：关掉 **「待审进检索」** 灰度；对已污染缓存跑 **强制重索引**（接 S6-03）。  
- **可暂缓**：可视化 diff、多级会签、与 OA 审批流打通——等大客户合同写了再加。

当天傍晚，李法务在后台把 **待审版合并进定稿** 或 **直接废止待审**；王姐的 **草稿** 被删除；**2025.8 定稿** 保留为唯一 **已发布**。小陈触发 **重索引**，并在发布弹窗加了 **红色二次确认**：**「发布后将对全体员工检索可见，是否废止 2024 版？」**

### 五、接近结尾：运营台是「知识从哪来」的签字栏

周二上午，李女士、赵工、小周在同一群里又试了一遍 **育儿假** 问题——三张截图终于 **口径一致**，脚注都指向 **《休假管理办法（2025.8 版）》§3.4**，卡片里的字 **一模一样**。

王姐在回访里写：**「以前我以为 **传文件 = 上制度**；现在发布前我会先看列表里 **是不是只有一行绿灯**。法务不点，我不催员工去问小言。」**

林薇给新同学讲 S6 第五课，把季末白板 **「知识从哪来」** 第四格打勾：

**「ACL 管 **谁能看见哪一页**；版本管 **哪一页算数**；Citation UX 管 **点了信不信**；运营后台管 **这一页算不算正式上架、谁签字让它上架**。上传是 **草稿进抽屉**；发布是 **盖上章摆上货架**——阿寻只该从 **货架** 拿货，不能从 **草稿纸堆** 里随机抽。」**

小陈把英文写在旁边：**Knowledge Ops Console。** 林薇又在白板第五行旁留了一格空笔迹：**「多租户之间再加固一道闸」**——澄光这次乱在 **同一租户内多状态**；若 **商家 A 的草稿飘进商家 B**，就是 **另一个量级的事故**。

## 概念正解

**知识运营后台（Knowledge Ops Console）** 是 B 端 RAG / 企业知识库产品里，供 **租户管理员、HR、法务、运营** 管理 **「文档从上传到可被 AI 检索引用」** 全流程的操作界面与策略层。它解决 **「文件传了但员工看不见 / 看见的不该看 / 同时存在多份互相打架」**：根因常是 **把上传当成发布**、**草稿/待审/已发布状态不清**、**缺少审核与废止流程**、**多版本并行索引**，以及 **运营动作不可审计**。典型能力包括：**生命周期状态机（草稿→审核→发布→废止）**、**角色分离（上传/审核/发布）**、**发布时版本替换与生效日**、**预览沙箱与生产索引隔离**、**列表级可观测（当前生效的是哪一份）**，以及与 **ACL、版本、引用展示** 的联动。

这里的「生命周期」应按需设计，而不是所有客户默认做全套：**单管理员、外部已审批、只上传定稿** 时，最小能力可以只是 **发布新版并废止旧版**；出现 **多人维护、库内预览、生产与预览双入口** 时，再增加三态与发布权限；只有 **多级会签、定时生效、强审计** 等场景，才值得建设待审流或对接 OA。判断标准不是公司人数，而是 **参与角色、知识风险、发布频率和审计要求**。

回扣故事：王姐 **周五上传以为已生效**，实际 **草稿未索引、待审被灰度检索、定稿周六才发布**——三人三答案；澄光用 **三态 + 一张表 + 发布即替换 + 上传发布分离** 止血；商小言 **素材区 vs 已上架区** 是同一产品逻辑在不同皮肤的映射。

在 **S6 · 知识可运营、权限可审计** 中的位置：本篇补齐 **「知识从哪来」** 的运营侧——**谁上架、谁下架、谁批准生效**；承接 S6-01 **可见性**、S6-03 **版本**；为后续 **多租户隔离再加固**、**检索可观测性** 打组织与流程基础。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 定义 **文档状态机** 与 **各状态是否进生产索引**；写清 **发布按钮权限**、**废止后旧脚注行为** |
| **方案评审** | 问：**待审文档能否被 HR 沙箱预览？** 发布新版是否 **自动废止旧版**？**上传成功** 的默认提示是什么？ |
| **指标设计** | **草稿积压数**、**发布平均耗时**、**多版本并行检索告警**、**「我传了但看不见」类工单率** |
| **跨团队沟通** | 对 HR：**「上传不是发布，像公众号存草稿」**；对研发：**「索引任务必须带 `publish_state` 过滤」**；对客服：**「先查后台状态列，再查模型」** |

## 类比锚定

**核心类比：电商后台「商品上架」——运营传了主图详情 ≠ 买家能看见；要经过 **提审 → 审核通过 → 上架**，下架后前台不应再搜到。知识库是 **「制度/FAQ 货架」**，运营后台是 **上架工作台 + 库存状态看板**。**

| 你熟悉的 PM 经验 | 知识运营后台要素 |
|------------------|------------------|
| 商品 **草稿 / 在售 / 下架** 三态 | 文档 **草稿 / 已发布 / 已废止** |
| **SKU 生效时间** 定时开售 | **版本生效日**、定时发布 |
| 只有 **已上架** 才进搜索与推荐 | 只有 **已发布** 才进阿寻生产索引 |
| **运营传图、店长审价、总部点上架** 分工 | **上传 / 审核 / 发布** 角色分离 |
| 后台 **「在售商品一览」** 对账 | **「当前生效版本」** 唯一高亮列表 |
| 商小言 **素材库 vs 线上 FAQ** 分区 | **沙箱预览 vs 生产检索** 隔离 |

---

## 类比边界说明

### A. 概念核心要点

1. **上传 ≠ 发布 ≠ 可被检索**——三者要在产品与文案里 **显式区分**。  
2. **状态机是检索前置条件**——阿寻索引任务必须 **过滤 `publish_state`**，不能仅靠事后 ACL 补救。  
3. **同一 `doc_key` 生产环境应 **单一已发布真相源****，避免同名多版本并行回答。  
4. **角色分离** 降低 **未审先发**；至少 **发布权限** 窄于上传权限。  
5. **审计与可观测**——运营动作要留痕；**「我传了」类工单** 应能 **后台一眼复盘**。

### B. 类比失效点

| 类比说法 | 失效点 | 更准确的理解 |
|----------|--------|--------------|
| 「像网盘传文件就算共享」 | 网盘 **共享链接** 即时；RAG **还要切片、索引、延迟**（S6-03） | **发布 = 触发索引流水线 + 标记可检索** |
| 「下架 = 删文件」 | 废止后可能仍需 **只读审计、脚注链到新版本** | **废止 ≠ 物理删除**；要定义 **检索剔除 + 引用迁移** |
| 「审核流越全越好」 | 中小客户 **没人填会签** 会绕过系统 | **三态 + 发布按钮** 先跑通，再 **对接 OA** |
| 「运营后台只管文档」 | 还有 **FAQ 条目、网页抓取、API 同步** 等多源 | 后台应 **统一「知识对象」视图**，不只 PDF |

## 本集 Checklist

**标准 / 规范流程**

- [ ] **状态机**：草稿 → 待审 → 已发布 → 已废止；非法跳转 **拦截 + 审计**  
- [ ] **角色分离**：上传 / 审核 / 发布；敏感库 **双人发布**  
- [ ] **生产索引仅 `published`**；待审走 **沙箱预览**，不写生产  
- [ ] **同 doc_key 单一已发布**；发布新版 **废止或设生效日**  
- [ ] **审计日志** 可导出；指标：**草稿积压、多版本并行告警、运营类工单率**  

**中小常用方案**

- [ ] 单管理员、只上传定稿：**发布新版 + 自动废止旧版**，不强加审批状态
- [ ] 多人维护或需预览：再做 **三态**（草稿 / 已发布 / 已废止）+ 列表 **状态列强制展示**
- [ ] 上传成功提示 **「尚未生效，请发布」**；高风险场景才要求 **发布人 ≠ 上传人**
- [ ] **发布即替换** 弹窗确认；关掉 **待审进检索** 类灰度  
- [ ] 商小言 **素材区 vs 已上架 FAQ** 分区同理  

**何时升级到完整版**

- 客户 **法务/合规** 要求 **会签与举证**；**多部门并行编制度**；**定时生效** 频繁；或 **「上传了但看不见 / 看见草案」** 类工单 **持续高于阈值**。
