> 今日概念在知识树中的位置：S7 收官后，**澄光制造** 的 **张先生** 再点「联系支持」，单子会进 **星尘统一工单池**；**商小言** 商家投诉 **退货款慢**、**内小言** IT 服务台 **权限上架申请** 也进 **同一队列**。老吴的 **真人支持** 坐席 **小方** 先接了一通 **修小言 run 催货**，却按 **商小言退款话术** 回——用户越听越急。今天拆 **进线意图分类**：**进线第一句（或第一屏字段）先判「这单像哪一类」**，再谈 **分给谁、哪个技能组**——**不是** 让坐席 **凭耳朵猜**，也 **不是** 把 **模型路由（老何）** 和 **工单分派** 混成一锅。

### 场景白板（读故事前 30 秒）

- **本集入口**：**小言平台工单台**——星尘 **真人支持** 与部分大客户的 **统一进线队列**；来源包括 **应用 B｜修小言**（run 接管、现场催货）、**应用 A｜商小言**（商家投诉、退款纠纷）、**应用 C｜内小言**（租户 IT 的权限/知识上架工单）。
- **进线意图分类（Intent Classification）**：白话：**工单进池前或进池瞬间**，用规则/模型把 **「用户想干什么、属于哪条产品线、哪类问题」** 打成 **意图标签**——例如 **`修小言_run_催货`**、**`商小言_退款投诉`**、**`内小言_权限申请`**——**供后续路由** 用。
- **工单分派 vs 模型路由**：白话：**老何** 管 **「这句话走几楼模型」**；**工单台** 管 **「这单派给哪个技能组/坐席」**——**两层不同**，本篇只讲 **进线先分类**。
- **本集冲突**：队列 **混单** 时 **没先分类**，坐席 **按习惯接商小言**；**修小言 run** 被 **当退款单** 处理，**PK 单号没人报**，张先生 **四十分钟又白等**。

## 寓言故事

### 一、统一队列里，铃声响了三次

S7 收官两周后，星尘把 **修小言 run 接管**、**商小言 商家升级投诉**、**内小言 大客户 IT 工单** 收进 **同一套「小言平台工单台」**——老吴组里的坐席 **不再按产品切三个浏览器 Tab**，而是 **一个队列、谁先响谁接**。

周一早上九点，**真人支持** 坐席小方的耳机连响三次。

**第一通**（她以为是老样子）：标题行写着 **「商小言 · 用户催处理」**，摘要里夹着 **「请尽快退款」** 几个字。小方条件反射点开 **商小言退款 SOP**，回电：**「您好，我是商小言支持，请问您的 **订单号** 是多少？退款一般 **3–5 个工作日**……」**

对面沉默两秒：**「我 **没退款**！我 **滤芯 run 黄灯** 五分钟了，你们 **仓库认哪张单**？」** 是 **澄光制造** 的 **张先生**——**RUN-CG-20261016-052**，**应用 B｜修小言** 的 **run 接管单**，被 **进线模板** 误打成 **商小言催处理**。

小方慌忙翻后台，才发现 **队列里混着三种底色**：蓝 **B**、橙 **A**、绿 **C**——她刚才 **只看了标题里的「催」字**。

**第二通** 她转给邻座：**内小言** 租户 IT 问 **「李女士检索越权那单，HR 文档上架审批走到哪了」**——邻座按 **修小言 run** 话术问 **「您的出库单号多少」**，IT 同事当场炸毛。

**第三通** 才是真 **商小言**：某电商商家骂 **「买家退货款三天没到」**——这通被 **邻座** 接走，却按 **内小言权限** 模板回复 **「请提交文档 ACL 申请表」**。

九点四十五，老吴在组里吼：**「今天 **不是模型不行**，是 **池子混了没人先分类**！」**

阿梅把三份录屏甩进飞书：**「S7-04 教会 **接得住**；S8 得先 **接得对**。」**

### 二、会诊：不是加人，是先问「这单像哪一类」

林薇没有让小方独自背锅。她按惯例：**阿梅** 在客户侧建汇总跟进 → 林薇 **初判 P2（体验与 SLA，未资损）** → 拉 **老吴、小陈、对口算法、商小言运营** 半小时会诊。

小陈先展示 **三单的原始进线包**——问题一目了然：

```text
RUN-052 原始标题：「用户催处理」+ 来源 app_id 修小言  + 有 run_id
  → 队列展示却合并成「商小言 · 用户催处理」（模板用错了）

IT 工单 原始：内小言 + ticket_type=acl_publish
  → 坐席屏无类型标签，只有「新工单」

商小言 退款：关键词「退货款」
  → 与「退货流程咨询」共用模糊标题「退货相关」
```

林薇在白板上画了两层：

```text
         用户 / 租户进线
              ↓
    ┌─────────────────────────┐
    │  ① 进线意图分类（本篇）   │  ← 「这单像哪一类？」
    │     意图标签 + 置信度      │
    └─────────────────────────┘
              ↓
    ┌─────────────────────────┐
    │  ② 技能组 / 坐席路由      │  ← S8-02 讲
    │  ③ 模型路由（老何）       │  ← 对话层，不是工单层
    └─────────────────────────┘
```

**「老何分的是 **模型楼层**；工单台分的是 **人**。张先生这单，**楼层** 和 **坐席技能** 都没错，**第一步意图就贴错标签**——后面全歪。」** 她说。

算法同学补了一句：**「分类可以 **规则 + 小模型** 叠；但 **意图表** 得产品定，不能 **81 类客服随手加**。」**

商小言运营举手：**「我们 **退款投诉** 和 **发货慢咨询** 标题都像 **催**——**不能只靠标题一个词**。」**

内小言 IT 对口人说：**「**权限申请** 和 **知识上架** 在我们台是两类，进星尘池子却都是 **绿 C**——坐席看不出 **要不要拉林薇**。」**

会诊结论：**先进线意图分类，再谈派给谁。**

### 三、意图表：产品定类，机器打标

林薇提交 **《小言平台进线意图分类双轨方案》**——**第一条是意图词典**，不是模型参数。

**标准 / 规范流程（多应用、可审计、可迭代）**

| 层级 | 说明 | 示例标签（`intent_id`） |
|------|------|-------------------------|
| **L0 · 产品线** | 来自哪个应用 / 租户域 | `app_b_xiuxiaoyan`、`app_a_shangxiaoyan`、`app_c_neixiaoyan` |
| **L1 · 进线渠道** | 用户主动 / run 接管 / IT 升级 / 商家投诉 | `channel_run_handoff`、`channel_user_escalation`、`channel_it_ticket` |
| **L2 · 业务意图** | 这单 **要办成什么事** | `intent_b_run_pick_unknown`、`intent_a_refund_dispute`、`intent_c_acl_publish` |
| **L3 · 紧急辅助** | 是否涉资损 / 合规 / 大面积 | `urgency_p0_financial`、`urgency_p1_data`（**不替代** PM 定级，只 **辅助排序**） |

**分类输入（多信号，不只标题）**

| 信号 | 修小言 RUN-052 应有 | 商小言退款应有 |
|------|---------------------|----------------|
| `app_id` | B | A |
| `run_id` 是否非空 | 有 | 无 |
| `handoff_reason` | `step_unknown_timeout` | — |
| 用户原话 / 表单 | 「仓库认哪张单」 | 「退货款三天没到」 |
| 关键词 | PK、run、拣货 | 退款、订单号、买家 |

**分类器双轨**

| 轨 | 做法 | 适用 |
|----|------|------|
| **规则优先** | `app_id + run_id + handoff_reason` **硬映射** L2 | **修小言 run 接管**——**宁可规则，别赌模型** |
| **模型补位** | 小分类模型 / LLM **只在规则未覆盖时** 打 L2 | **商小言**「催」类歧义句 |
| **人工复核队列** | 置信度 &lt; 阈值 → **`intent_review`** | 新意图、灰度期 |

**中小常用方案（编制有限时的默认路径）**

- **只做 L0 + 规则 L2**：**按 app_id 分三大池**，池内 **run 单单独子队列**——**不混商小言**。
- **标题模板强制带前缀**：`[修小言-run]` / `[商小言-投诉]` / `[内小言-IT]`——**土但有效**。
- **坐席屏第一行只显示**：**意图标签中文** + **推荐技能组（下一篇细讲）**。
- **每周意图错分 Top10** 人工改标签 → **回流规则**。

**何时升级到完整版**

- 三池并一 **真·统一队列**；**商小言 与 修小言 文案高度相似**；需 **模型分类 + 置信度 + 审计**；要与 **S8-03 改派审计** 联动。

### 四、分类对了，第一句就不再是「退款几天到」

双轨灰度：**澄光制造** 的 **RUN-052** 重进池——这次 **进线包** 在入队前跑分类：

```text
L0: app_b_xiuxiaoyan
L1: channel_run_handoff
L2: intent_b_run_pick_unknown
L3: urgency_p2_sla（产线等备件，非 P0 资损）
confidence: 0.98（规则命中）
```

小方屏上 **第一行红字** 不是「用户催处理」，而是：

> **【修小言 · run 接管 · 拣货状态未知】** 推荐：修小言 L2 运营 / 已绑 **交接包**

她回电张先生：**「张工，系统显示 **RUN-052**、出库 **SHP-1052-A**；我这边 **查仓库状态**——您 **不用提供订单号**，也 **不是退款单**。」**

十五秒后只读查询带回 **PK-052**——和 S7-04 剧本同构，但 **差别在开口第一句**：**分类对了，话术模板自动选对**。

同周 **商小言退款** 进线打 **`intent_a_refund_dispute`**，邻座 **不再问 PK 单**；**内小言 ACL 上架** 打 **`intent_c_acl_publish`**，标题直达 **对口 PM 会诊队列**——**林薇** 在 **第三通** 才看到 **李女士越权** 的续跟，而不是 **混在 run 池里埋三天**。

老吴组 **错分率** 从周初 **38%** 降到 **9%**——剩下的主要是 **商小言「催发货」vs「催退款」** 仍要模型补位。

林薇在 S8 开篇复盘里写第一句人话：

**「派单之前，先问 **这单像哪一类**；**听错第一句，后面 **S7 的交接包** 也送不到对的人。」**

小陈把字段写在角上：**`intent_id` · `intent_confidence` · `classifier_version` · `intent_review_flag`.** 阿梅补：**「意图表是 **产品资产**，不是 **算法黑盒**。」**

## 概念正解

**进线意图分类（Intent Classification for Ticket Routing）** 指：在 **工单进入统一队列之后、分给具体坐席或技能组之前**，用 **结构化信号（应用来源、run_id、表单类型、转人工原因）+ 规则 / 分类模型** 判定 **「这单属于哪条产品线、哪种业务意图」**，输出 **可审计的意图标签与置信度**——**供后续路由、话术模板、SLA 计时** 使用；**不是** 用 **对话模型路由（老何）** 替代 **工单分派**，也 **不是** 让坐席 **扫一眼标题里的「催」字** 决定接法。

回扣故事：**RUN-052** 因 **标题模板** 被标成 **商小言催处理**，小方 **按退款 SOP 开口**；**三池混单** 时 **内小言 IT** 与 **真退款** 也 **串话术**；双轨方案用 **L0–L3 意图表、规则优先 + 模型补位、置信度复核、坐席屏意图第一行** 把 **「先分类」** 从 **口号** 变成 **入队流水线**；**分类对了，S7-04 的交接包和话术才接得上**。

在 **S8 · 平台端 AI 分派工单** 中的位置：**开篇扫盲**——全季 **「进线怎么分、分给谁、分错了怎么改、和模型路由差在哪、看什么指标」** 的第一条；本篇只解决 **「像哪一类」**，**技能组路由** 在 **S8-02**。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 写 **意图词典 L0–L3、分类输入字段、规则/模型分工、置信度阈值、错分回流** |
| **方案评审** | 问：**修小言 run 是否规则硬分类？** **商小言「催」类是否单独 L2？** **意图表谁维护、多久发版？** |
| **指标设计** | **意图错分率、低置信度占比、分类延迟、错分导致首次响应时长、错分改派率** |
| **跨团队沟通** | 对客服：**坐席屏第一行是意图不是标题**；对算法：**产品给意图表，模型只补缺口**；对研发：**分类在入队前，别和对话路由混服务** |

## 类比锚定

| 你熟悉的 PM 旧经验 | 进线意图分类 |
|--------------------|--------------|
| 快递 **「生鲜 / 文件 / 大件」** 先贴品类标，再分网点 | **L2 业务意图** 再 **路由技能组** |
| 医院 **分诊台「发热 / 外伤 / 儿科」** 第一问 | **进线先分类**，不是 **直接进诊室** |
| 工单系统 **「Bug / 需求 / 咨询」** 下拉必选 | **意图词典** + **入队强制带标签** |
| 呼叫中心 **IVR「查余额请按 1」** | **规则优先** 的 **硬映射**（run 单 = 按 2） |
| 电商 **售后原因** 必选才能提交 | **表单字段** 是分类的 **高置信信号** |

## 类比边界说明

### A. 概念核心要点

1. **分类 ≠ 派单**：本篇 **只打标签**；**分给谁** 是 **技能组路由（S8-02）**。  
2. **分类 ≠ 模型路由**：**老何** 选 **模型档**；**工单台** 选 **人**——**字段与 SLA 不同**。  
3. **意图表是产品资产**：**L2 业务意图** 由 **PM + 运营** 定义，算法 **实现分类器**。  
4. **多信号优于标题**：`app_id`、`run_id`、`handoff_reason` **比用户一句话可靠**。  
5. **错分要可审计、可回流**：**`intent_review`** + **周度错分榜改规则**。

### B. 类比失效点

| 失效 | 为什么不能照搬 |
|------|----------------|
| **「像 IVR 按 1 按 2」** | 很多进线是 **系统转人工**，用户 **没按键**；要靠 **结构化进线包** |
| **「客服一听就懂」** | **统一队列** 下 **修小言 / 商小言 话术相反**；**不能靠耳朵** |
| **「一个模型端到端派单」** | **规则 + 小模型 + 人工复核** 更 **可解释、可审计** |
| **「意图越多越好」** | **L2 过细** → **错分飙升、坐席记不住**；要 **可运营粒度** |
