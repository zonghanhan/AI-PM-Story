### 场景白板（读故事前 30 秒）

- **本集入口**：**小言平台工单台**——S8-01/02 已能 **分类 + 路由**；本篇讲 **派单理由是否可见**、**改派是否留痕**。
- **分派解释（Dispatch Explainability）**：白话：坐席和用户（按需）能看懂 **「这单为什么分给我 / 这个组」**——例如 **意图命中、技能匹配、负载、溢出代受理**；**不是** 黑箱弹窗。
- **改派审计（Reassignment Audit）**：白话：**转单、退回、升级** 时 **必填原因码 + 可选备注**，系统记 **谁、何时、从哪到哪、是否通知用户**；**事后能查、能复盘**。
- **本集冲突**：**路由修好了**，但 **上周错派无人认领**；**资金组改派 L1** **没留痕、短信吓商家**——**张先生要说法，商家以为退款被拒**。

## 寓言故事

### 一、PK 报对了，投诉却没停

S8-02 灰度第三天，**修小言 L2 运营阿凯** 接起 **RUN-053**——屏上 **派单原因** 一行行展开：

```text
intent: intent_b_run_pick_unknown
route: sg_xxy_run_l2 → 阿凯
reason: skill_match(wms_read) + load 1/8 + shift_on
policy_version: routing_v0.3
```

他 **十二秒** 带回 **PK-053**。张先生语气松了一点，下一句却硬了：

**「拣货单号 **今天对了**。上周 **052** 你们 **小方** 让我 **转了三次**——**谁派的？** 我要 **书面说明**，厂里面 **要归档**。」**

阿凯愣住：他能看见 **今天** 的 `route_reason`，**上周 052** 在系统里只有 **「assigned_agent: 小方」**——**没有「为何派给 L1」** 的字段；**改派记录** 更是 **三条「转同事」聊天截图**，**无结构化 audit**。

同日下午，**商小言资金组** 坐席 **大刘** 把 **REF-881** **点「改派」** 退回 **L1 池**——**商家侧** 手机 **秒收短信**：

> 「您的工单已转接，请耐心等待。」

商家 **「悦衣坊」** 运营在群里 **@ 阿梅**：**「退款 **是不是被拒了**？怎么又转走了？」** **L1 小方** 新开 **REF-881**，摘要栏 **空白**，备注只有系统灰字 **「资金组退回」**——**无原因码、无上一棒留言**。

老吴把两通录音并排投屏：**「S8-02 解决 **接对人**；今天解决 **说得清、改得明**。」**

### 二、会诊：不是道歉信，是派单与改派的「账本」

阿梅汇总 **澄光投诉** 与 **悦衣坊群聊** → 林薇 **初判 P2（体验与合规风险，未直接资损）** → 拉 **老吴、小陈、商小言运营、资金组大刘、修小言阿凯** 会诊。

小陈调出 **RUN-052 历史** 与 **REF-881 改派链**：

```text
RUN-052（上周）
  assigned_agent: 小方
  skill_group: support_l1_general
  route_reason: NULL          ← 无派单解释
  reassignment_log: []        ← 无改派审计，只有 IM 截图

REF-881（今日）
  funds → L1 改派
  reassigned_by: 大刘
  reason_code: NULL           ← 改派栏空着
  notify_user: true（默认）    ← 商家收到吓人短信
  handoff_note: NULL           ← L1 无交接说明
```

林薇补全白板 **S8 四层** 的第三格：

```text
         用户 / 租户进线
              ↓
    ① 进线意图分类（S8-01）
              ↓
    ② 技能组 / 坐席路由（S8-02）
              ↓
    ③ 分派解释与改派审计（本篇）  →  route_reason + reassignment_audit
              ↓
    ④ 模型路由（老何）——对话层，不进工单账本
```

**「派单解释回答 **『为什么是我接』**；改派审计回答 **『谁动的、为何动、用户知不知道』**。** 052 **能复盘路由版本**，却 **不能回答上周为何进 L1**——**当时没记 `routing_policy_version`**。** 881 **大刘其实想写 **「缺退货物流单号，请 L1 代收截图」**——**界面没强制填，默认还发短信**。」**

大刘有点委屈：**「我不是拒退，是 **材料不齐**……** 商家看见 **『转接』** 以为 **踢皮球**。」**

阿凯问：**「张先生要 **归档**，我能给他 **今天的 route_reason**——**上周的能不能 **补记**？」**

小陈：**「**补记可以，但要标 **retroactive**；**新单必须实时写**。」**

会诊结论：**派单必显解释；改派必填原因；用户通知分场景；审计可导出。**

### 三、双轨方案：解释上屏，改派留痕

林薇提交 **《小言平台分派解释与改派审计双轨方案》**。

**标准 / 规范流程（可追责、可对外说明）**

**1. 派单解释（坐席屏 + 内部审计）**

| 字段 | 谁看 | 示例（RUN-053） |
|------|------|-----------------|
| `route_reason_summary` | 坐席首屏 | 「意图 run 拣货未知 → L2 组；您具备 wms_read」 |
| `route_reason_detail` | 展开 / 审计 | `skill_match`, `load 1/8`, `shift_on`, `policy routing_v0.3` |
| `overflow_flag` | 坐席 + 用户话术 | `false`；若为 true：**开口第一句**「当前由协作组代受理」 |
| `routing_policy_version` | 审计 | `routing_v0.3`——**复盘时可对齐配置快照** |

**2. 改派审计（任何转单必经）**

| 步骤 | 规则 |
|------|------|
| **触发** | 坐席主动改派、组内退回、值班长重分、系统自动溢出 |
| **必填** | `reason_code`（枚举）+ `handoff_note`（≥10 字给下一棒） |
| **记录** | `from_agent` / `to_agent` / `from_group` / `to_group` / `reassigned_by` / `at` |
| **用户通知** | **默认关闭**；仅 `notify_user=true` 的场景白名单（如 **指定新对口经理手机号**） |
| **禁止** | **空原因改派**、**静默跨组退回** |

**常用 `reason_code` 枚举（产品 + 运营维护）**

| code | 含义 | 是否默认通知用户 |
|------|------|------------------|
| `missing_material` | 缺材料，请前序组代收 | **否**（内部流转） |
| `skill_mismatch` | 派错组，纠正路由 | **否** |
| `customer_request` | 用户要求换对口人 | **是**（可选模板） |
| `escalation` | 升级值班长 / 产研 | **视 SLA** |
| `shift_end` | 下班交接 | **否** |

**3. 历史投诉与对外说明（张先生类）**

| 动作 | 说明 |
|------|------|
| **生成《派单说明》** | 导出 **intent、skill_group、route_reason、policy_version**；若历史缺失，标 **「当时未采集，参考同期同类单」** |
| **错派归因** | 对比 **当时 policy** vs **现行 policy**——**「上周为 round_robin 策略，属已知缺陷，已 v0.3 修复」** |
| **责任边界** | **系统策略问题** vs **坐席误操作**——**不靠甩锅个人**，**靠版本与 audit** |

**4. 坐席改派 UI（大刘那条线的修法）**

```text
改派至：L1 · 商小言咨询组
原因码：[missing_material ▼]  （未选无法提交）
交接说明：缺退货物流截图，请 L1 联系商家上传，齐后回资金组。
□ 通知用户（默认不勾）
[确认改派]
```

**中小常用方案（编制有限时的默认路径）**

- **派单解释只上一行**：`route_reason_summary` **一句人话**，**detail 先不落库**。
- **改派原因 5 个枚举就够**：`缺材料 / 派错组 / 用户要求 / 升级 / 下班交接`——**备注必填一句**。
- **用户通知全关**：改派 **默认不发短信**；**只有用户明确要求换人才勾**。
- **历史单不补全**：**只对灰度后新单** 强制 audit；**上周 052** 用 **「已知缺陷说明 + 修复版本」** 回复客户，**不伪造字段**。
- **周报人工导出**：**错派 + 改派 Top 原因** Excel **先人工拉**，**不上实时看板**。

**何时升级到完整版**

- 客户 **要求派单说明归档**、**合规审计**、**多租户改派权限**；需 **detail 字段、policy 快照、实时看板、retroactive 补记流程、与 SLA 联动**。

### 四、改派栏填上，短信不再吓人

双轨上线一周，**三条线** 同时收口。

**张先生 / RUN-052 投诉**  
阿梅在 **真人支持** 协同下出具 **《派单说明》** 一页纸：

```text
工单 RUN-052 · 澄光制造
进线意图：intent_b_run_pick_unknown（正确）
当时派单：support_l1_general / 坐席小方
原因说明：当时路由策略为 round_robin_all（routing_v0.2），
         未启用技能硬过滤；属平台策略缺陷，非坐席个人过失。
现行策略：routing_v0.3，同类单直达 sg_xxy_run_l2。
补救：RUN-053 已 12s 首响；后续同类单监控错组率 <5%。
```

张先生回复：**「**能说清 **就行；** 厂里面 **要的是过程，不是甩锅名**。」**

**悦衣坊 / REF-881**  
大刘再遇 **缺物流截图**，改派界面 **必选 `missing_material`**，备注 **「请商家上传退货面单照片，齐后 @资金组」**——**短信不勾**。小方屏上 **交接说明完整**，**二十分钟后** 材料齐，**一键回派资金组**，audit 记 **L1→资金 · reason: material_complete**。

**溢出代受理**  
一例 **L2 全员会议**，**RUN 单溢出** 到 **值班长**——屏上 **`overflow_flag: true`**，**模板第一句**：**「当前 L2 全员会议，由值班长代查仓，权限已临时开通」**——**张先生同类用户** 不再听见 **「我转同事」** 循环。

老吴看板新增：**空原因改派率** 从 **38%** 降到 **0%**（强制校验）；**改派后用户投诉率** 降 **一半**。

林薇复盘：

**「路由回答 **『谁该接』**；解释与审计回答 **『凭什么、谁改的』**——**改派栏空着，等于告诉用户 **『踢皮球』**。」**

小陈落库：**`route_reason_*` · `reassignment_id` · `reason_code` · `handoff_note` · `notify_user` · `routing_policy_version`.** 阿梅补：**「**商家怕的不是转单，是 **不知道为什么转**。」**

## 概念正解

**分派解释（Dispatch Explainability）** 指：工单 **派给某技能组 / 某坐席** 时，系统 **结构化记录并可展示** **「为何这样分」**——意图命中、技能匹配、负载、排班、溢出等——让 **接单人能上手、值班长能复盘、客户（按需）能拿到说明。** **改派审计（Reassignment Audit）** 指：任何 **转单、退回、重分** 必须 **留痕**：谁操作、何时、从哪到哪、**原因码与交接备注**、**是否通知用户**——**禁止空原因改派**。

回扣故事：**RUN-052** 路由修好后，张先生仍追 **上周四十分钟谁派的**——**历史无 `route_reason` 与 audit**；**REF-881** **资金组改派 L1** **未填原因却默认发短信**，商家误以为 **退款被拒**。**双轨方案** 用 **派单解释字段、改派必填原因、用户通知白名单、对外《派单说明》** 把 **「说得清、改得明」** 产品化。

在 **S8 · 平台端 AI 分派工单** 中的位置：**上线专题**——全季五条里的 **「分错了怎么改、凭什么这样分」**；承接 S8-02 **路由结果**，为 S8-04 **「和模型路由边界、排队 SLA」** 铺路。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 定义 **`route_reason` 字段、改派 `reason_code` 枚举、交接备注字数、用户通知默认策略** |
| **方案评审** | 问：**改派能否不填原因？** **溢出代受理开口话术是否强制？** **历史错派对客户怎么说？** |
| **指标设计** | **空原因改派率、改派一次解决率、改派后投诉率、派单说明导出次数** |
| **跨团队沟通** | 对客服：**改派 = 填表不是踢球**；对法务：**audit 保留多久**；对客户成功：**《派单说明》谁出具** |

## 类比边界说明

### A. 概念核心要点

1. **解释面向多方**：**坐席** 要上手快；**运营** 要复盘；**客户** 只要 **必要时的过程说明**——**不是把算法日志甩给用户**。  
2. **改派默认静默**：**内部流转**（缺材料、派错组纠正）**不应默认发短信**——**通知是显式选择**。  
3. **原因码 + 备注缺一不可**：**枚举** 便于统计；**备注** 承载 **个案细节**——**只有「退回」二字不够用**。  
4. **历史诚实**：**缺字段** 时 **标 retroactive / 已知缺陷**，**不伪造 audit**——**信任比漂亮报表重要**。  
5. **与路由版本绑定**：**派单解释** 应带 **`routing_policy_version`**——**「当时策略如此」** 可验证。

### B. 类比失效点

| 失效 | 为什么不能照搬 |
|------|----------------|
| **「像快递每条都推送」** | 工单 **一天改派三四次** 会 **打扰用户**；**内部流转应静默** |
| **「坐席随便写备注就行」** | **无枚举** 则 **无法做 Top 原因、无法门禁** |
| **「解释 = 把模型置信度展示给用户」** | 用户要 **「为何换组、接下来谁办」**，不是 **0.98** |
| **「审计只为追责坐席」** | 大量错派来自 **策略版本**——**audit 用于改策略，不是只扣 KPI** |

## 本集 Checklist

**标准 / 规范流程**

- [ ] 派单写入 **`route_reason_summary` + detail + `routing_policy_version`**  
- [ ] 坐席首屏 **可展开派单解释**；**`overflow_flag`** 绑定 **开口话术**  
- [ ] 改派 **强制 `reason_code` + `handoff_note`**；**禁止空提交**  
- [ ] **`notify_user` 默认 false**；**白名单场景** 才可勾选  
- [ ] 审计日志：**from/to agent/group · operator · timestamp**  
- [ ] **《派单说明》** 导出模板（含 **历史缺陷诚实表述**）  
- [ ] 指标：**空原因改派率、改派后投诉率、说明导出次数**  
- [ ] 保留策略：**audit 保留周期** 与 **合规对齐**

**中小常用方案**
