### 场景白板（读故事前 30 秒）

- **本集入口**：**应用 C｜内小言**——某客户企业飞书里的 **AI 小言**（对话助手）；**李女士** 是该租户下的 **普通员工**，问的是 **本公司年假制度**。
- **ACL**：Access Control List，访问控制列表——白话：**这份文档/这一段，允许谁看** 的名单；在 RAG 里要在 **检索阶段** 生效，不能等模型生成完再删。
- **真人支持 / 工单惯例**（**S6 季统一说明，后续篇不再重复**）：租户侧 **IT 服务台**（或商小言场景下的 **商家客服 → 星尘支持**）先建工单 → 星尘 **对口 PM + 值班产研** 初判定级 → 按归因拉会诊。**AI 小言** 是对话助手，**不是** 客服；比喻角色（如「老关」）**不能** 独自定 P0、派单。
- **本集冲突**：小言 **引用了李女士本不该看见的 HR 内部页**，答得 **又准又有出处**——越像「高质量回答」，风险越大。

## 寓言故事

### 一、出处对了，人不该在

周一上午，林薇的手机震了一下——**内小言** 大客户「澄光制造」的 IT 服务台在飞书工单里 @ 了她。

工单正文很克制，附件是一张截图：

李女士（工艺部员工）问：**「我今年还剩几天年假？调休能不能和年假一起休？」**

**AI 小言** 回复得相当专业——三条要点，末尾挂着脚注 [1][2]。她点开 [1]，跳到了《澄光制造员工休假管理办法（2025 版）》第三章，**高亮段和她的问题严丝合缝**。

工单里真正刺眼的是 [2]：

> **来源 [2]**：《薪酬与年假折算——HR 内部操作指引（管理岗）》§2.4「总监及以上年假预支与绩效挂钩说明」

李女士的截图上，她自己用红框圈了这一段，附言：**「我只是个工艺员，为什么小言把 **只有 HR 和管理层能看** 的内部指引也列出来了？里面还有 **职级档位的折算系数**。」**

服务台坐席在工单里补了一句：**「用户没有抱怨答错，是抱怨 **看见了不该看的页**。请星尘侧帮忙看是不是 **知识库权限配置** 问题。」**

林薇没有自己定级。她先把工单转给 **当周值班产研**，在内部协作频道里 @ 了负责 **内小言** 的对口研发小陈，备注：**「疑似检索越权，请初判是否 P1——客户已标记 **数据敏感**，但未报大面积扩散。」**

十分钟后小陈回复：**「复现了。不是幻觉，是 **阿寻捞段时没做用户级过滤**。」**

---

### 二、库房很大，但每排架子没挂牌

为了讲清楚，小陈把日志摊在飞书文档里。

李女士提问时，系统实际做了这些事：

```
用户问题（李女士 · 工艺部 · 员工）
   ↓
向量化 + 关键词检索（Hybrid，照旧）
   ↓
阿寻返回 Top 8 段——按相似度排序
   ↓
Rerank 后取 Top 3 进模型
   ↓
AI 小言生成 + Grounding 脚注
```

**缺了哪一步？** 小陈在「阿寻返回」那一行画了红叉：

**「检索结果里 **没有按李女士的身份过滤**。对她可见的《休假管理办法》和 **仅 HR/管理岗可见** 的《内部操作指引》都在同一个 **租户知识库** 里，Embedding 又都沾着『年假』『调休』——**相似度上她不该看的那页，排进了前三**。」**

林薇皱眉：**「飞书文档本身不是有权限吗？她点 [2] 的链接，飞书会拦吧？」**

小陈：**「飞书里她可能打不开原文——但 **小言已经把里面的句子复述进对话了**，还标了脚注。 **泄露发生在检索进模型那一刻**，不是点击链接那一刻。」**

他又补了一刀：**「Grounding 这次 **帮了倒忙**——出处越精确，用户越确信『系统官方告诉我』。」**

会上，客户企业的 HR 接口人王姐也进来了（语音转文字）：**「我们上传知识库时，以为 **整包导入** 就行。不知道还要在星尘侧再配 **谁能检索到哪一页**。」**

林薇在笔记本上写了两个词：**租户隔离 ≠ 用户授权**。

---

### 三、工单怎么流转，才算像真公司

下午，林薇拉了个短会：值班研发小陈、算法同学、客户成功、法务同事。**没有人当场拍板「这就是 P0」**——按星尘内部惯例，先过一张 **初判表**：

| 项 | 结论 |
|----|------|
| **影响面** | 已知 1 条会话；HR 指引类文档 **约 40 份** 在库内标记不清 |
| **可利用性** | 需用户 **主动问相关词** 才易触发，非一键导出全库 |
| **合规** | 客户劳动合同涉及 **薪酬相关敏感信息**，需 **24h 内止血 + 书面说明** |
| **初判级别** | **P1（高优）**，对口 PM 林薇牵头，**检索 + 权限** 联合修复 |

止血动作当天做完：

1. **运营后台** 把《薪酬与年假折算——HR 内部操作指引》等 40 份文档 **整库下架检索**（仍可在源系统查阅，但不进 RAG）。
2. **AI 小言** 对该租户临时开启 **「仅公开制度类标签可检索」** 粗开关。
3. 客户成功向澄光 IT 与 HR 发 **事件说明模板**，李女士侧由 **真人支持** 回访，确认她 **未转发截图**。

这些都没解决根因。林薇在需求文档里写：**「我们要的是 **谁能看见哪一页** 的产品能力，不是每次出事就人工下架。」**

---

### 四、会上吵的是：检索前对名单，不是生成后道歉

第二周方案会，小陈把白板最上面一行写成：**「过滤发生在检索之前；生成阶段再拦，已经晚了。」**

王姐问：**「能不能让模型 **自己判断该不该说**？」**

林薇摇头：**「那是输出护栏。今天的问题是 **材料根本不该进上下文**。模型看不见，才不会在脚注里 **帮你把秘密念一遍**。」**

小陈：**「中小先 **文件夹/标签三档**：公开制度、管理岗、HR 专属；每块 chunk 带 tag，查询 **先 filter 再相似度**。完整 **IdP（Identity Provider，企业身份源，如飞书/AD）** 同步可以 Q3 再卖。」**

他们用李女士原题做了 **回归对照**：

| 方案 | 李女士问年假 | 结果 |
|------|--------------|------|
| **仅租户隔离** | 命中 HR 内部指引 | 脚注 [2] 泄露职级折算 |
| **+ 标签 ACL** | 只捞 `公开制度` | 仅 [1] 休假办法 |
| **+ 管理岗误标公开** | 仍泄露 | 说明 **运营标错比技术更难**——要上架预览 |

澄光先上 **标签粗分 + 以角色预览检索**；IdP 同步列入增购。

---

### 五、接近结尾：不是模型嘴不严，是检索没对名单

一个月后，澄光 **内小言** 的「越权引用」工单 **归零**。运营后台多了一栏 **「以某角色预览检索」**——王姐上传新文档前，会先选 **「工艺部员工」** 点一下，看阿寻 **会不会捞到 HR 专区**。

林薇给新同学讲 S6 第一季，指着李女士那张截图：

**「多租户隔离解决 **A 公司看不见 B 公司**；检索 ACL 解决 **同一公司里，李女士看不见 HR 那一页**。RAG 不是 **把整库倒进模型**，是 **替这个人拿他有权看的几页纸**——**拿纸之前就要对名单，不是念完再道歉**。」**

小陈把英文写在旁边：**Retrieval ACL。** 法务同事补了一句：**「第 11 篇的 Grounding 让 **每一句话有出处**；今天这一篇让 **每一个出处 **先过权限**。** 两个都上了，才叫能拿去给法务审的客服。」**

李女士后来又在 **内小言** 里问了一次年假，回复底部只有 [1] 公众制度。她在工单回访里写：**「这次像问公司前台，不像误闯人事档案室。」**

林薇把 S6 的三条产品责任抄进季末白板——今天完成第一条的子问题：**「谁能看见」** 要在 **检索** 层回答；**「知识从哪来、坏了怎么发现」** 留给后面的篇目。

## 概念正解

**检索权限 / ACL（Retrieval Access Control）** 指在 RAG 流程中，**根据当前用户（或角色、部门、租户）的授权**，决定 **哪些文档片段可以进入检索候选集乃至模型上下文**。它解决的是 **「捞段」阶段的越权**：即使源文档系统在点击链接时会拦访问，只要 **无权限内容已被检索进 prompt**，模型仍可能 **复述、摘要并带脚注展示**。典型做法包括：入库时写入 **可见性标签**、查询时带 **用户身份上下文**、在向量/关键词检索中 **先过滤再排序**、Grounding **仅展示有权来源**，并配合 **审计日志与运营预览**。它与 **租户隔离**（不同企业之间）互补，常与 **知识运营后台、IdP/HR 主数据同步** 一起设计；**不能靠** 调低温度、加强 System Prompt「不许泄密」来替代——**材料不进上下文，才是硬边界**。

回扣故事：李女士的脚注 [2] 是 **检索未过滤** 而非幻觉；小陈的日志强调 **过滤必须在阿寻返回之前**；澄光 **整库下架** 是止血，**文件夹 ACL + 角色预览** 才是产品化；王姐想靠模型「自觉不说」对应常见误区——**输出护栏替不了检索 ACL**。

在 **S6 · 知识可运营、权限可审计** 中的位置：本篇锚定子系列第一条产品责任——**「谁能看见哪一页」**；后续的 **切片、版本、引用体验、投毒对抗** 都建立在 **「先有权，再谈准不准」** 之上。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 写清 **用户上下文从哪来**（SSO 字段、部门表）、**过滤发生在检索哪一步**、**无权限时是静默跳过还是提示「无权查看」** |
| **方案评审** | 问：**租户隔离做了吗？用户级 ACL 呢？** 源系统权限变更 **多久同步到索引？** 脚注链接拦得住，**复述拦得住吗？** |
| **指标设计** | **越权检索命中率**（抽检/红队）、**ACL 拒绝过滤段数**、**上架预览覆盖率**、**权限相关工单数** |
| **跨团队沟通** | 对运营：**「上传 ≠ 全员可见，先选可见范围」**；对工程：**「filter 在向量查询里做，别只靠后处理」**；对法务：**「检索审计日志保留多久」** |

## 类比锚定

**核心类比：图书馆代查资料——管理员按你的 **借书证等级** 决定能从哪个书库取哪几本书，而不是把整栋楼的书都搬到桌上再让你别翻机密册。**

| 你熟悉的 PM 经验 | 检索 ACL 要素 |
|------------------|---------------|
| 后台 **菜单权限**（运营看得到，客服看不到） | **角色 → 可见文档集** |
| 飞书文档 **「仅部门可见」** | **源系统 visibility 同步到索引** |
| 搜索框 **搜不到无权限页面**（企业微信 / 钉钉知识库） | **检索先 filter 再排序** |
| 导出 Excel **按列脱敏** | **字段级 ACL（进阶）**；本篇先 **文档/段落级** |
| 审计 **「谁下载了薪资表」** | **检索日志：谁问了、捞了哪些 doc_id** |

## 类比边界说明

### A. 概念核心要点

1. **ACL 在检索阶段生效**——无权限片段 **不应进入 prompt**；仅靠 **输出护栏或 Prompt 禁止泄密** 不可靠。  
2. **租户隔离 ≠ 用户授权**——同一客户企业内部仍有 **部门/职级/项目** 差异。  
3. **Grounding 会放大越权伤害**——**精确出处 + 复述正文** 比裸链接更易造成 **「官方泄露」** 观感。  
4. **运营标错是常态**——要有 **「以某角色预览检索」** 与 **上架范围** 可视化。  
5. **审计与止血同样重要**——事件后需知 **哪些文档曾被错误纳入候选集**。

### B. 类比失效点

| 类比说法 | 失效点 | 更准确的理解 |
|----------|--------|--------------|
| 「和飞书权限一模一样就行」 | 向量索引 **复制权限有延迟**；**切片后** 一段文档可能 **跨敏感边界** | 要定义 **同步频率、切片与权限粒度**；必要时 **敏感段单独入库** |
| 「搜不到就等于安全」 | 模型仍可能 **用参数化知识瞎编**；ACL 管的是 **库内证据**，不是 **所有泄露面** | **检索 ACL + Grounding + 输出护栏** 分层；本篇只管 **库内检索** |
| 「给每个用户建一个独立小库最简单」 | 文档量大时 **运维爆炸**；**公共制度** 重复切片浪费 | **共享索引 + ACL 标签** 是更可扩展路径 |
| 「拦了检索用户就永远不知道有这份文档」 | 产品可选择 **提示「存在但无权查看」** vs **静默跳过**——涉及 **体验与社工风险** | 需求里 **显式写策略**，别留给工程默认 |

## 本集 Checklist

**标准 / 规范流程**

- [ ] 入库文档带 **visibility 元数据**，支持 **与源系统 ACL 同步**（含同步延迟 SLA）  
- [ ] 检索 **先 filter 再相似度 / Rerank**；日志记录 **被 ACL 剔除的 doc_id**  
- [ ] Grounding **仅展示有权来源**；无权限内容 **不得出现在模型上下文**  
- [ ] 运营后台提供 **「以角色预览检索」** 与 **上架范围** 说明  
- [ ] 合规 **审计日志**（谁问、捞了啥、拦了啥）保留策略明确  

**中小常用方案**

- [ ] **文件夹 / 标签三档**（公开 / 管理岗 / HR 专属）+ 手动角色映射  
- [ ] 默认 **deny by default**：未标公开不进检索  
- [ ] 事件止血 playbook：**临时下架敏感标签 + 粗开关**  

**何时升级到完整版**

- 客户出现 **职级/项目级** 混库检索需求；**飞书/AD 权限变更频繁**；监管要求 **检索级审计**；或 **越权类 P1 工单** 重复出现。
