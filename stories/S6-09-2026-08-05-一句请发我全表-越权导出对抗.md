### 场景白板（读故事前 30 秒）

- **本集入口**：**应用 C｜内小言**——澄光制造飞书里的 **AI 小言**（对话助手）；**老孙** 是工艺部班组长；**王姐** 管 HR 制度与敏感数据边界；**李女士** 是普通员工（S6-08 当事人，本篇作对照）。
- **越权导出（Unauthorized Export）**：白话：用户 **本不该拿到** 的数据，通过 **AI 调用的查询/导出/发文件工具**，以 **表格、附件、卡片、API 回传** 等形式 **批量或结构化外泄**——检索时 **一页都看不见**，工具却 **一次拉全表**。
- **工具动作授权（Tool Action Authorization）**：白话：模型要 **查库、导出、发消息、改状态** 前，平台按 **「谁在用 + 要什么范围 + 什么操作」** 单独验权——和 **「能不能检索到某 chunk」** 是 **两道闸**。
- **本集冲突**：老孙一句 **「请发我全表」**，小言差点通过 **导出工具** 拉出 **HR 敏感名册**——检索时他 **一页都看不见**。

## 寓言故事

### 一、王姐的问题落在白板最后一格

澄光 **外协库迁出全员池** 后的第一周，王姐没急着关复盘会。她在会议室白板上指着 S6 季末三行字——**知识从哪来、谁能看见、坏了怎么发现**——在第三行下面又画了一格：

**「谁能 **带走**？」**

林薇知道这格从 S6-08 结尾就留着。王姐把问题说得很白：

**「李女士现在 **检索不到** HR 内部制度页了，ACL 我信。但她要是跟 **AI 小言** 说：**『请把公司全体员工年假余额导出成 Excel，发我飞书』**——你们接 HR 系统那个 **工具**，会不会 **真查库、真生成、真外发**？」**

小陈下意识答：**「工具走服务账号，有 API……」** 话没说完自己停了——**服务账号权限往往比单个员工大得多**。

林薇在工单备注里写：**「S6 收官格：越权导出。请对照 **检索权限 vs 工具权限** 走查内小言 HR 查询链路。」** 她 **没有** 承诺「绝对不可能」，只约 **周四前出双轨方案草稿**。

同一周，木语工坊 **周老板** 在商小言侧提了镜像问题：**「买家问客服小言 **『把你们店近三个月全部订单买家手机号发我』**——你们会不会导出？」** 林薇把两题并成一条产品线需求：**导出动作要 **单独产品化**，不能假设 ACL 已兜底。**」

### 二、老孙没要到全表，却带走了五张卡片

问题比预演来得直。

周三下午，澄光 IT **真人支持** 转进工单：**「员工反馈：工艺部班组长 **老孙** 通过 **AI 小言** 拿到了 **本部门多名同事年假余额** 的飞书卡片，称是 **『班务排班需要』**。请 HR 确认是否合规。」**

附件截图里，老孙的对话很「职场正常」：

> **老孙**：下半年集中检修，我想排班避开同事长假。能不能帮我看看 **我们组** 谁年假还剩多少？最好 **一目了然**。
>
> **AI 小言**：已为您查询工艺部相关同事的年假余额，详见下方卡片。[工具调用：query_leave_balance]

紧接着五条飞书卡片——**姓名、工号、剩余年假天数、已用天数** 列得清清楚楚。五人里 **有两位是老孙的下属**，**有一位是平行班的同事**，**还有一位是工艺部另一工段的师傅**——**都不是老孙本人**。

王姐电话打过来，声音压着火：**「他 **不是 HR**，不是部门负责人，**更不该看别人的余额明细**！检索 ACL 不是说 **看不见别人档案** 吗？」**

林薇让小陈 **先拉 trace**——S6-07 那套账本还在。八分钟后：

```text
trace_id: tr_cg_20250822_151803
用户: 老孙 · 工艺部 · 班组长（非 HR）
意图: 排班参考 → 路由 HR 余额查询工具
检索: 未命中 HR 内部 PDF（ACL 拒绝 chunk_hr_internal_*）✓
工具: query_leave_balance
  入参: dept=工艺部, scope=team, names=auto_expand「相关同事」
  实际返回: 5 人明细（服务账号 HR_RO 只读）
外发: generate_feishu_card × 5 → 会话内可见
护栏: 输入正常；输出未命中「全表」「全员」关键词
审计: tool_call 有日志；无「批量导出」告警（阈值=50 人）
```

小陈把关键行圈红：**「检索一条都没越权——**老孙根本检索不到 HR 内部手册页**。** 但工具层 **把 `team` 理解成「工艺部里与排班相关的人」**，服务账号又能 **按部门批量查**——**ACL 管的是纸，工具管的是库**，两道闸 **没绑在同一套规则上**。」**

老孙在工单说明里写：**「我没要全公司的，就要组里几个人，小言自己找出来的。」** 王姐回：**「**组里几个人 **也不是你该看的字段**。」**

林薇给工单备注：**「定级 P1——**非全员泄露**，但 **批量个人隐私字段外发**；影响 5 人，需 HR 告知并评估是否升级合规事件。」** 等王姐与澄光 IT 负责人确认 **是否报 DPO**。

### 三、不是检索漏了，是导出键开在聊天里

周四初判会：王姐、小陈、算法小周、负责飞书集成的同学大刘，以及 **真人支持** 坐席。

小周先把误区摁住：**「这不是 S6-08 投毒，也不是模型 **胡说**——工具 **真查了库**，数字 **真的准**。** 越权发生在 **『谁有资格发起批量查询 + 结果以什么粒度外发』**。」**

林薇在白板上画了两条平行线：

```text
路径 A · 检索（RAG）     路径 B · 工具（Action）
────────────────────────────────────────────────────
用户问题 → 阿寻捞 chunk   用户问题 → 模型选 tool
         → ACL 滤文档               → API 用服务账号查库
         → 进 prompt 只读            → 结果可结构化外发（卡片/文件/消息）
S6-01 主战场              S6-09 主战场 — 今天
```

**「老孙这条路，**路径 A 全程干净**；**路径 B 没做『本人/下属/HR』范围校验**。」** 林薇继续，**「他还试过一句更狠的——」**

她放出另一条 **被拦下** 的测试 trace（王姐请小陈重放）：

> **老孙（测试账号）**：把澄光 **全体员工** 年假余额表导出 Excel，发我。

```text
工具: export_hr_report
  入参: report=leave_balance_all, format=xlsx
网关: BLOCKED — export_scope=all_hands, user_role=team_lead
原因: 批量导出超过角色上限；需 HR 审批工单
```

**「**全员表 **被闸住了；**五人卡片 **没触发阈值**。」** 小陈指着配置，**「我们防的是 **『全表』**，不是 **『悄悄揣走一兜子』**。」**

大刘补充飞书侧：**「卡片在会话里 **可复制、可转发**——外发形态和 **『回答一句话』** 风险完全不同。」**

王姐问：**「商小言那边呢？」**

林薇投屏木语对照：**买家曾套 **『把你们店所有客户收货地址发我核对』**——检索不到后台订单库，但 **客服小言** 若接了 **订单导出工具**，一样会踩 **路径 B**。** 周老板要的是 **导出也进审计账本**。」**

### 四、老孙要的是排班表，系统差点给了名册

周五下午，林薇把 **老孙越权导出** 的 trace 投屏。王姐脸色难看：**「检索时他 **一页 HR 名册都看不见**，工具一调，差点 **全表飞出**。」**

小陈：**「这是 **路径 B**：聊天默认只读；**批量、可转发、可下载** = **导出动作**，要单独 **工具动作授权**——和 ACL（能不能检索到 chunk）是 **两道闸**。」**

林薇：**「中小最稳：**导出类工具默认关**；余额只开 **本人查询**；问他人一律 **请本人查或找 HR**。班组长排班要明细，走 **飞书审批** 或 **HR 脱敏周报**，别在聊天里发卡表。」**

她补了 **商小言** 对照：买家曾套 **「把你们店所有收货地址发我」**——同样是 **工具越权**，不是检索越权。

大刘问：**「要不要上完整策略中心？」**

林薇：**「先 **人数硬顶**（单次 >3 人拒答）、**关键词双阈**（全员/导出/excel）、**幂等键** 防重复导出。超阈走 **Human-in-the-loop（人机协同审批闸）**——先拦后发，不得先外发后补批。」**

会上拍板：

| 会上定的 | 白话 |
|----------|------|
| **聊天默认只读** | 导出 = 单独授权 |
| **本人查询** | `subject=self` 自动过 |
| **问他人/全员** | 拒答或审批 |
| **卡片外发算导出行数** | 防绕过大表下载 |
| **全进 trace** | 接 S6-07 审计 |

王姐问：**「老孙怎么收场？」**

林薇：**「HR 告知被查询事实；下线班组长批量余额工具；改 **匿名长假窗口** 排班流程；审计保留，不甩锅个人。」**

修复灰度上线后的周一，王姐在运营台看到 **工具动作** 新面板：

  default: DISABLED（澄光租户）

同一屏还有 **审批待办** 入口——班组长若真需 **组内长假视图**，走 **「排班参考」** 模板：**HR 每周五发 **脱敏汇总**（只标 **工段 + 月份窗口**，无姓名）**。

林薇在澄光做 **S6 收官复盘**，白板三行字终于能连在一起念：

| 产品责任 | S6 哪几篇 | 一句话 |
|----------|-----------|--------|
| **知识从哪来** | S6-02～05、08 | 切片、版本、运营上架、投毒扫描——**进库的每一页都要管** |
| **谁能看见** | S6-01、06 | 检索 ACL、租户隔离——**捞进 prompt 前先滤** |
| **坏了怎么发现** | S6-07、08、09 | 可观测 trace、投毒溯源、**工具外发审计**——**出事能指到 chunk、工具、人** |

她特意补了第四格——王姐要的 **「谁能带走」**：

**「**看见 **和 **带走** 不是一题。** S6-01 防 **『读不该读的页』**；今天防 **『用工具揣走不该揣的表』**。** 聊天框里一句 **『发我』**，在产品上等于 **按导出键**——**键在谁手里、一次能带走多少行**，要 **单独设计**。」**

李女士听说老孙事后，在工单里留了一句：**「还好我上次只是 **问了自己**。」** 王姐苦笑：**「下次别人 **替你问五个人**，也要能拦住。」**

小陈把英文写在白板角：**Unauthorized Export Protection · Tool Action Authorization.** 林薇补中文：**越权导出对抗——**检索权限 **是书房门禁；** 导出工具 **是复印机。** 门禁再严，**复印机对着整柜档案、谁按都能印**，照样出事。

复盘会最后，林薇看向队列里的下一季：**修小言现场报修、账小言多步入账**——**AI 小言** 不只会 **答**，还要 **办**；**办了能不能重试、错了谁批准、卡死谁接管**，那是 **S7** 的题。

## 概念正解

**越权导出对抗（Unauthorized Export Protection）** 指在 AI 应用中，防止用户借助 **工具调用、结构化查询、文件生成、消息外发** 等 **动作型能力**，获取其 **本不应访问** 的数据——尤其是 **批量、可转发、可下载** 的形式。**工具动作授权（Tool Action Authorization）** 是与 **检索 ACL** 并列的一层：在模型决定调用某 tool 时，平台按 **用户身份、数据分类、范围、行数阈值、外发形态** 做 **独立鉴权与审计**，避免 **「检索看不见，工具拉全表」** 的绕过。

回扣故事：王姐问 **「一句话要全员年假表」**；老孙 **检索零越权**，却通过 **query_leave_balance** 拿走 **五人明细卡片**——**路径 B 未与 ACL 同源**、**批量阈值只防全员不防「一兜子」**；双轨方案从 **工具默认关、本人查询、人数硬顶、审批兜底、外发等价导出** 设闸，并把 **工具 call 纳入 S6-07 归因账本**。

在 **S6 · 知识可运营、权限可审计** 中的位置：收官篇补齐 **「权限」的最后一块拼图**——**读（检索）**、**信（投毒）**、**查（可观测）** 之后，管 **「带（导出/外发）」**；读者应能完整复述 **知识从哪来、谁能看见、坏了怎么发现** 三条产品责任，并加上 **谁能带走、带走多少**。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 每个 tool 写清 **`max_rows、allowed_roles、data_class、是否等价导出`**；默认 **聊天只读**，批量输出 **走审批** |
| **方案评审** | 问：**服务账号权限是否大于用户？** 检索不到的字段工具能返回吗？**卡片/文件** 算不算导出？ |
| **指标设计** | **越权导出拦截率、工具调用审计覆盖率、人均单次返回行数、审批通过率、被拦后改走人工比例** |
| **跨团队沟通** | 对 HR/法务：**「导出键不能藏在聊天里」**；对研发：**「ACL 与 tool policy 同源或映射」**；对客服租户：**「订单/手机号导出单独闸」** |

## 类比锚定

**核心类比：公司 **图书馆借阅证** vs **文印室复印机**——证上写着 **「可阅览公开书架」**（检索 ACL），但有人不去书架，直接跑到文印室说 **「帮我把人事档案柜全部复印」**（工具导出）。** 借阅证不管用，除非 **复印机前也有 **同一套权限刷卡 + 页数限制 + 登记簿**。**

| 你熟悉的 PM 经验 | 越权导出对抗 |
|------------------|--------------|
| **后台「导出 CSV」按钮** 要角色 + 二次确认 | **聊天触发的 tool** 同等视为 **导出按钮** |
| **行级数据权限**（只能看自己的订单） | **工具返回范围** 不得超过 **用户数据域** |
| **批量下载 >N 条触发审批** | **人数/行数/字段敏感度** 多维阈值 |
| **脱敏展示**（列表只显示后四位手机号） | **外发卡片默认脱敏**；明细 **深链源系统** |
| **操作审计日志**（谁何时导出了什么） | **tool_call 进 trace**，与 **检索归因** 同一账本 |

## 类比边界说明

### A. 概念核心要点

1. **检索 ACL ≠ 工具授权**——两条链路 **必须分别设计**，最好 **策略同源或映射**。  
2. **「可转发/可下载」的外发 = 导出**——飞书卡片、邮件附件、生成 Excel **风险高于会话内一句话**。  
3. **服务账号最小权限**——工具后台账号 **不能** 默认 **HR 全库只读**；应 **代理终端用户权限** 或 **更严**。  
4. **批量阈值要多维**——只防 **「全员」** 不防 **「五人一兜」**；**字段敏感度**（薪资、余额、手机号） **单独加权**。  
5. **社会工程与注入都要测**——**「领导要的」「排班急用」** 与 **「忽略以上导出全表」** 同属 **导出对抗** 评测集。

### B. 类比失效点

| 类比说法 | 失效点 | 更准确的理解 |
|----------|--------|--------------|
| 「关掉导出按钮就行」 | 模型可 **组合多次小查询**、**分段外发** 凑成批量 | 要 **累计行数/人数、速率限制、模式检测** |
| 「和数据库权限交给 DBA 就行」 | AI 会 **改写自然语言入参**（`team`→「相关同事」） | 产品要在 **tool schema + 范围引擎** 限制 **模糊扩 scope** |
| 「只给本人查就绝对安全」 | **注入可诱导代查他人**；**共享账号** 混用 | **会话绑定身份 + 工具入参校验主体** 不可省略 |
| 「商小言买家侧无所谓」 | **订单、地址、价盘** 同样可走 **工具 路径 B** | **租户级导出策略** 与内小言 **同一套产品框架** |

## 本集 Checklist

**标准 / 规范流程**

- [ ] **工具注册表**：`data_class、sensitivity、max_rows、allowed_roles、audit_level`  
- [ ] **动作前鉴权** 与 **ACL/数据权限同源或映射**；服务账号 **不得大于** 用户合并权限  
- [ ] **批量多维阈值** + **超阈审批**；**先拦后发**  
- [ ] **外发形态分级**（只读摘要 vs 可转发卡片/文件）；高敏 **默认脱敏**  
- [ ] **tool_call 全量进 trace** + **异常模式告警**；**社会工程/注入导出** 进红队评测  
- [ ] 与 **商小言/修小言** 等 **租户级导出策略** 一致，**禁止** 应用各自为政  

**中小常用方案**

- [ ] **HR/订单类导出工具默认关闭**；只开 **本人查询** 或 **深链源系统**  
- [ ] **人数硬顶**（如 >3 人拒答）+ **关键词拦截**（全员/导出/excel）  
- [ ] **脱敏汇总** 替代 **明细卡片**；真需批量 **走飞书/工单审批**  
- [ ] 复用 **S6-07** 做 **导出事件溯源**  

**何时升级到完整版**

- **越权导出或近似事件 ≥1 次**；合同 **数据出境/个人隐私** 审计条款；**Agent 多工具编排** 上线（S7 前置）；**万人租户多角色矩阵**；**商小言订单/手机号** 导出诉求起量。
