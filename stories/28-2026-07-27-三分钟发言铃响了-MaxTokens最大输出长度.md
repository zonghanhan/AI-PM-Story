### 场景白板（读故事前 30 秒）

- **本集入口**：星尘 **小言平台后台** →「模型参数」页里 **Max Tokens / max_tokens** 一行；账单里 **输出 Token 数** 与 **截断率** 并列。
- **Max Tokens（最大输出长度）**：白话：模型 **这一轮最多能说多长**；管 **输出**，不管 **读进多少材料**（那是 Context Window，见第 9 篇）。
- **finish_reason=length**：白话：生成日志里 **因长度到了而正常截停**——不是系统报错，是 **发言铃响了**。
- **助手**：各应用里的 **AI 小言**；**苏姐** 是财务；**张先生** 仍是 **应用 B（修小言）** 客户。
- **本集冲突**：**重复惩罚**（Frequency Penalty，见第 27 篇）调稳后，**修小言** 的更换步骤 **说到一半断掉**；**内小言** 某制度问答 **一口气吐出八千字**，没人看完——两边都是 **max_tokens 配错了场景**。

## 寓言故事

### 一、步骤说到「然后安装」就没了

Frequency Penalty（重复惩罚，见第 27 篇）上线两周，修小言的 **车轱辘话投诉** 降了七成。林薇以为 **生成参数** 这一章可以松口气。

周三下午，张先生又在客户群里 @ 她，附了一张截图：

**「滤芯装到一半，小言回我：『请先断电，确认机型匹配后，取下旧滤芯，清洁接口，然后安装——』后面没了。我车间师傅问我：安装什么？装哪？你们是不是省流量？」**

林薇第一反应还是查 **检索和剧本**——SOP 片段完整，System Prompt 里写了 **「分步输出，一步一行」**。她拉 **当次生成日志**，输入侧一切正常；目光落到 **输出侧**：

**completion_tokens：128**  
**finish_reason：length**  
**max_tokens：128**

小陈指着 `finish_reason`：**「`length` 就是 **铃响了**——**这一轮允许它往外说的 Token 上限到了**，生成被 **硬截断**。上面 `completion_tokens: 128` 是 **实际吐出了多少**；用户看到的是 **话说一半**，日志里写的是 **正常结束（因长度）**，不是模型不会写。」**

林薇愣了一下：**「我们 Context Window 不是配了 128k 吗？材料明明都读进去了。」**

小陈摇头：**「那是 **圆桌能坐多少人**（输入上限）；今天是 **每人最多讲几分钟**（输出上限）。** 读得进整本手册，不代表 **允许它念完一整本**。」**

---

### 二、会议室里的发言铃

为了讲清楚，小陈把白板改成 **部门周会**。

**「想象内部分享会。PPT 材料可以发一百页（输入），但主持人给每人 **三分钟发言铃**（输出）。铃响那一刻，不管你讲到第几页，**必须停**——不是内容不好，是 **规则就这么写的**。」**

他在铃旁边写了几个数字：

| 场景 | 常见 max_tokens 体感 | 用户感受 |
|------|----------------------|----------|
| **短信验证码式短答** | 几十 | 干脆，但 **稍复杂就断** |
| **客服首屏回复** | 一两百 | 够寒暄 + 一个要点 |
| **维修 SOP 分步** | 五百–一千 | 要 **留尾**，否则 **缺最后两步** |
| **制度全文复述** | 不设或过大 | **账单爆炸**，用户 **根本不看** |

苏姐正好抱着 **上月 API 账单** 进门，听到「不设上限」几个字，脸色一沉：**「内小言上周有个制度问答，**单次输出将近六千 Token**——相当于 **一篇小论文**。财务问：这是 **产品默认值**，还是 **谁忘了拧盖子**？」**

林薇调出那条会话：用户问 **「差旅报销制度里，境外发票怎么处理？」** 本该 **摘三条要点 + 附制度链接**；小言却 **从总则第一章复述到附则**，流式输出 **滚了四分钟**。用户中途关页面，后台仍 **继续生成到顶**。

日志里 **max_tokens 设 4096**，实际却吐到 **五千多 Token**——小陈解释：**「个别厂商实现对得不严，偶尔还能冲破标称上限；但产品判断不变：**你没按场景设闸，模型就爱 **把知道的都倒出来**。」**

---

### 三、不是写得短，是「允许写多长」

当晚预发，他们 **固定同一份滤芯 SOP 检索结果**，只改 **max_tokens**，让修小言生成 **更换步骤** 五遍：

| max_tokens | 典型现象 | finish_reason |
|------------|----------|---------------|
| **64** | 只到 **「取下旧滤芯」** | length |
| **128** | 张先生截图那种 **「然后安装——」** | length |
| **512** | 七步齐全，含 **扭矩与复测** | stop |
| **4096** | 步骤重复两遍，还附 **「常见误区」小作文** | stop |

林薇盯着第一列：**「用户骂 **半句话**，后台却可能记成 **成功返回**——接口没报错，只是 **内容被铃响截断了**。」**

她在 **双轨文档** 里加了一页：

**标准 / 规范流程（多租户、强审计）**

| 环节 | 做什么 |
|------|--------|
| **场景区间** | **短答 / 卡片 / SOP / 长文** 分档默认 max_tokens；**禁止全站一个数** |
| **与 Context Window 分工** | 输入窗管 **读多少**；max_tokens 管 **说多少**；**两者独立计费、独立告警** |
| **截断监控** | 看 **finish_reason=length 占比**；SOP 类 **>1% 就要查** |
| **流式体验** | 前端 **截断时显式提示「未完待续」** 或 **自动续写一轮**；别让用户 **对着半截话发呆** |
| **成本闸门** | 长文场景 **默认摘要 + 链接**；真要全文再 **二次确认** 或 **提高上限** |

**中小常用默认方案（星尘当前）**

- **接云 API**：修小言 SOP **512–1024**；内小言制度问答 **256–512（摘要模式）**；创意长文 **单独 SKU + 明示字数**。  
- **前台映射**：**「简答 / 标准 / 详解」** 三档——对应不同 max_tokens，**不写 Token 英文**。  
- **可暂缓**：**续写按钮**（「继续说完」）比 **盲目拉高默认上限** 更省成本。

张先生那单，他们把 **修小言 SOP 接口** 从 **128 调到 768**，同题再生：**七步到 **「通电复测无泄漏」** 才收尾**。张先生回：**「这次像一份完整工单。」**

---

### 四、铃响之后，是续讲还是翻页？

复盘会上，产品新人问：**「截断了，让模型 **接着上一句继续说** 不就行了吗？」**

小陈：**「可以，那叫 **续写 / 多轮补全**——但要 **产品化**：用户点一次「继续」，**再花一轮输出 Token**；还要防 **无限续写刷账单**。更稳的是 **先把场景默认上限配对**。」**

大刘补工程细节：**「max_tokens 在流式里 **边吐边计数**；用户 **提前关页面**，有的供应商 **仍计满已生成部分**，有的 **按断开截断**——**合同里要写清**。另外 **128 个 Token 中英文不一样**：中文 **一百多字** 可能就到底了。」**

林薇把 **常见误区** 写在白板底：

1. **Context Window 大 ≠ 回答可以无限长**——输入和输出 **两把尺子**  
2. **finish_reason=length 不是偶发 bug**，是 **上限配太小** 的 **正常信号**  
3. **上限过大不是「大方」**，是 **延迟变长、账单变厚、用户反而不读**  
4. **截断投诉要先查 max_tokens**，再查检索、惩罚、温度  
5. **「详解档」要有入口**，别让 **默认通道** 承担 **论文级输出**

苏姐最后提了一个 **产品指标**：**「我希望在账单里看见 **输出 Token 分场景分布**，别只有一张总数——否则我不知道是 **谁把铃关掉了**。」**

---

### 五、接近结尾：铃不是禁言，是节奏

又一周，修小言 **「步骤断一半」** 工单 **归零**；内小言制度问答 **平均输出 Token** 降了 **六成**，**「太长不看」** 的反馈少了。配置台 **参数组合卡** 多了一行：

| 场景 | max_tokens 建议 | 产品备注 |
|------|-----------------|----------|
| 首屏短答 | 128–256 | 够一个结论 + 一个动作 |
| 维修 SOP | 512–1024 | **必须测截断率** |
| 制度摘要 | 256–512 | 默认 **要点 + 链接** |
| 长文生成 | 单独开关 | **明示预估字数与费用** |

林薇给新同学讲岗，指着 **max_tokens**：

**「用户骂 **话说一半**，多半不是模型 **变笨了**，是 **发言时间到了**。这个参数就是 **三轮分享里每人几分钟**——**铃响必须停**，但 **产品可以决定：给几分钟、铃响后让不让续讲、谁为多出来的分钟买单**。」**

小陈把英文写在旁边：**Max Tokens。** 阿梅改文案参数前先问第二句：**「用户要 **一句话标题**，还是 **一整页说明书**？」**——**两个场景，两个上限，别全站 128，也别全站 4096。**

张先生在修小言群里又发了一张 **新滤芯照片**，这次附言：**「步骤完整了。下次要是太长，给个 **继续说完** 按钮也行。」** 林薇把这句贴进 **需求池**：**铃响之后怎么接**，是 **下一篇交互题**；**今天先把 **铃设对**。

## 概念正解

**Max Tokens（最大输出长度）** 是大语言模型在 **单次生成** 中，允许 **输出侧** 产生的 **Token 数量上限**：它 **不限制模型读进多少材料**（那是 **Context Window / 输入 Token**），只限制 **这一轮最多能「说」多长**。到达上限时，生成 **主动停止**，日志常见 **`finish_reason: length`**（因长度截断）。**设太小**，会出现 **步骤缺尾、句子半截、列表没列完**；**设太大或不限**，则 **延迟增加、输出 Token 费用上升、用户阅读负担加重**，模型还可能 **重复铺陈、夹带无关内容**。常与 **场景分档、流式展示、续写策略、成本监控** 一起设计；**不能替代** 好的 Prompt（「请用三条要点回答」）或 **摘要式产品形态**。

回扣故事：张先生的 **「然后安装——」** 是 **max_tokens=128 + finish_reason=length**；内小言 **制度全文复述** 是 **上限过大 + 未做摘要产品形态**；预发表格说明 **同一材料在不同上限下的完整度差异**；苏姐的账单追问对应 **输出 Token 分场景治理**；「续讲按钮」对应 **截断后的产品接续策略**，与 **先把默认上限配对** 是两层问题。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 按 **短答 / SOP / 长文** 写 **max_tokens 默认值与上下限**；写明 **截断时前端文案** 与 **是否提供续写**；与 Context Window **分开列项** |
| **方案评审** | 问：投诉是 **真截断（length）** 还是 **模型主动停（stop）**？**流式中途关页** 怎么计费？中文场景 **128 Token 够几条步骤**？ |
| **指标设计** | **finish_reason=length 占比**、分场景 **平均输出 Token**、截断会话的 **人工重试率**、长文场景的 **阅读完成率 vs 费用** |
| **跨团队沟通** | 对运营：**「详解档 = 更高上限 + 更慢 + 更贵，不是隐藏开关」**；对工程：**「日志请带 max_tokens 与 finish_reason」**；对财务：**「输出 Token 按场景分桶」** |

## 类比锚定

**核心类比：部门周会的「每人发言三分钟」铃。** 会前材料可以发很多页（输入 Context Window），但 **每人上台只能讲到铃响**（输出 Max Tokens）；**铃响不是评价内容好坏**，只是 **这一轮的时间规则**；**想讲完** 可以 **申请加场（续写）** 或 **会前改议程（调上限 / 改摘要形态）**。

| 你熟悉的 PM 经验 | Max Tokens 要素 |
|------------------|-----------------|
| 发布会 **嘉宾限时 3 分钟** | **单次输出的硬上限** |
| 邮件 **「请三条 bullet 回复」** | **Prompt 软约束**；max_tokens 是 **硬闸门** |
| 工单 **描述截断「…」** 用户以为系统坏了 | **finish_reason=length** 需 **产品显式提示** |
| 直播 **弹幕区刷长文没人看** | **上限过大 → 成本与体验双输** |
| 会议 **「超时请坐，想补充请举手第二轮」** | **续写 / 多轮补全** 的产品化 |

## 类比边界说明

### 一、概念核心要点

1. **Max Tokens 管输出，Context Window 管输入**——**读得进 ≠ 允许说得完**；需求与计费 **都要分开写**。  
2. **截断（length）是配置结果，不一定是故障**；SOP、清单类场景 **必须监控截断率**。  
3. **上限过小伤完整度，过大伤成本与阅读**——靠 **场景分档 + 摘要默认 + 详解可选** 平衡。  
4. **与 Temperature、Top-p、Penalty 独立**：那些管 **怎么说**；max_tokens 管 **说多长**。  
5. **流式输出不消除截断问题**，只把 **「等到底才发现半截」** 变成 **「看着字停住」**——**前端要有接续策略**。

### 二、类比在哪里会失效

| 类比说法 | 失效点 | 更准确的理解 |
|----------|--------|--------------|
| 「三分钟到就一定会停」 | 有的实现 **与模型硬顶、stop 序列** 交互复杂；**实际字数因中英文 Token 不同** | 用 **Token 数 + 业务实测** 标定，不用 **「相当于几百字」** 拍脑袋 |
| 「把铃调大就能解决所有半截话」 | 模型可能 **啰嗦重复**；**账单与延迟线性恶化** | **优先改 Prompt / 摘要形态**，再 **适度提上限** |
| 「用户关页面就不计费了」 | **供应商策略不一**；有的 **已生成 Token 仍计费** | **合同与监控按厂商规则** 单独对齐 |
| 「和 Context Window 是一回事」 | **输入输出分开限**；**总费用 = 输入 Token + 输出 Token** | 产品文档 **禁止混写成「窗口大小」一个词** |
