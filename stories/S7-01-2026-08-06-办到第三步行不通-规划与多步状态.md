> 今日概念在知识树中的位置：S6 收官后，**修小言** 现场 **拍照报修** 已能 **答**——手册、停产、滤芯型号说得头头是道。星尘把 **「一条龙代办」** 提上日程：识图 → 查质保 → 查备件 → 建工单 → 通知仓库。演示视频里 **AI 小言** 七步一气呵成；上线第一周，**张先生** 在产线边盯着转圈，**第三步行不通**，再点一次，**两张工单** 躺在半路。今天卡在 **规划与多步状态**：Agent **办事** 不是一次问答，产品要画 **任务状态机**——**办到哪、卡在哪、重试从哪续、用户看见什么**。

### 场景白板（读故事前 30 秒）

- **本集入口**：**应用 B｜修小言**——设备客户企业租户里的 **AI 小言**（对话助手）；**张先生** 是现场工程师，用 App **拍照报修**；**阿梅** 是星尘售后运营，盯客户工单与演示录屏。
- **Agent 办事链**：白话：用户一句「帮我办」，**AI 小言** 要 **自己拆步骤、调多个工具、等上一步结果再往下走**——不是 RAG 捞一页就答完。
- **多步状态（Task / Run State）**：白话：一次「办事任务」在系统里要有 **唯一任务号、当前第几步、每步成功/失败/等待中、已拿到的中间结果**——像快递单 **已揽收 / 运输中 / 派送失败**，不能每次重试都从 **「下单」** 重来。
- **WMS（仓库管理系统）**：客户企业管 **备件入库、出库、库存数量** 的那套系统；本篇第三步「查库存」就是调它。
- **本集冲突**：演示里七步 **一键成功**；现场 **第三步 WMS 超时**，张工以为没办成再点一次，结果 **建了两张工单**。

## 寓言故事

### 一、演示里的一键，和现场的一句「帮我办」

修小言 **Agent 报修 1.0** 上线前，阿梅在客户群里发过一段 **90 秒录屏**，标题很直白：**「拍照到工单，不用切三个系统。」**

画面里，演示账号 **「华东维保·张工」** 对着一台注塑机控制柜拍了张铭牌图，跟 **AI 小言** 说：

> **张工（演示）**：这台机子液压站异响，帮我走报修，顺便看看滤芯有没有现货。

**AI 小言** 在侧边栏弹出 **步骤条**，像进度条一样往下走：

```text
① 识图确认机型 …… 完成
② 查质保与合约 …… 完成
③ 查备件库存 …… 完成
④ 创建售后工单 …… 完成
⑤ 通知区域工程师 …… 完成
```

最后一句总结：**「工单 XR-2026-0812-009 已创建，滤芯 PM-8842 仓内有 3 件，已为您预约明日上门。」** 群里一片「可以可以」。

林薇在内部评审里把 **S7 季目标** 写在白板第一行：**Agent 从演示到值班**——**能答** 不够，要 **能办**；**演示一键成功** 不够，要 **现场超时、重试、半道卡死** 都有产品说法。

她特意问小陈：**「步骤条是 **真状态**，还是 **前端动画**？」**

小陈当时答得诚实：**「演示环境 **仓库接口 Mock**（用假数据顶替真 WMS），七步 **串行预编排**；真租户接 **客户 WMS（仓库管理系统）**，第三步 **可能慢、可能挂**。」**

阿梅记了一句客户原话：**「张工他们可不会等 90 秒还不动。」**

---

### 二、第三步行不通，屏幕上还在说「正在为您办理」

问题在 **灰度第三天** 进来。

客户企业 **澄光制造** 的 **张先生**——修小言老用户，报修过滤芯、查过停产公告——在产线边拍了张 **冷却塔风机** 铭牌，发给 **AI 小言**：

> **张先生**：风机轴承异响，可能得换总成。帮我报修，顺便查一下 **CF-220 总成** 有没有货，别让我白等工程师来。

前两句回复还挺像演示：**「已识别机型 CF-220，质保期内。」** 然后界面进入 **「正在为您办理……」**，转圈超过 **四十秒**。

张先生又拍了一张 **异响部位** 特写发过去，想补信息。 **AI 小言** 回：**「请稍候，正在为您查询备件库存。」** 还是转圈。

一分钟后，终于弹出一句：**「抱歉，备件系统暂时繁忙，请稍后重试。」** 没有步骤条，没有 **「办到哪了」**，只有 **失败**。

张先生站在噪声很大的车间里，手指已经点向 **「再试一次」**——同一句话又发了一遍：

> **张先生**：刚才没办成，再帮我报修一次，查 CF-220 总成库存。

这一次 **快了很多**：十五秒内连收三条——**「质保有效」**、**「库存 1 件」**、**「工单 XR-2026-0816-047 已创建」**。张先生松口气，收拾工具准备去下一台机。

两小时后，澄光 IT **真人支持** 把工单转进星尘：**「张工反馈 **重复报修**，仓库看到 **两张工单 047、048**，内容几乎一样；现场只想要 **一张单 + 准确库存**。」**

阿梅把截图丢进值班群。林薇让小陈 **拉 trace**——S6-07 那套账本还在，只是字段从 **chunk_id** 换成了 **tool_call_id** 和 **一步都没记全的 run_id**。

### 三、不是模型笨，是任务没有「停在半路」的地址

周四初判会：林薇、阿梅、小陈、负责 WMS 对接的大刘，以及 **真人支持** 坐席。

小陈先把两次会话的 trace 并排投屏：

```text
【第一次 · 14:03】session_id: sess_cg_zhang_0816_a
  turn_1: 用户图文 → 识图 tool OK → 机型 CF-220
  turn_2: 查质保 tool OK → in_warranty=true
  turn_3: 查库存 query_spare_part(CF-220) → TIMEOUT 32s（WMS 网关 504）
  turn_4: 模型生成「请稍后重试」→ 会话结束（无 run 持久化）

【第二次 · 14:06】session_id: sess_cg_zhang_0816_a（同会话）
  turn_5: 用户「再帮我报修」→ 模型 **重新规划整条链**
  turn_1': 识图（用上下文，未再调图）→ OK
  turn_2': 查质保 → OK（重复调用）
  turn_3': 查库存 → OK，qty=1
  turn_4': 创建工单 create_ticket → XR-0816-047
  turn_5': 模型又触发 create_ticket（retry 语义歧义）→ XR-0816-048
```

大刘指着 **504**：**「客户 WMS 中午有 **批处理窗口**，接口 **慢是常态**——不是修小言独有。」**

林薇关注的却是另一行：**「第一次 **第三步挂了**，系统里 **没有一张『办了一半』的任务单**；用户第二次说 **『再报修』**，模型 **从整条链开头理解**——质保 **又查一遍**，工单 **建了两张**。」**

阿梅补充用户视角：**「张工看见的是 **转圈 + 失败**；他以为 **啥也没办成**。** 演示里的步骤条 **这次根本没出现**。」**

小陈在白板上画了两条链：

```text
问答链（S1–S6 主战场）          办事链（S7 主战场）
────────────────────────────────────────────────────
一问一答 / 检索 + 生成          多步 tool 串行 / 有条件分支
无「半完成」业务含义              必须有 run_id、step、status
失败 = 重说一遍                   失败 = 从 **断点** 续办 or 显式取消
```

**「演示的七步，是 **产品经理写的剧本**；真 Agent 是 **模型现场拆步骤 + 调工具**。** 没有 **状态机托底**，剧本 **只在 PPT 里成立**。」** 林薇总结。

张先生在工单备注里写得很实在：**「我不是要投诉 AI，我就要别让我猜办没办成。」**

### 四、会上先吵了一句：演示的七步，现场接不住

周五下午，林薇把 **张工双工单** 的 trace 投在会议室墙上，开门见山：**「演示像一键，现场像黑盒——问题不在模型会不会拆步骤，在 **系统认不认『办到一半』**。」**

大刘先举手：**「第三步慢，是客户 **WMS（仓库管理系统）** 中午批处理，504 不稀奇。」**

阿梅把手机举起来：**「张工原话：**别让我猜办没办成**。他以为第一次啥也没建，才又报修一次。」**

林薇点头：**「所以不是再加一个更聪明的 planner，是先给每次『帮我办』发 **run 号**——像快递单，**已揽收 / 运输中 / 派送失败** 得写得出来。」** 她转向小陈：**「完整 BPM（业务流程管理）编排台我们暂时没有，**账小言** 那边也一样——拉 **MES（制造执行系统，记产量工单的业务库）**、再对 **PLC（产线设备侧采集，常和 MES 各记各的）**、生成 JSON、调 import，**第三步超时也不能从头 import 两次**。」**

小陈接话：**「中小客户先卖 **固定五步剧本**：识图→质保→库存→建单→通知，**不让模型自造第八步**——像 **BPMN**（画业务流程图的那套符号）的 lite 版，不是一上来就 DAG（有向无环图，可视化拖拽每一步箭头那种编排台）。」**

林薇在白板写下 **当天能拍板** 的几条——她说剩下的细则进 PRD，会上只过 **人话**：

| 会上定的 | 谁关心 | 白话 |
|----------|--------|------|
| 每次办事有 **run_id** | 张工、客服 | 用户能查 **办到哪一步** |
| 失败 **从断点续**，不整条重跑 | 研发 | 质保查过就别再查一遍 |
| **建单带幂等键**（同一 run 只建一张单） | 仓库 | 别再来 047、048 |
| WMS 慢时 **先建单、库存后补** | 张工 | 半成功也要说得清 |
| 步骤条绑 **真状态** | 阿梅 | 演示那种假动画不许上线 |

大刘皱眉：**「异步回调可以，但库存字段谁回写？」**

林薇：**「先 **人工补** 也能跑——**宁可单先落地，别双单**。等重复建单一周 ≥3 起，再谈 **Saga**（跨系统长事务，某步失败要补偿回滚那一套）和完整编排台。」**

阿梅问：**「张工那两张单怎么办？」**

林薇：**「047 保留，048 标记重复合并；给张先生推 **run 详情链接**——让他看见第三步曾经超时、第二次是从断点续上的。客服回访一句，不甩锅模型。」**

---

### 五、接近结尾：演示的七步，终于长在系统里

修复灰度上线后的周二，张先生在同一台 **CF-220** 上又测了一次（测试环境）。这次 **AI 小言** 第一句就回：

> 已为您开启报修任务 **RUN-CG-20260820-003**。当前进度：**① 识图 ✓ ② 质保 ✓ ③ 查库存进行中…**

库存接口又 **卡了 25 秒**——界面 **没假装成功**，步骤条 **③ 变黄**，下面一行小字：**「备件系统响应慢，可 **仅建工单** 或 **等待库存**。」**

张先生点了 **「仅建工单」**。系统 **跳过库存步**，**④ 建单 ✓**，run 状态 **「部分完成：库存待补」**。没有第二张单。

林薇在内部复盘白板写下 S7 第一句人话：

**「问答是 **回合制**；办事是 **工序制**。** 工序要有 **工单号、工位、做到哪**——**Agent 规划** 是 **拆工序**；**多步状态** 是 **让工序可暂停、可续办、可给人看**。」**

小陈把英文写在角上：**Agent Planning · Multi-step State · Run Persistence.** 阿梅补：**「演示里的一键，是 **剪辑过的工序**；值班要 **未剪辑的进度条**。」**

张先生在回访里留了一句：**「这次我知道 **卡库存**，不是 **卡你们不想理我**。」** 林薇把这句话贴进 PRD 首页。

## 概念正解

**规划与多步状态（Agent Planning & Multi-step State）** 指：当 **AI 小言** 从 **「回答问题」** 升级为 **「代办多步任务」** 时，产品必须为每一次办事建立 **可持久化的任务实例（run/task）**，并在其上演 **规划（拆步骤、选工具、处理分支）** 与 **状态流转（进行中 / 成功 / 失败 / 等待 / 取消）**。**规划** 解决 **「先做什么、再做什么」**；**多步状态** 解决 **「做到哪了、中间结果是什么、失败从哪续、用户看见什么」**——二者缺一不可，否则演示里的一键办事，在现场会变成 **黑盒转圈、重复下单、半张工单躺在半路**。

回扣故事：演示七步 **Mock 串行** 像一键；张先生 **第三步 WMS 超时**，系统 **无 run 持久化**，用户 **「再试」** 触发 **整条链重跑 + 双工单**；双轨方案用 **run_id、步骤状态机、断点续办、幂等建单、真实步骤条** 把 **办事** 从 **聊天回合** 里 **抽成可运营的工序**。

在 **S7 · Agent 从演示到值班** 中的位置：开篇 **概念扫盲**——先立 **「办事 = 工序制」** 的产品心智；后续 Human-in-the-loop 审批、工具失败重试与补偿、人工接管，都 **挂在 run/step 状态之上**。没有状态，**审批闸无附着点，重试不知重哪步，人工接管看不见半成品**。

**双轨落地（会上定的摘要，细则见 Checklist）**：**标准流程** 强调 run 持久化、状态机内规划、步级持久化与断点续办、真实进度条、异步降级与可观测；**中小默认** 先卖固定五步剧本 + 一张 run 表 + 建单幂等 + 「先建单、库存后补」话术；**暂缓** 完整 BPM 编排台、DAG 可视化、Saga 长事务——等重复建单或合同 SLA 逼上来再升级。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 每个 Agent 场景写 **步骤清单、合法状态转移、失败用户文案、是否允许部分成功**；**禁止** 只写「调用工具链」 |
| **方案评审** | 问研发：**run 存在哪、超时谁杀、重试是否幂等、UI 绑真状态还是假动画** |
| **指标设计** | **run 成功率、平均完成步数、卡死步 Top3、重复建单率、断点续办占比** |
| **跨团队沟通** | 跟客户 IT：**WMS（仓库管理系统）慢是常态** → 产品 **异步补库存**；跟算法：**规划在状态机内**，不是 **无限 tool 循环** |

## 类比锚定

| 你熟悉的 PM 旧经验 | Agent 规划与多步状态 |
|--------------------|----------------------|
| 电商下单 **订单状态**（待付款→待发货→配送中） | **run_id + step status**；用户随时查 **办到哪** |
| 审批流 **流程引擎**（节点、退回、重新提交） | **状态机转移**；失败 **回到失败节点**，不是 **重提整个流程** |
| 接口 **幂等键** 防重复支付 | **`idempotency_key=run_id`** 防 **重复建工单/重复入账** |
| 物流 **「运输中」可追踪** | **步骤条绑真实 tool 状态**；**等待** 要显示 **在等什么** |
| 客服 **工单挂起**（等客户补材料） | run **暂停态**；**部分完成**（单已建、库存待补）要 **可查询** |

## 类比边界说明

### A. 概念核心要点

1. **办事链 ≠ 问答链**：多步依赖 **上一步输出**，必须 **持久化中间结果**。  
2. **规划要有边界**：产品定义 **允许步骤与转移**；完全 **模型自由编排** 在值班场景 **不可控**。  
3. **用户可见状态必须真实**：假进度条 **一次失信**，用户就会 **疯狂重点**。  
4. **失败是常态路径**：每步 **超时、降级、续办、取消** 都要 **预写**，不是 **异常分支随便兜**。  
5. **写操作默认幂等**：建单、入账、发货 **同一 run 只能成功一次**（除非显式「再来一单」）。

### B. 类比失效点

| 失效 | 为什么不能照搬 |
|------|----------------|
| **「和 BPM 一模一样」** | **BPM**（Business Process Management，业务流程管理）用固定流程引擎管节点与审批；Agent **步骤可能动态**（要不要先识图、先查库存再决定派谁）；状态机要 **预留分支**，但 **不是** 纯人工配死的全流程 |
| **「像聊天一样失败就重发一句」** | 重发 **自然语言** 模型可能 **理解成新任务**；续办要靠 **`run_id` + 显式动作**，不能 **只靠上下文记忆** |
| **「超时就像接口重试三次」** | 工具重试 **可能重复写库**；要 **步级幂等 + 业务补偿**（S7 后续篇），不能 **无脑 retry** |
| **「步骤条像上传进度」** | 上传 **进度连续**；Agent **某步可能等外部系统分钟级**；要 **异步、部分成功、转人工**，不是 **0–100% 假条** |

## 本集 Checklist

**标准 / 规范流程**

- [ ] 每次办事生成 **`run_id`**，与 `session_id` 分离；**全生命周期可查询**  
- [ ] 产品定义 **步骤类型、合法转移、终止态**；模型规划 **在状态机内**  
- [ ] 每步 **持久化 input/output/error**；**中间结果** 供下一步与 **人工接管** 使用  
- [ ] **断点续办** 默认 **从失败步重试**；**已成功步不重复**（除非用户显式重来）  
- [ ] **写操作 tool** 带 **`idempotency_key`**；监控 **重复建单/重复入账**  
- [ ] UI **步骤条 / 时间线绑真状态**；**等待、失败、部分成功** 有 **固定话术**  
- [ ] trace 以 **`run_id`** 聚合；对接 S6-07 **可观测账本**  

**中小常用方案**

- [ ] **固定 5 步剧本** + 有限分支（报修、入账各一套）  
- [ ] **一张 run 表** + 三步状态 `pending/running/done|failed`  
- [ ] **建单幂等**；库存/对账 **可后补**  
- [ ] **步骤条 MVP**：当前步中文名 + 失败一行原因  
- [ ] WMS / MES（制造执行系统）**慢**：**先建单、后补字段** 话术

**何时升级到完整版**

- **重复建单/重复入账 ≥ 周级多起**；合同 **办事 SLA**；**单 run 超 8 步** 或 **跨应用编排**；需要 **审批闸、补偿事务**（触发 S7-02～04 专题）。
