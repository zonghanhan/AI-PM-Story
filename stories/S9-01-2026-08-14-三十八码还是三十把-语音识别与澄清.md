> 今日概念在知识树中的位置：S8 收官后，战场从 **运营侧工单台** 转到 **终端用户张嘴说话**。**悦衣坊** 在 **商小言买家侧** 开了 **语音改规格**——买家对着手机说 **「三十八码」**，**AI 小言** 却把购物车改成 **「三十把」**；商家后台 **真人客服** 接到投诉：**「我没说要批发！」** 同一周，**澄光制造** 的 **张先生** 在 **修小言现场** 口述 **「CX-708 滤芯」**，系统记成 **「C X 七百零八」**——**备件检索零命中**。今天拆 **语音识别与澄清**：**话先变成字（ASR）**，**字错了要在落单/建单前拦住**——**不是** 让大模型 **「猜用户想说啥」** 就完事。

### 场景白板（读故事前 30 秒）

- **本集入口**：**应用 A｜商小言买家侧**——C 端买家在 **商家店铺客服窗口** 用 **语音** 改尺码、改数量；**不是** 商家 SaaS 后台登录用户。**应用 B｜修小言** 对照：现场工程师 **口述故障/型号** 报修。
- **ASR（Automatic Speech Recognition，语音识别）**：白话：**麦克风音频 → 文字**；错在这一步，后面 **RAG、下单工具** 再聪明也救不回来。
- **澄清（Disambiguation）**：白话：当 **听写不确定** 时，**产品主动让用户确认**——点选、朗读回听、二选一卡片——**在调用下单/建单 API 之前**。
- **本集冲突**：**「三十八码」→「三十把」** 直接改购物车；**「CX-708」→「C X 七百零八」** 检索失败——**缺 ASR 置信度门槛与澄清 UI**。

## 寓言故事

### 一、买家说尺码，购物车进了批发量

悦衣坊是星尘 **商小言** 的老客户。十月大促前，运营在 **买家侧 widget** 灰度了 **「按住说话改规格」**——买家不用戳三级 SKU 页，**对着话筒说一句** 就能改尺码。

周二晚高峰，买家 **小周** 在直播间抢了一双运动鞋，付完款发现拍成 **四十二码**，赶紧进店铺 **AI 小言** 窗口，按住底部话筒：

> 「我要改成 **三十八码**，别的别动。」

三秒后，界面流式刷出 **AI 小言** 回复：

> 「好的，已为您将 **同款运动鞋** 数量改为 **三十把**，尺码维持四十二码。」

小周愣住：**「我什么时候说要 **三十把**？！」** 他往上翻，**语音转写条** 灰字写着：

```text
用户语音转写：我要改成三十把别的别动
ASR 置信度：0.71
是否触发澄清：否（阈值 0.65）
```

购物车快照里，数量栏从 **1** 变成了 **30**——**下单工具 `updateCartLine`** 已执行成功。

小周点 **「联系客服」**，悦衣坊 **真人支持** 坐席小琴回电：**「系统显示您 **语音确认改数量**……」** 小周：**「我说的是 **三十八码**！」** 小琴翻录音，耳朵里也听得出是 **「码」**，屏上却是 **「把」**。

小琴按惯例在星尘侧建跟进单 → **商小言对口 PM 林薇** 初判 **P2（体验，未资损）** → 拉 **小陈、算法语音同学、悦衣坊运营** 会诊。

---

### 二、会诊：错在「听写」，不是小言「理解力」

小陈先把 **同一条 session** 的链路摊开：

```text
① 音频采集（买家侧 WebRTC）
② ASR 服务 → 文本「我要改成三十把别的别动」
③ LLM（AI 小言）读转写文本 → 解析意图「改数量」
④ Tool updateCartLine(qty=30) → 成功
```

算法语音同学指着 **②**：**「**声学上 **三十八码** 和 **三十把** 在直播环境、外放喇叭下，**拼音相近、能量偏低**——ASR 给了 **0.71**，你们 **澄清阈值 0.65**，**等于没拦**。」**

林薇：**「买家以为 **对机器人说话**；系统当成 **已经落字的指令**——**中间少了一站「您说的是哪一个？」**」**

悦衣坊运营补刀：**「SKU 里 **码** 是规格，**把** 是量词——**ASR 不挂商品词典**，**LLM 也猜不回来**。」**

小陈在白板写：

```text
  用户张嘴
      ↓
  【ASR：音频→文本】  ← 本篇主战场
      ↓
  【澄清：不确定就问】 ← 本篇产品闸
      ↓
  【NLU/LLM：意图+槽位】
      ↓
  【下单/建单工具】     ← S9-02 再讲结构化
```

**「S8 教 **派单**；S9 第一句得教 **听写**。** 听错了还 **自动调工具**，等于 **帮用户下错单**。」** 林薇说。

---

### 三、对照：车间里那句「CX-708」

同一会诊，阿梅投 **修小言** 录屏：**澄光制造** **张先生** 在车间对着手机报修：

> 「滤芯型号 **CX-708**，产线 B，压力报警。」

**AI 小言** 回复：**「未找到 **C X 七百零八** 对应备件，请确认型号。」** 张先生骂：**「我说的就是 **CX-708**！」**

语音同学把 **波形 + N-best（候选转写列表）** 拉出来：

```text
Top-1: C X 七百零八        conf 0.68
Top-2: CX-708 滤芯         conf 0.66
Top-3: C X 七零八          conf 0.59
```

小陈：**「**字母数字串** 和 **中文数字** 在 ASR 里天天打架；**备件库** 只有 **CX-708** 这种写法——**Top-2 才是对的**，但系统 **只喂 Top-1 给 LLM**。」**

林薇：**「商小言是 **码/把**；修小言是 **708/七百零八**——**同一类 bug：低置信度 + 无澄清 + 单候选进下游**。」**

张先生那单 **没建工单**——**检索零命中** 后 **AI 小言** 提示 **「请拍照铭牌或手动输入」**，算 **半道拦住**；小周那单 **工具已写库**，**体验更糟**。

---

### 四、双轨方案：先澄清，再落单

林薇提交 **《语音入口 ASR 与澄清双轨方案》**。

**标准 / 规范流程**

**1. ASR 输出契约（进 LLM 前）**

| 字段 | 用途 |
|------|------|
| `transcript_top1` | 最佳转写 |
| `confidence` | 句级或槽位置信度 |
| `nbest[]` | 前 3–5 候选（含分数） |
| `audio_snippet_id` | 可回听片段 |
| `domain_hints` | 租户热词（SKU、备件号、尺码表） |

**2. 澄清触发（产品规则，先于工具）**

| 条件 | 动作 | 禁止 |
|------|------|------|
| `confidence < τ_high`（如 0.85）且含 **数量/尺码/型号槽** | **澄清卡片** | 直接 `updateCart` |
| **N-best 前两名** 编辑距离小且 **语义冲突**（码 vs 把） | **二选一 UI** | 静默选 Top-1 |
| 命中 **高危词**（批量、全部、退款） | **朗读确认**（S9-03 预告） | 单次 ASR 即写库 |
| `confidence ≥ τ_high` 且无冲突槽 | 可进 LLM | — |

**小周案修正**：**「三十八码 / 三十把」** 触发 **澄清卡片**：

```text
您说的是：
  [ A ] 尺码改为 38 码
  [ B ] 数量改为 30 把
  [ 🎤 ] 重说一遍    [ ⌨️ ] 改打字
```

**仅用户点 A 后** 才调 **`updateCartLine(size=38)`**。

**3. 领域热词（租户级）**

- **商小言**：悦衣坊上传 **尺码表、SKU 读音表**（三十八码 → `size_38`）  
- **修小言**：澄光 **备件号白名单** 进 ASR **热词偏置**（CX-708 优先于「七百零八」）

**4. 可观测性**

- 打点：`asr_confidence`、`clarification_shown`、`clarification_choice`、`tool_blocked_by_asr`  
- 商家后台 **真人客服** 可见 **转写 + 候选 + 用户最终选择**——**减少「系统说你确认了」扯皮**

**中小常用方案**

- **统一用云 ASR 默认模型** + **全局澄清阈值 0.80**（宁多问一句）  
- **只澄清两类槽**：**数量**、**尺码/型号**——别的先当普通文本  
- **无 N-best 时**：转写条旁固定 **「不对？点这里改」** 文本框  
- **修小言现场**：澄清失败 **默认落拍照铭牌**（第 17 篇多模态兜底）  
- **先禁「语音直接改数量」**，只开 **改尺码/改地址**——降风险

**何时升级到完整版**

- **直播/车间噪声** 导致 **澄清率 >40%** 仍大量错单；多租户 **热词上千**；需 **自训练 ASR / 流式 partial 澄清**；**语音下单占 GMV 显著** 且客户合同 **要求误下单率门禁**。

---

### 五、灰度一周：多问一句，少赔一单

方案上线后，悦衣坊 **语音改规格** 会话里 **约 18%** 弹出澄清卡——**其中 12%** 用户原话确实是 **码/把** 类易混，**点选后零错单**。

小周那条链路回放：**新策略下工具 不会执行**；他点 **「重说一遍」**，第二次说 **「三八码」**，ASR **0.89**，**直接改尺码成功**。

修小言侧 **张先生 CX-708**：澄清卡展示 **「CX-708 滤芯」** vs **「C X 七百零八」**，他点前者，**备件检索命中**，**未再拍照**。

林薇在 **S9 开篇复盘** 白板写了一句：

**「语音产品第一关不是 **『有多聪明』**，是 **『听写错了敢不敢承认』**——**澄清是产品谦卑，不是 AI 无能。**」**

小陈落库：`asr_nbest`、`clarification_trigger_reason`、`user_disambiguation_choice`、`tool_gate_asr`。阿梅在客户群：**「S9 才刚开始；下一篇 **语音怎么变成订单行**——**结构化落单**。」**

## 概念正解

**语音识别（ASR）** 把 **用户音频** 转成 **文本**；**澄清（Disambiguation）** 是在 **ASR 不确定或候选冲突** 时，**用产品交互**（卡片、点选、重说、改打字）**让用户确认**，**再** 把文本交给 **LLM 与下单/建单工具**。**语音下单** 的错误，大量发生在 **听写层**，不是 **模型「理解力」** 层——**低置信度仍调写库工具**，等于 **把 ASR 的锅甩给 LLM**。

回扣故事：**小周「三十八码」→「三十把」** 因 **阈值过低 + 无码/把澄清** 直接 **`updateCartLine`**；**张先生 CX-708** 因 **只取 Top-1 且数字串歧义** 检索失败。**双轨方案** 用 **N-best、槽位澄清、租户热词、工具闸门、客服可见转写** 把 **「听清」** 做成 **硬门槛**。

在 **S9 · 用户端 AI 语音下单** 中的位置：**开篇扫盲**——全季第一条 **「听错怎么纠」**；**结构化落单、朗读确认、噪声降级** 留待 S9-02～04。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 写 **ASR 输出字段**、**澄清触发表**、**禁止「低置信度调下单工具」** |
| **方案评审** | 问：**阈值谁定？** **N-best 展不展示？** **澄清失败降级路径？** |
| **指标设计** | **`asr_word_error_rate`（抽样）**、**`clarification_rate`**、**`voice_order_error_rate`** |
| **跨团队沟通** | 对语音算法：**要 N-best 不是只要一行字**；对商家：**热词谁维护**；对客服：**转写与候选可回看** |

## 类比锚定

| 你熟悉的 PM 旧经验 | ASR + 澄清 |
|--------------------|------------|
| 搜索框 **拼音联想** 要选第几个 | **N-best 候选** + 用户 **点选** |
| 地址库 **「您指的是朝阳区还是朝阳市」** | **槽位歧义澄清卡** |
| 短信验证码 **输错重发**，不是 **猜对就扣款** | **听写不确定 → 禁止写库** |
| 客服 **复述确认**：「您是说 38 码对吧？」 | **澄清 UI = 产品化复述** |
| 表单 **必填项红框** 拦提交 | **工具闸门** 拦 **低置信度下单** |

---

## 类比边界说明

### A. 概念核心要点

1. **ASR 与 NLU 分层**：**先听写、再理解、再办事**——**跳过澄清 = 把声学错误直接送进钱包**。  
2. **置信度不是装饰**：要有 **产品阈值** 与 **槽位级策略**（数量、型号比「闲聊句」更严）。  
3. **N-best 是 PM 资产**：**不只给算法调参**——**要给用户看见「还可能是什么」**。  
4. **租户热词是运营活**：**SKU、备件号、地名** 靠 **商家/客户维护**，**不是一次性上线**。  
5. **澄清率不是越低越好**：**该问就问**；**压澄清率** 往往 **抬高错单率**。

### B. 类比失效点

| 失效 | 为什么不能照搬 |
|------|----------------|
| **「像输入法，错了用户自己会改」** | **语音下单** 很多用户 **不看灰字转写**，**以为说了就算数** |
| **「澄清一问就烦，全去掉」** | **直播噪声、方言、车间回声** 下 **必问**——**省一句多问一句赔一单** |
| **「ASR 准了就不用澄清」** | **同音异义**（码/把）**与 ASR 准确率正交**——**要规则 + 词典** |
| **「全交给 LLM 猜」** | **写库工具** 需要 **确定性字段**——**猜错成本由用户与商家承担** |

## 本集 Checklist

**标准 / 规范流程**

- [ ] ASR 输出含 **`confidence` + `nbest`**，**不只一行转写**  
- [ ] **低置信度 / 槽位冲突** → **澄清 UI**，**未确认禁止写库工具**  
- [ ] **租户热词** 流程：谁上传、谁审核、何时生效  
- [ ] **商小言 / 修小言** 分 **domain_hints**，**禁止共用一张热词表**  
- [ ] 客服/运营台可回看 **转写、候选、用户点选**  
- [ ] 指标：**澄清率、澄清后改选率、语音错单率**（抽样听音）  
- [ ] 与 **S8 工单边界**：**语音错单投诉** 进线带 **`asr_trace_id`**  

**中小常用方案**

- [ ] 全局澄清阈值 **0.80**；**只澄清数量/尺码/型号**  
- [ ] 转写条旁 **「不对？改打字」** 常驻  
- [ ] 修小言 **检索失败 → 拍照铭牌**  
- [ ] 先灰度 **改尺码**，暂不开 **语音改数量**  
- [ ] **周抽 15 条** 语音会话人工听写对照  

**何时升级到完整版**

- **直播/工业噪声** 场景占比高；**澄清率长期 >35%** 仍 **错单超阈**；需 **流式 partial 澄清、定制 ASR、实时 WER 门禁、与 S9-03 朗读确认联动**。
