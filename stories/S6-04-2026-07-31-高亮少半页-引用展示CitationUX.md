## 寓言故事

### 一、脚注对了，展开却像随机选了一段

澄光把哺乳假版本问题压下去后的周三，工艺部又在飞书群里 @ 了 IT 服务台。

李女士的截图很典型：**AI 小言** 正文三条要点都对——**每日 2 小时、可合并为一次 2 小时、产假期间有效**；脚注 [1] 也工整：

> **来源 [1]**：《澄光制造员工休假管理办法（2025.8 版）》第三章 **§3.2 哺乳假**

她点 [1]，内小言右侧滑出 PDF 预览。高亮区域却让她愣住：黄框从 **「……每日」** 中间开始，上面缺了 **「3.2 哺乳假」** 标题；往下扫，黄框在 **「合并使用」** 上一行戛然而止，**「不得超过 1 次 2 小时」** 落在灰区外。

李女士在工单里写：**「回答我信，脚注标题也对。但展开像 **随机选了一段**——我拿这张截图去人事窗口对质，对方说 **§3.2 明明还有半页条件**，小言只亮了一半。」**

服务台坐席备注：**「非权限、非旧版。用户反馈 **引用跳转/高亮不准**。请星尘看 **脚注展示**。」**

林薇转给值班研发小陈，内部写：**「复现：答案与 chunk 内容一致，**高亮框与章节边界不对齐**。初判体验问题，非 P0 数据；但 HR 王姐说 **再有两起就不敢让员工点脚注了**。」**

---

### 二、库房给的是一块砖，用户要的是一面墙

小陈把李女士那次问答的日志摊开。阿寻命中的块元数据如下：

```text
chunk_id: cg-leave-2025.8-ch-041
char_start: 4821
char_end: 5098
page_pdf: 14
section: §3.2（解析器未单独存标题行）
highlight_sent_to_ui: char 4840–5076   ← 比 chunk 两端各缩进了一截
```

**「模型读的是整块 ch-041。」** 小陈在文档里画框，**「UI 高亮却用了 **更短的子串**——说是怕黄框太长；结果 **切点落在句中**，上下各缺半句。」**

他又补了一条 **应用 A** 的对照：某商小言商家客服办退货，**AI 小言** 引合同 **「第七条 无理由退货」**，买家点脚注跳进商家上传的 PDF 合同，高亮落在 **第六条末尾 + 第七条开头**——买家截图投诉：**「出处写第七条，亮的是六和七的缝。」** 客服在工单里写：**「条款没错，**跳转像撕页**。」**

林薇问：**「所以 Grounding 做了，**展示层又切了一刀**？」**

小陈点头：**「检索块（chunk）≠ 展示引用（citation span）。Chunking 按 **token/字数** 切；PDF 按 **页码坐标** 排；脚注若只存 `chunk_id` 而不存 **页内锚点 + 章节路径**，前端只能 **大致框一块**，用户就觉得 **随机**。」**

---

### 三、三种「对」，只有一种用户认

下午林薇拉王姐、小陈和产品设计同学开了个短会。王姐开门见山：**「员工现在分两派：一派只看正文不信脚注；一派点了脚注对不上就不敢转 HR。」**

林薇在白板上写 **三种「对」**——她说这是 Citation UX 最容易被研发和产品各说各话的地方：

| 谁眼里的「对了」 | 实际意味着什么 | 用户敢不敢点 |
|------------------|----------------|--------------|
| **模型：答案与块语义一致** | 生成时确实读了 ch-041 | **不一定**——用户没看日志 |
| **脚注：章节号写对** | 展示层解析出 `§3.2` | **不一定**——点进去高亮跑偏 |
| **用户：能核对完整条款** | 跳转后 **标题、正文、例外** 一眼对齐 | **敢**——这才是李女士要的 |

设计同学补了一句：**「用户点 [1] 的心理是 **「带我去原文核对」**，不是 **「给我看系统内部第 041 号砖」**。」**

他们归纳 **引用展示** 要同时管好四件事：

1. **锚点（Anchor）**：脚注跳转到 **页码 + 段落/章节 ID**，而不是只有 `chunk_id`。  
2. **高亮跨度（Highlight Span）**：黄框应对齐 **完整句子或条款单元**，**禁止句中起止**；必要时 **向上下扩展到段落边界**。  
3. **预览形态（Preview）**：飞书里优先 **侧栏卡片** 展示引用原文 + 文档名/版本/章节；**「查看全文」** 再跳 PDF。  
4. **一致性（Consistency）**：正文里的数字、脚注标题、高亮正文 **三者可逐字对照**；对不上要 **标「节选」** 或 **展开全文**。

王姐问：**「能不能像 Word 目录一样，点 §3.2 就整节亮出来？」**

林薇：**「可以——那叫 **章节级引用**；至少别 **半句高亮**。」**

### 四、先修展示契约，再谈漂亮卡片

小陈摊开方案——同样分 **标准** 与 **中小默认**。

**标准 / 规范流程（多制度库、要强审计、多格式文档）**

| 能力 | 做什么 |
|------|--------|
| **引用对象模型** | 每条 citation 存：`doc_id、version、page、section_path、char_span、sentence_ids`；与 chunk **多对一或一对一** 可映射 |
| **高亮规则** | **句边界对齐**；跨 chunk 时 **合并展示 span**；PDF 用 **文本层坐标** 反算高亮框，扫描件走 **OCR 框 + 人工校准** |
| **预览分层** | 默认 **引用卡片**（标题 + 版本 + 节选全文）；二级 **PDF 定位**；支持 **复制原文** |
| **多引用排序** | [1][2] 按 **章节顺序** 而非相似度分数排序；重复块 **去重展示** |
| **异常态** | 块已废止 → 脚注灰显 **「来源已更新」** 并链到新版本；权限不足 → **不展示链接**（接 S6-01） |
| **可观测** | **引用点击率、核对失败反馈、高亮偏移工单率**；日志可回放 **「用户点了哪条 citation」** |

**中小常用默认方案（星尘当前可卖）**

- **「块即引用，句边界补齐」**：脚注仍绑 `chunk_id`，但 UI 高亮 **向上下扩到句号/换行**；禁止再 **人为缩短** 高亮串。  
- **卡片优先**：飞书/网页 **侧栏先出 3–8 行原文** + **文档名（版本 · § 章节）**；PDF 跳转作 **次要按钮**。  
- **章节标题必显**：解析器尽量抽出 **§ 号与标题行** 放进卡片头；抽不出则脚注写 **「节选」**。  
- **单库止血**：澄光可对 **《休假管理办法》** 开 **章节级锚点表**（人工维护 20 条），先保高频制度。  
- **可暂缓**：扫描件 OCR 框精修、多文档 **交叉引用图谱**、**视频时间戳引用**——等大客户合同里写了再加。

会上李女士的原题被拿来 **验尸**：把 ch-041 的展示 span 扩到 **完整 §3.2 段落** 后，王姐用手机试了一遍：**「这次像人事窗口打开的那份，不是随机选行。」**

### 五、接近结尾：答对只是及格，敢点才是信任

又过两周，澄光 **「脚注展开不准」** 工单从 **每周三四张** 降到 **零星**。工艺部有人开始在群里贴 **小言截图 + 脚注卡片** 互相答疑——因为 **卡片上的字和人事通知能逐句对上**。

林薇给新同学讲 S6 第四课，把季末白板 **「知识从哪来」** 第三格打勾：

**「ACL 决定 **谁能看见**；Chunking 决定 **每一块是否完整**；版本决定 **是不是今天该执行的那一页**；Citation UX 决定 **用户敢不敢点、点了信不信**。模型 **答对** 只是及格；**出处能核对** 才配写进 HR 通知里的「去问小言」。」**

小陈把英文写在旁边：**Citation UX。** 李女士在回访里写：**「现在点 [1] 先看见一整段 §3.2，再决定要不要翻 PDF——不像以前，高亮 **少半页**，我还得自己猜下面是不是还有。」**

林薇在白板第四行旁留了下一格空笔迹：**「谁有权把文档上架、下架、标废止」**——那是 **知识运营后台** 的事；脚注再准，若 **没人运营上架流程**，库还是会乱。

## 概念正解

**引用展示（Citation UX）** 指：在 RAG 或 Grounding 场景下，**如何把系统内部的检索块（chunk）翻译成终端用户可理解、可点击、可核对的引用体验**——包括脚注文案、预览卡片、PDF 跳转位置、高亮范围、版本与章节信息，以及异常态（节选、已更新、无权限）的展示。它解决的是 **「答案看起来对，但用户一点出处就对不上」**：根因常不是模型胡说，而是 **chunk 边界 ≠ 条款边界**、**高亮 span 被二次截断**、**仅有 chunk_id 没有页码/章节锚点**，或 **预览层与 PDF 层各画各的框**。典型做法包括：**引用对象模型（文档 + 版本 + 章节 + 句级 span）**、**句/段边界对齐的高亮**、**侧栏引用卡片优先于裸跳 PDF**、**多引用排序与去重**，以及 **引用点击与「核对失败」类反馈的可观测**。

回扣故事：李女士 **§3.2 标题对、高亮少半页**，是 **展示 span 短于完整条款且未句边界对齐**；商小言合同 **第七条亮到第六条缝**，是 **页码锚点与章节解析不准**；澄光 **块即引用 + 句边界补齐 + 卡片优先** 是中小可交付路径。

在 **S6 · 知识可运营、权限可审计** 中的位置：本篇锚定 **「知识从哪来」** 的第三层——**用户能否核对**；承接 S6-02 **Chunking 切在哪**、S6-03 **脚注版本号**；为后续 **知识运营后台（谁上架/谁下架）**、**检索可观测性** 打基础——运营需要知道 **用户点的引用是否经常对不上**。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 定义 **citation 数据契约**（页码、章节、span、版本）；写清 **卡片预览 vs PDF 跳转** 的默认路径与 **「节选」** 规则 |
| **方案评审** | 问：**跨 chunk 引用如何合并高亮？** 扫描件 PDF 是否 **降级为卡片-only**？废止版本脚注 **链到哪里**？ |
| **指标设计** | **引用点击率**、**引用后「仍要人工确认」率**、**高亮偏移工单率**、**卡片与正文数字不一致率** |
| **跨团队沟通** | 对设计：**「用户要核对，不是欣赏黄框」**；对研发：**「别在 UI 层二次截断 chunk」**；对运营：**「章节标题抽不出要标节选，别装完整」** |

## 类比锚定

**核心类比：论文参考文献——正文里写 **[1]**，读者期望翻到 **准确页码、完整段落** 核对；若注脚写「第三章」却高亮到 **第二章末尾**，再正确的结论也没人敢引用。**

| 你熟悉的 PM 经验 | Citation UX 要素 |
|------------------|------------------|
| 帮助中心 **「复制锚链接」跳到标题下全文** | **章节/标题级锚点 + 完整段落高亮** |
| 电商 **订单详情「查看物流」直达节点，而非首页** | **脚注深链到条款/页，而非文档封面** |
| 评论 **@某人 高亮整条消息，不是半个 emoji** | **句边界对齐，禁止半句起止** |
| 搜索结果 **摘要下方灰色来源域名** | **卡片展示：文档名 + 版本 + 章节路径** |
| 工单 **附件预览优先，下载次之** | **侧栏引用卡片优先，PDF 全屏次要** |

## 类比边界说明

### A. 概念核心要点

1. **Grounding ≠ Citation UX**——模型有据可依是 **后端**；用户能核对是 **前端与契约**。  
2. **chunk 是检索单位，citation 是展示单位**——二者可映射，但 **不应默认相等**。  
3. **高亮要对齐 **人能读的边界****（句、段、款），而不是 **向量块边界**。  
4. **预览分层**：先给 **可读的引用卡片**，再提供 **全文定位**；降低 **PDF 坐标系** 直接暴露给用户。  
5. **与版本、ACL 联动**——脚注须带 **版本号**（S6-03）；无权限 **不展示可点链接**（S6-01）；废止来源要有 **更新提示**。

### B. 类比失效点

| 类比说法 | 失效点 | 更准确的理解 |
|----------|--------|--------------|
| 「像浏览器 Ctrl+F 搜关键词」 | 关键词命中 **第一处** 未必是 **条款完整意群**；多命中会 **乱跳** | 用 **结构化章节锚点**，而非裸字符串搜索 |
| 「高亮越长越好」 | 过长会 **淹没重点**、跨节混淆；用户仍要 **看章节标题** | **条款单元对齐** + 卡片头 **显式 § 路径** |
| 「PDF 页码永远准」 | 重新排版、手机阅读、扫描件 **页码与文本层错位** | 准备 **页码 + 文本 span 双锚点**；扫描件 **降级策略** |
| 「脚注 [1] 一个数字就够」 | 多段依据需要 **[1][2]** 且要 **去重、排序**；否则像 **乱序拼凑** | **多引用模型 + 章节序排序** |

## 本集 Checklist

**标准 / 规范流程**

- [ ] **Citation 对象模型**：`doc_id、version、page、section_path、span`；与 chunk **可映射、可一对多**  
- [ ] 高亮 **句/段/款边界对齐**；跨 chunk **合并 span**；扫描件有 **降级策略**  
- [ ] **卡片预览默认** + PDF 深链次要；支持 **复制引用原文**  
- [ ] 多引用 **[1][2] 按章节排序**、重复块 **去重**  
- [ ] 废止/无权限 **异常态文案**；指标：**点击率、核对失败率、偏移工单率**  

**中小常用方案**

- [ ] 脚注绑 chunk，但 UI **句边界补齐**、**禁止二次截断**  
- [ ] 卡片展示 **文档名 + 版本 + § + 节选全文**；抽不出章节则标 **「节选」**  
- [ ] 高频制度 **人工章节锚点表** 止血；商小言合同类 **优先修第七条类跳转**  

**何时升级到完整版**

- 客户 **监管审计** 要求 **引用可回放**；**扫描件/OCR** 占比高；**多文档交叉引用** 频繁；或 **「脚注对不上」** 类工单 **持续高于阈值** 影响 HR/法务敢不敢推内小言。

## 落地细节答疑（读者补课）

故事第四章那张「中小默认方案」表压得很紧，几条容易看懂却不知道「到底怎么做」。这里把三条常被追问的展开。

### 一、三条中小方案分别在做什么

| 方案 | 一句话 | 入库时做什么 | 展示时做什么 |
|------|--------|--------------|--------------|
| **章节标题必显** | 卡片头至少写出「第几节叫什么」 | 解析器抽标题行，chunk 存 `section_path`（如 `第三章/§3.2 哺乳假`） | 读 `section_path` 显示；抽不出就标 **「节选」**，不假装完整 |
| **单库止血** | 只对高频制度人工钉准跳转 | 运营对《休假管理办法》维护一张 20 条 **章节锚点表**（章节→页/段） | 命中该文档时按表跳转、按段高亮，而非 UI 临时猜黄框 |
| **可暂缓** | 难而贵的引用能力先不做 | —— | 扫描件 OCR 精修、跨文档图谱、视频时间戳先列为范围外 |

关键心态：**抽不出章节时「诚实标节选」比「假装完整」更不容易被 HR/法务打回。**

### 二、人工锚点表不是很麻烦、文档一改就废吗？

是——所以它叫 **止血**，不是长期骨架。控住麻烦靠四条纪律，而不是「永远手搓全库」：

1. **只保 Top 文档**：仅高频被问的那几份；其余文档继续走「块 + 句边界 + 抽不出标节选」的自动路径。
2. **锚点表绑 `doc_version`**：一版一套；制度升版时旧表 **失效或重标**，禁止 silently 沿用旧页码（呼应 S6-03 版本延迟）。
3. **挂进上架流程**：制度改版上架 checklist 增一项——**「锚点表已核对 / 或本版降级为仅卡片+节选」**；把「文档一动」变成可预期的运营动作。
4. **设退出条件**：当解析器对「带正式目录的 Word/PDF」够准，就把该文档 **从人工表摘掉**，只给扫描件/变态排版留人工。

改动分流：只改措辞→抽检几条即可；增删章节、大改结构→必须重标，或先关掉章节跳转只出卡片全文。若客诉本就不多、解析已稳，这条甚至可以不建——它是 **可选止血**，不是必做项。

### 三、「多文档汇总引用」不就是交叉引用吗？

不是同一件事，别混。

| | 普通多文档回答（多数产品已有） | 交叉引用图谱（可暂缓的重活） |
|--|-------------------------------|------------------------------|
| 触发 | 检索 TopK 里 chunk 恰好来自 docA、docB | 文档正文里写了「详见《薪酬办法》§5」这种 **显式指向** |
| 例子 | 问年假：命中《休假办法》+《考勤细则》，`[1][2]` 各引一段 | 《休假办法》让你去看《薪酬办法》某条，系统能顺着跳过去 |
| 数据 | 各 citation 绑自己的 chunk | 额外维护 **文档间的边**：`休假§3.2 --参见--> 薪酬§5` |
| 难度 | 标准 RAG，现在就该有 | 要解析「见××」、建关系图、多跳召回、双栏预览 |

普通多文档引用怎么跑：

```text
提问 → 检索（可跨多篇）→ 多个 chunk 塞进 Prompt
     → 模型综合作答 → 句末挂 [1][2]，各指各自 chunk
```

S6-04 要先保证的，就是 **每个 [1][2] 自己跳得准、高亮对齐**——哪怕它们来自两篇不同文档。这已经覆盖大量问答。

交叉引用图谱是在此之上再加三步（所以贵、所以暂缓）：

1. **建边（离线）**：解析「参见/详见/见附件」→ 抽成图边 `from→to`。
2. **联合检索（在线）**：命中 A 带出链接时，**追加召回 B 的目标条款**（多跳），而不是靠语义碰巧也捞到 B。
3. **双文档预览（展示）**：点脚注时左右并排「当前段 + 被引段」，或先提示「本条引用了另一份文件」再跳。

一句话：**回答里引用两篇 ≠ 文档之间互相指着。** 前者是标准能力先做好；后者是制度级关系网，等客户合同真要「点参见必须跳到另一本」再上。
