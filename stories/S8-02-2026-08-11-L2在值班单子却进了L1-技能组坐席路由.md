> 今日概念在知识树中的位置：S8-01 把 **进线意图** 贴对了——**RUN-052** 不再被当成 **商小言退款**。**澄光制造** 的 **张先生** 等来的却是 **L1 坐席小方** 的 **「我帮您查一下，稍等转同事」**——**转了三手，四十分钟**；Meanwhile **修小言 L2 运营** 阿凯 **明明在线**，屏上 **RUN 队列却是 0**。今天拆 **技能组 / 坐席路由**：**意图标签之后，这单该进哪个技能组、哪个坐席接**——看 **技能、权限、负载、租户对口**，**不是** **谁空闲谁接**、也 **不是** **全组抢单**。

### 场景白板（读故事前 30 秒）

- **本集入口**：**小言平台工单台**——S8-01 已给进线打上 **`intent_id`**；本篇讲 **标签之后怎么派给人**。
- **技能组（Skill Group）**：白话：坐席按 **能办什么事** 分的队——例如 **修小言 L2 运营**（能查仓库/拣货状态）、**商小言资金组**（能操作退款通道）、**内小言 IT 对口**（能改 ACL/知识上架）。
- **坐席路由（Agent Routing）**：白话：**工单入队后**，系统按 **意图 → 技能组映射 + 组内负载 + 坐席状态** 决定 **派给谁**；支持 **溢出、回退、粘性指派**（同一客户尽量同一对口人）。
- **本集冲突**：**意图对了**，但路由策略仍是 **全组轮询**；**RUN-052** 进了 **L1 通用组**，**L2 有权限查仓却接不到单**——**张先生** 听见 **「您稍等，我转同事」** 第三次时挂断。

## 寓言故事

### 一、标签对了，开口却还是「我帮您转一下」

S8-01 灰度上线一周，**真人支持** 坐席小方觉得 **轻松了一点**——屏上 **第一行** 终于不是「用户催处理」，而是：

> **【修小言 · run 接管 · 拣货状态未知】** `intent_b_run_pick_unknown` · 置信度 0.98

她点开 **澄光制造** **张先生** 的 **RUN-052**，话术模板也对了：**不问订单号、不问退款**。

但 **第三句** 就卡住：

**小方**：「张工，我这边 **看不到仓库拣货状态**，需要 **转给有权限的同事**……您 **稍等**。」

张先生：**「上周你们就说 **分类改好了**。现在 **标签对了，人还是不对**？」**

小方 **转了两次**：先 **@ 修小言 L1 邻座**——邻座 **只会查工单状态**，**PK 单号** 仍空白；再 **@ 大群**「谁有 WMS 只读？」——**修小言 L2 运营阿凯** 在隔壁工位 **刷手机**，他的屏上 **「修小言-run 队列：0」**。

四十分钟后，阿凯 **手动搜 run_id** 才接上：**「SHP-1052-A 已在拣货台，PK-052。」** 和 S7-04 结局一样，但 **多绕了三手**。

同周 **商小言** 一笔 **`intent_a_refund_dispute`** 被 **L1 小方** 接到——她 **按模板开口对了**，却 **点不了退款查询按钮**（**资金组** 才有 **支付通道只读**）；**真退款单** 在 **L1 池里泡了六小时**，商家在群里 **@ 阿梅**。

老吴在周会上拍桌：**「S8-01 解决 **听错第一句**；今天解决 **接错第一个人**。」**

---

### 二、会诊：不是加 L2 人手，是改路由表

阿梅汇总客户侧跟进 → 林薇 **初判 P2（SLA 体验，未直接资损）** → 拉 **老吴、小陈、商小言运营、修小言值班阿凯** 会诊。

小陈把 **RUN-052** 的路由 trace 投屏：

```text
intent_id: intent_b_run_pick_unknown  ✓（S8-01 已命中）
routing_policy: round_robin_all_agents  ← 问题在这
assigned_group: support_l1_general
assigned_agent: 小方（L1，无 wms_read）
skill_required: [wms_read, xiuxiaoyan_l2]  ← 字段有，路由没用
fallback: manual @大群
```

林薇在白板上补 **S8-01 那两层** 的下一格：

```text
         用户 / 租户进线
              ↓
    ① 进线意图分类（S8-01）  →  intent_id
              ↓
    ② 技能组 / 坐席路由（本篇）  →  skill_group + agent_id
              ↓
    ③ 分派解释与改派审计（S8-03）
    ④ 模型路由（老何）——对话层，不进工单路由表
```

**「意图是 **『这是什么单』**；技能组是 **『谁有资格接』**。** 小方 **标签读对了**，**路由表却把她当万能入口**——**RUN 单要 `wms_read`，她 profile 里没有，系统 **不该派给她**。」**

阿凯举手：**「我 **L2 值班表** 写了 **周一三五全天 run 队列**；**路由没读排班**，只读 **谁在线**——**在线的 L1 比我先抢到铃**。」**

商小言运营补刀：**「**退款纠纷** 和 **发货慢咨询** 在 S8-01 已拆开意图；**路由仍进同一 L1 池**——**资金组三个人**，**屏上永远 0 单**。」**

会诊结论：**建意图 → 技能组映射；组内按技能 + 负载派单；无可用坐席走溢出策略，别静默掉进 L1。**

---

### 三、路由表：意图指路，技能组守门

林薇提交 **《小言平台技能组与坐席路由双轨方案》**。

**标准 / 规范流程（多技能组、可审计、可排班）**

**1. 技能组定义（产品 + 运营维护）**

| 技能组 ID | 能办什么事 | 必备技能标签 | 典型坐席 |
|-----------|------------|--------------|----------|
| `sg_xxy_run_l2` | 修小言 run 接管、查仓/拣货 | `wms_read`, `run_handoff` | 阿凯等 L2 运营 |
| `sg_sxy_funds` | 商小言退款、支付通道查询 | `payment_read`, `refund_escalate` | 资金组 |
| `sg_sxy_l1` | 商小言咨询、非资金类 | `shangxiaoyan_l1` | 小方等 L1 |
| `sg_nxy_it` | 内小言 ACL、知识上架 | `acl_ops`, `kb_publish` | IT 对口 + 林薇会诊队列 |
| `sg_escalation_eng` | 产研值班、P0/P1 升级 | `oncall_eng` | 小陈轮值 |

**2. 意图 → 技能组映射（路由表核心）**

| intent_id | 主技能组 | 溢出组（主组无人/超时） | SLA 首响 |
|-----------|----------|-------------------------|----------|
| `intent_b_run_pick_unknown` | `sg_xxy_run_l2` | `sg_escalation_eng`（15 min） | 10 min |
| `intent_a_refund_dispute` | `sg_sxy_funds` | `sg_sxy_l1`（仅收集材料，不承诺退款） | 30 min |
| `intent_c_acl_publish` | `sg_nxy_it` | `sg_escalation_eng`（合规） | 4 h |

**3. 组内坐席选择（不是抢单）**

| 策略 | 说明 | RUN-052 应有行为 |
|------|------|------------------|
| **技能硬过滤** | 坐席 **缺 `wms_read` 不进候选** | 小方 **根本不在候选池** |
| **负载均衡** | 组内 **当前在手单量最少** 优先 | 阿凯 vs 另一 L2 **均分** |
| **排班窗口** | 读 **值班表 + 技能组绑定** | 周一阿凯 **只接 run 组** |
| **粘性指派（可选）** | 同租户 **30 天内优先上次对口人** | 澄光 **优先阿凯**（熟悉交接包） |
| **溢出** | 主组 **全离线或超时** → 溢出组 + **横幅提示**「非对口组代为受理」 | 避免 **静默转 L1** |

**4. 坐席屏必显（派单可解释）**

```text
派单原因：intent_b_run_pick_unknown → sg_xxy_run_l2
选中坐席：阿凯（技能命中 wms_read + run_handoff，负载 2/8）
若改派：必填原因 → S8-03 审计
```

**中小常用方案（编制有限时的默认路径）**

- **按意图粗分 3 组**：**修小言-run 专组**、**商小言-资金组**、**其余 L1**——**不建 8 个技能组**。
- **路由规则写死映射表**（Excel → 配置台）：`intent_id` **一行一个主组**，**暂不做负载算法**，组内 **round_robin**。
- **L2 坐席手动「签入」run 队列**——**土办法**：不签入 **不接 run 单**；比 **全组抢铃** 强。
- **资金类按钮权限与技能组绑定**：**没进资金组** 的坐席 **UI 上隐藏退款查询**——**从界面防误接**。
- **溢出只一条规则**：主组 **15 分钟无人认领** → **飞书 @ 值班长**，**不自动塞给 L1**。

**何时升级到完整版**

- 技能组 **>5**、**跨租户粘性**、**多班次排班**；需 **动态负载 + 溢出链 + 改派审计（S8-03）**；要与 **排队 SLA 看板** 联动。

### 四、铃响在阿凯桌上，第一句就能报 PK

双轨灰度第二天，**RUN-052** 同类进线 **不再进小方池**：

```text
intent: intent_b_run_pick_unknown
route: sg_xxy_run_l2
agent: 阿凯（skill match, load 1/8, shift on）
elapsed_to_assign: 4s
```

阿凯耳机 **一声响**，屏上 **交接包 + WMS 只读入口** 同屏——**十五秒** 带回 **PK-052**。回电张先生：

**「张工，**RUN-052**，拣货 **PK-052**，状态 **拣货中**——**不用转同事**，我这边 **权限够查**。」**

同周 **商小言退款** 直达 **资金组**，**L1 小方** 池里 **只剩咨询类**；她开玩笑说：**「终于不用假装我能退款了。」**

老吴看板：**错组率**（意图对但技能组错）从 **31%** 降到 **6%**；剩下主要是 **溢出代受理** 未在开口第一句 **说明「非对口组」**——留给 **S8-03 改派话术**。

林薇复盘一句话：

**「分类回答 **『这是什么单』**；路由回答 **『谁该接』**——**标签对了却进 L1，等于分类白做。**」**

小陈落库字段：**`skill_group_id` · `routing_policy_version` · `assigned_agent_id` · `overflow_flag` · `route_reason`.** 阿梅补：**「技能组是 **编制表**，不是 **组织架构图**——**几个人也能先画三张表**。」**

## 概念正解

**技能组 / 坐席路由（Skill-based Routing）** 指：在 **进线意图已分类** 之后，工单系统根据 **「这单需要什么能力」**（技能标签、工具权限、产品线经验）映射到 **技能组**，再在组内按 **坐席状态、负载、排班、粘性规则** 选择 **具体接单人**；主组 **不可用或超时** 时走 **可配置的溢出链**——**不是** 全队列 **轮询抢单**，也 **不是** **谁在线谁接**。

回扣故事：**RUN-052** 意图已正确，但 **路由策略仍是 round_robin_all**，**小方**（L1、无 `wms_read`）被派单后 **只能转同事**；**阿凯**（L2 在线）**run 队列显示 0**；**商小言退款** 进 L1 **点不了资金查询**。双轨方案用 **技能组定义、意图→组映射、技能硬过滤、排班签入、溢出与坐席屏派单原因** 把 **「分给谁」** 产品化；**路由对了，S8-01 的分类和 S7-04 的交接包才一次接到底**。

在 **S8 · 平台端 AI 分派工单** 中的位置：**基础偏应用**——全季五条里的 **「分给谁」**；承接 S8-01 **「像哪一类」**，为 S8-03 **「分错了怎么改、怎么审计」** 铺路。

在 **AI 产品岗** 的典型场景：

| 场景 | 具体例子 |
|------|----------|
| **需求文档** | 写 **技能组清单、技能标签、意图→组映射表、组内选择策略、溢出链、排班绑定** |
| **方案评审** | 问：**run 单是否硬过滤 `wms_read`？** **退款是否必须进资金组？** **L1 能否代受理、开口怎么说？** |
| **指标设计** | **错组率、组内首响时长、溢出占比、改派率、一次解决率（按技能组）** |
| **跨团队沟通** | 对客服：**签入哪组接哪类单**；对研发：**路由与权限系统同源**；对运营：**技能组 = 编制不是部门名** |

## 类比锚定

| 你熟悉的 PM 旧经验 | 技能组 / 坐席路由 |
|--------------------|-------------------|
| 客服 **「售前 / 售后 / 投诉专席」** 分机号不同 | **技能组** = **按能力分队列** |
| 工单 **「指派给会 Java 的同学」** | **技能标签硬过滤** 候选坐席 |
| 餐厅 **「川菜师傅只做川菜档」** | **intent → 技能组** 映射 |
| 滴滴 **「就近 + 车型匹配」** 派单 | **负载 + 技能** 组内选择 |
| CRM **「客户专属客户经理」** | **粘性指派**（同租户对口人） |

---

## 类比边界说明

### A. 概念核心要点

1. **路由承接分类**：**`intent_id` 是输入**；**`skill_group_id` + `agent_id` 是输出**——两步 **不同配置表**。  
2. **技能组 ≠ 组织架构**：**三个人** 也可划 **run 专组 + 资金组 + L1**；**按能力不按职级**。  
3. **权限与路由同源**：坐席 **缺工具权限** 则 **不应出现在候选池**——**别只靠 UI 藏按钮**。  
4. **溢出要有声量**：代受理 **必须标记 `overflow_flag`**，**开口说明非对口**——**静默掉进 L1 = 错组**。  
5. **排班是路由输入**：**在线 ≠ 可接该类单**；**签入 / 值班表** 要进路由。

### B. 类比失效点

| 失效 | 为什么不能照搬 |
|------|----------------|
| **「和 IVR 转人工一样」** | 很多单是 **系统转接**，用户 **没选技能**；靠 **意图 + 映射表** |
| **「资深坐席都能接」** | **统一队列** 下 **修小言 / 商小言 工具权限不同**；**资深 L1 也查不了仓** |
| **「抢单提高积极性」** | **抢单** → **简单单被抢、难单积压**；**RUN/资金** 宜 **派单** |
| **「一个模型端到端派给人」** | **可解释路由表 + 审计** 优先；模型可做 **负载预测** 但 **映射表产品定** |

## 本集 Checklist

**标准 / 规范流程**

- [ ] **技能组清单** + **技能标签** 与 **权限系统** 对齐  
- [ ] **意图 → 主技能组 → 溢出链** 映射表 + **发版流程**  
- [ ] 组内策略：**技能硬过滤、负载、排班、粘性（可选）**  
- [ ] 坐席 **签入 / 签出** 与 **技能组** 绑定  
- [ ] 派单 **可解释字段**：`route_reason` · `routing_policy_version`  
- [ ] **溢出单** 标记 + **开口话术**（非对口代受理）  
- [ ] 指标：**错组率、组内首响、溢出占比、一次解决率**  
- [ ] 与 **S8-03 改派** 字段预留

**中小常用方案**

- [ ] **三粗组**：run 专组 / 资金组 / L1 其余

- [ ] **资金按钮** 仅资金组可见

**何时升级到完整版**

- 技能组增多、**多班次排班**、**租户粘性**；需 **动态负载 + 溢出链 + S8-03 改派审计 + SLA 看板**。
