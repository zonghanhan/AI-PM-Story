> 今日概念在知识树中的位置：小言已经会 **查手册（RAG）**、会 **跑腿（Agent）**、会 **换口音片（LoRA）**——但用户一句「怎么变冷淡了」，团队却 **吵不出结论**。今天这篇讲 **Evaluation / 评测体系**：没有尺子，就不知道改对了没有、变差了怪谁、该不该上线。它和后面第 18 篇护栏分工不同——**评测管「好不好、退没退步」；护栏管「能不能说、动作能不能自动做」**。

### 场景白板（读故事前 30 秒）

- **本集入口**：小言平台的 **发版/灰度门禁**；客诉发生在 **商小言** 续费挽留会话。
- **谁在吵**：客成带用户截图进晨会 → PM 林薇初判「缺尺子」→ 拉测试/算法/知识库会诊；**不是**销售拍桌子定回滚。
- **双轨提醒**：故事里会出现「两百题 + CI + A/B」的**完整版**；同时写清 **10 人团队下周就能开干的中小默认路径**——先救命集，再谈流水线。
- **读完应能回答**：金标从哪来、离线怎么比、自动分防什么、没流量 A/B 时看什么、什么时候才升级到完整评测编制。

## 寓言故事

### 一、用户说「变冷淡了」，会议室里七张嘴

周一晨会，**客户成功**把一张截图投到大屏——这是客成从工单里捞的 **P2 体验投诉**，不是销售自行立案。

用户原话：「你们小言 **怎么变冷淡了**？上周还会主动问我要不要预约演示，这周像 **念说明书**。」

销售老赵拍桌：「肯定是 **销售片 LoRA** 被谁卸了！立刻回滚！」

运维大刘摇头：「我查过配置， **销售路由没动**。」

算法小陈说：「也可能是 **基座 v2 小版本** 上周静默升级了。」

知识库负责人阿寻举手：「或者 **检索没捞到** 销售话术手册——用户问的是续费场景，手册里那段 **共情话术** 在第三章。」

林薇没有立刻拍板回滚。她在白板中央画了一个问号：

```
变冷淡了 → 怪谁？
  基座？ LoRA？ RAG？ Prompt？ 还是用户记错了？
```

老周只问一句：「你们 **怎么证明** 现在比上周差？差 **多少**？差在 **哪类问题**？」

有人小声说：「用户反馈算吗？」

林薇答：「算 **信号**，不够 **尺子**——今天一个用户说冷淡，明天三个用户说 **太热情像推销**，我们照谁的改？回滚申请我可以提，但得先有 **可复现的对比**，别用会议室手感替发版决策。」

---

### 二、「我觉得还行」救不了发版

当天下午，林薇拉了个 **临时评审**：要不要 **紧急回滚** 上周的配置？

测试同学小李现场 **随手问了小言十个问题**——在会议室里念出来，大家点头：「嗯，语气还行啊。」

法务陈姐皱眉：「你问的 **都是简单 FAQ**，用户截图里是 **续费挽留**——场景不一样。」

小陈补刀：「而且 **同一条问题**，多跑两次，答案 **措辞会变**——大模型不是 deterministic 按钮，你 **手感试两下** 不等于 **质量稳定**。」

老赵急了：「那到底上不上线？业务等不起！」

林薇意识到：他们缺的不是 **再吵一轮**，而是一套 **可重复、可对比、可分工** 的判法——像传统软件里的 **回归测试 + 验收标准**，只是 AI 产品的「对不对」不再只有 **0 和 1**，还有 **好不好、稳不稳、敢不敢给客户看**。

她没有当场批准回滚，而是看向客成：「今晚先把近一周 **续费、挽留** 相关工单脱敏捞出来，先凑 **三十来条** 真问法就行——别追求完美题库。」又对小李说：「明天你拿这三十条，让 **上周线上那包** 和 **现在这包** 各答一遍，每题跑两次；你跟客成一人打分，续费语气如果明显掉一截，或者新冒出两道事实硬伤，我们再谈回滚。没触线，就别全家桶撤。」

编制就十来个人，大刘有点懵：「那网上说的两百题、CI、A/B……」

「那些是以后的事。」林薇在笔记本上写下三个词，还没解释，先贴在白板角上：

```
金标题
人工评
自动分
```

「这周先把这三十题跑通。尺子可以先买小号的——总好过继续用会议室手感发版。」

---

### 三、质检科的第一张卷子（完整版 vs 先跑起来）


次周，林薇拉上小陈、小李、阿寻做 **卷子**——内部叫 **「金标集」**（Golden Set：固定题 + 标准答案或评分 rubric）。

大刘问：「网上都写要 **两百题进 CI**，我们做不做得到？」

林薇在白板画了两列：

| | **中小默认（本周就能干）** | **标准完整版（编制够再上）** |
|--|---------------------------|------------------------------|
| 题量 | **30–50 题「救命集」**：续费/报价/拒答/称谓各一撮 | **150–300 题**，按线上意图分布抽样 |
| 谁来标 | **PM + 客成 + 测试** 轮流标，双人交叉抽 20% | 标注同学 / 外包 + 质检抽检 |
| 怎么跑 | **飞书多维表 / 表格**：左列问法，右列两版答案与分数 | 脚本或云厂商评测任务，候选 vs 基线一键跑 |
| 自动分 | 先做一个 **禁词表 +「是否带手册引用」勾选** | 引用命中率、拒答率等进 **CI/发版脚本** |
| 在线 | **无正规 A/B** 时：看续费标签工单量、人工接手率、客成周反馈 | **灰度 5%–10%** + 核心指标看板 |
| 升级触发 | 对外公网放大、强监管客户、周客诉 ≥N、同时多人改 Prompt/知识库 | 固定编制后默认走完整流水线 |

**第一步：选题要像真用户。**

他们先落地 **中小默认**：从工单脱敏抽出 **40 条**（续费 15、合同 10、故障 8、称谓/拒答 7）。小李说：「上次会议室十个 FAQ，在这 40 条里几乎撞不上——难怪都觉得还行。」

完整版仍规划 **两百条**按场景分层，但林薇写进备忘录：**「200 题是季度目标，不是本周门禁前提。」**

**第二步：每题写清「什么叫过」。**

续费场景 rubric（可直接抄进表格）：

| 维度 | 及格（≥4/5） | 直接不及格（任一条） |
|------|--------------|----------------------|
| 事实 | 价格/政策与现行手册一致，能指出依据段落 | **编造优惠、折扣、赠送** |
| 语气 | 先承认续费压力，再给选项；不嘲讽 | 一上来 **硬推销/恐吓断服** |
| 合规 | 无「一定续上」「保证涨价」等绝对化 | 出现绝对化承诺或竞品贬损 |
| 可执行 | 给出预约演示 / 工单 / 自助链接之一 | 只空洞安慰，**无下一步** |

陈姐补了一句：「两人打分差 ≥2 分，必须当面仲裁——**不能平均掉了事**。」

**第三步：固定「考条件」。**

同一张卷子写明：**基座版本、LoRA 片、知识库索引版本、Prompt 文档哈希**。缺一项，对比作废。

阿寻问：「40 条标完要多久？」

林薇答：「两人半天。**首轮贵，后面省**——没有首轮，你们永远在周一晨会口头复试。」

---

### 四、三把尺子，量出三种「差」

**第一把尺：离线评测（Offline Eval）——发版前的模拟考。**

小李用表格跑完「上周线上 vs 本周候选」：

| 场景 | 上周线上 | 本周候选 | 变化 |
|------|----------|----------|------|
| 续费挽留 | 语气均分 4.2/5 | **3.1/5** | **掉 1.1，触线** |
| 合同条款 | 事实通过 9/10 | 9/10 | 持平 |
| 白标称谓 | 7/7 | 7/7 | 持平 |

续费 15 题里，有 **4 题** 候选版 **没引到共情段落**，读起来像说明书。

顺藤摸瓜：候选版 **知识库索引重建** 时，销售手册 **分块切碎**，共情话术经常进不了 Top3——**阿寻的锅，不是 LoRA**。

**中小执行清单（可照抄）：**

1. 导出两版答案到同一表 → 按 rubric 打分（约 2 小时）。  
2. 只盯 **预设红线**：续费均分掉 ≥0.5 **或** 事实不及格新增 ≥2 题。  
3. 触线则开 **定向缺陷单**（检索分块），**禁止**「先把 LoRA 卸了再说」。

**第二把尺：自动指标（Automated Metrics）——便宜、可频繁跑的阅卷助手。**

小陈先上了中小也能做的两刀，再谈 CI：

- **禁词/绝对化**：正则扫「一定」「保证」「最优惠」（表驱动，半小时能写）。  
- **引用勾选**：答案是否出现手册标题或文档 ID（人工勾或简单字符串匹配）。  

完整版再加：**引用命中率**（与检索 TopK 对齐）、**该拒未拒率**，并挂进发版前脚本——**自动分守门，不独断语气好坏**。

**第三把尺：在线评测（Online Eval）——上线后的真实大考。**

编制够时：林薇让数据同学做 **A/B**——5% 候选 / 95% 线上，看 **人工接手率、会话满意度、续费标签升级率**；合同/报价加 **人工抽检**。

编制不够时，她写了 **「穷人版在线评测」**：

- 客成每周五抽 **续费会话 10 条**（PM 双人看）。  
- 盯工单里 **「冷淡/推销/答非所问」** 标签周环比。  
- 人工接手率按意图过滤，不看全局一个数。  

第三天，完整链路里续费 **接手率略升**，与离线触线同向。林薇拍板：**修索引分块，暂不升级基座，不动销售片**。

老周总结：「要是没有卷子，你们大概率 **先回滚 LoRA**，真正问题却留在库里。」

---

### 五、尺子要维护，不是做一次就挂墙上

一个月后，「三把尺子」写进了 **发版门禁**。但新坑也来了——林薇一本本记进复盘。

先是产品上了 **新套餐**，金标集还在考 **旧价格**。自动分一片绿灯，上线第二天客成又被骂「报价瞎说」。林薇在群里只回一句：「下次改价目，**连带改卷子**——哪怕先改那五道相关题也行，别让尺子自己骗自己。」

后来有人提议：「卷子能不能出简单点，通过率好看一点？」像期末考只考第一章。林薇摇头：「卷子得像真实工单长什么样。通过率是考完才出来的数，不是我们要刷的 KPI。」

再后来，禁词表、引用勾选全绿，陈姐抽了十条约会/报价会话，照样打回三条语气问题。小陈有点挫败。林薇拍拍表格：「机器擅长抓 **明着越界**；**得体不体面**，还是得人看。自动分守门就好，别让它当法官。」

最冤的一次：对比报告忘了写 **Prompt 昨晚有个小改**，全组折腾两天怀疑 LoRA 退化。大刘后来在模板顶上加了四格必填——基座、片、知识库、Prompt——缺一格就不许开对比会。

也有人问：什么时候才上两百题、CI、正经 A/B？林薇没有念条款，只讲最近的日子：「等商小言真对公网放大、或者来了强监管客户；等续费客诉连着两周往上窜；等能改 Prompt 和知识库的人多到互相踩脚、一周发好几版——那时候再抢编制上流水线。现在这四十题救命集，先别丢。」

小陈在文档里给这套东西起了名：**Evaluation Pipeline（评测流水线）**——从 **金标集维护 → 离线对比 → 自动门禁 → 灰度或周抽检 → 复盘** 一条龙。他又补了一句：「流水线可以先单车道。」

林薇跟新人说：「**Prompt、RAG、LoRA、Agent** 都是 **杠杆**；**评测** 是 **天平**。杠杆可以换，**没有天平，你不知道换对了没有**——天平也可以先买小号的。」

晨会结束，老赵问：「所以用户说变冷淡，下一步？」

林薇答：「先问 **哪类场景、哪类用户、从什么时候**——再查 **三把尺子**，别 **凭会议室手感**。」

## 概念正解

**Evaluation / 评测体系**，是 AI 产品里 **用可重复的方法衡量模型与系统表现** 的制度：包括 **测什么（场景与金标集）**、**怎么判（人工 rubric + 自动指标）**、**何时测（发版前离线、上线后在线或周抽检）**、**测完怎么决策（门禁、回滚、定向修复）**。它要回答的是：变好了还是变差了、差在哪、该改 Prompt / 检索 / 微调还是路由——而不是「再试两个问题」。

在子系列 **S2 · 平台装得下** 里，评测是平台能力：**多应用共用的发版天平**；本集用商小言续费把天平用起来。与第 18 篇对照：评测不管「能不能说」，只管「这一版比上一版好不好、稳不稳」。

回扣故事：

- **吵不出锅** → 缺可复现对比与分场景指标；  
- **会议室十问** → 不能替代代表性金标 + 固定考条件；  
- **30–40 题先跑 vs 200 题规划** → **双轨**：默认路径与完整版；  
- **续费掉分、合同持平** → 分场景才能定位到分块而非误伤 LoRA；  
- **升级触发条件** → 编制与风险到了再上 CI/A/B，避免假大空。

在 **AI 产品岗** 的典型场景：

| 场景 | 你要怎么用这个概念 |
|------|-------------------|
| **需求文档** | 写清评测范围、及格 rubric、门禁红线；单列 **中小默认**（题量/谁评/多久）与 **升级触发** |
| **方案评审** | 问：基线是谁？人工评谁评多少条？自动分防什么？没有 A/B 时周抽检看什么？ |
| **指标设计** | 分层：事实 / 体验 / 效率；避免单一通过率绑架 |
| **跨团队沟通** | 用户个案是线索；要可回归脚本或可共享的评分表；高风险人工抽检进门禁 |

## 类比锚定

**核心类比：回归测试用例 + 验收标准 + 灰度/客诉归因。** AI 输出非确定性，所以要 **固定考题、阅卷规则、看生产信号** 三件套；编制不够时，用 **小回归 + 双人抽检** 代替大考场。

| 你熟悉的 PM 经验 | Evaluation 要素 |
|------------------|-----------------|
| 上线前跑回归，对比上一版 | **离线评测**：同金标集，候选 vs 线上基线 |
| 用例来自真实 Bug/路径 | **金标集** 来自脱敏工单，按场景分层 |
| 验收写清 P0 必须过 | **Rubric**：事实/语气/合规/可执行 + 一票否决 |
| CI 冒烟失败阻断合并 | **自动指标** 守门（禁词、引用勾选…） |
| 全量前灰度看核心指标 | **在线 A/B**；或中小 **周抽检 + 接手率** |
| 事故追配置/数据版本 | 报告记全 **基座 / LoRA / 知识库 / Prompt** |

---

## 类比边界说明

### 一、概念核心要点

1. **评测为了决策**：输出是改哪里、上不上、回不回滚，不是虚高通过率。  
2. **必须固定考条件**：基座/数据/Prompt/检索库可追溯。  
3. **分场景重于笼统总分**。  
4. **离线 + 自动 + 在线（或周抽检）互补**，不能互相替代。  
5. **金标集是活文档**；假安全感比没有评测更危险。  
6. **完整流水线有升级门槛**；中小先救命集。

### 二、类比失效点

| 类比说法 | 失效点 | 更准确的理解 |
|----------|--------|--------------|
| 「过了就能上」 | 输出概率性；边界易漏 | 看分布与退步幅度；关键场景多次采样 + 人工复核 |
| 「金标越大越好」 | 维护爆、易脱节 | 重代表性与高风险；定期用新工单刷新 |
| 「自动指标=质量」 | 与业务相关性弱，易刷分 | 自动守门；语气/争议靠人工 rubric |
| 「没投诉就不用评」 | 沉默离开；合规未必投诉 | 在线指标 + 抽检；高风险主动挖 |
| 「必须先上 A/B / CI」 | 中小编制不够会空转 | 先表格离线 + 周抽检；触发条件到了再升级 |

### 动手小练习（约 20 分钟）

1. 选 1 个场景，写 **15 条真实问法** + 每条 **及格/一票否决**（照抄文中续费表结构）。  
2. 画发版门禁：**2 个自动指标（含 1 个禁词）** + **1 个必须人工抽的场景** + **1 个在线或周抽检指标** + **1 条红线阈值**。  
3. 写出你们团队的 **中小默认路径**（题量/谁评/工具）和 **3 条升级到完整版的触发条件**。
