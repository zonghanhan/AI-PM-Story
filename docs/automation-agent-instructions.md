- 必须有**故事标题** + **分章节小标题**（建议 3–6 章）

- **真实场景合理性**（强制）：

# 文风与禁忌

## 总语气

- 像资深 PM 同事午饭时讲明白一件事：**专业、好懂、不装**
- 系列读感应是 **连续剧现场**，不是内部 Wiki 或厂商白皮书

## 分区写作（强制）

| 区块 | 文风 | 适合放什么 |
|------|------|------------|
| **寓言故事** | 现场戏：对白、冲突、试错、复盘 | 机制如何被碰到、代价如何显现 |
| **概念正解 / 边界 / Checklist** | 可执行说明书 | 对照表、红线阈值、升级触发、字段清单 |

强调双轨、可执行时，**先保证故事仍是戏**；细则沉到故事后区块。宁可故事里少写三条 bullet，也不要让一章读起来像 PRD。

## 故事章：提倡

- 用人物嘴说清数字与红线（「今晚先捞三十来条真问法」「掉一截再谈回滚」）
- 用一次具体翻车讲清原则（卷子考旧价、忘了标 Prompt 小改）
- 术语首次出现用白话括注；让读者跟着情节摸到概念，而不是先背定义

## 故事章：禁止（高发翻车）

- 整章 **编号 SOP**（「1.今天 2.明天 3.后天」任务清单体）
- **条款体复盘**（「坑 1：… → 规定：…」「坑 2：… → 规定：…」连排）
- 故事正文里大段 **「中小执行清单（可照抄）」**、升级触发条件 bullet 墙
- 删掉人名后仍通顺得像 **内部 Wiki / 操作手册** 的段落（说明戏不够）
- 论文腔、公式推导、一次打包多个概念、结尾突然甩术语不解释
- 为串前作人物硬派活，导致组织分工不像真公司

## 正反对照（写作时默念）

- **反例**：林薇把决策拆成可执行三步：1.今天… 2.明天… 3.后天晨会只看均分是否掉≥0.5…  
- **正例**：林薇看向客成：「今晚先把续费工单脱敏捞三十来条。」又对小李说：「两包各答一遍；语气掉一截或冒出两道事实硬伤，再谈回滚。」

- **反例**：坑 1：卷子过时 → 规定必须附卷子变更单。坑 2：…  
- **正例**：新套餐上线后自动分虚高、客成挨骂；林薇在群里说「改价目连带改卷子，先改那五道也行。」

# Git 工作流（每次任务完成后执行）

**统一策略（单人日更推荐）：建分支 → 开 PR → 默认自动合进 `main`。**  
目标：`main` 上通常能直接看到最新文档；需要时你也能「先不合、自己审完再合」。

## 默认模式（自动合并）

1. 从最新 `origin/main` 拉取后，新建并切换分支：  
   `cursor/ai-fable-{YYYY-MM-DD}`  
   （若同日已存在，用 `cursor/ai-fable-{YYYY-MM-DD}-2` 等后缀，**不要**在脏分支上叠无关提交）
2. 在该分支写作与改索引；`git add`：新建的 `stories/*.md`，以及更新过的 `README.md`、`stories/世界观.md` 等
3. `git commit`，提交信息：`docs(ai-fable): {概念名} - {故事名}`
4. `git push -u origin <分支名>`
5. 向 **`main`** 开 Pull Request（标题建议同 commit；正文含：子系列代号、概念、文件路径、3–6 条 takeaway）
6. **合并该 PR 到 `main`**（squash 或 merge 均可；优先 squash 保持 main 历史干净）  
   - 若环境提供 PR/合并工具则用之；若仅有 `gh` 且具备写权限，可用 `gh pr create` + `gh pr merge`
7. 确认 `main` 已包含今日文件后，在对话概要里给出：**分支名、PR 链接、是否已合并**

## 审核模式（仅开 PR，不合并）

若用户当次指令含以下任一含义：**「仅开 PR」「先不合并」「等我审核」「不要自动合并」**：

- 执行到上节第 5 步为止，**禁止 merge**
- 对话中明确写：`状态：待你合并` + PR 链接
- `main` 在你手动 Merge 前可以暂时不是「今日最新」——最新在 PR 分支上

## 不要做的事

- **不要**在未说明的情况下直接 `git push origin main`（已废止直推 main 作为默认）
- **不要** `force push` 到 `main`
- **不要**把多日未合 PR 堆在同一个长期分支上；一日一分支
- 若 push/开 PR/合并失败：说明原因与下一步，不要静默跳过

## 直推 main 的风险（供你决策时对照）

单人仓库直推并非不能用，但常见代价是：坏稿立即污染默认分支、缺少「今日先挂起」闸门、回滚叙事不如「revert 某个 PR」清晰。本策略用 **自动合并** 保留「main 常新」，用 **审核模式** 保留「自己合」。
